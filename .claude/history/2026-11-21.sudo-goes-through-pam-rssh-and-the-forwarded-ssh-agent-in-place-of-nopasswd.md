# Sudo goes through pam_rssh and the forwarded SSH agent in place of NOPASSWD (2026-11-21)

- **Ansible's become needs `noninteractive_auth`:** become runs `sudo -H -S -n`, and without `Defaults noninteractive_auth` (sudo 1.9.10 and later) `-n` refuses before PAM is asked, so pam_rssh never gets to check the agent.
- **The guard is `sudo -n -k -v` under `verifypw=always`:** `always` makes `-v` authenticate whatever NOPASSWD rules the user still has, so the check before their removal passes only through pam_rssh. sudo-rs has no `verifypw`.
- **The rollout is safe because sudoers.d is read in lexical order and the last match wins:** `10-pam_rssh` sorts before `90-cloud-init-users`, `90-<user>-nopasswd` and vkasm's `kasm_admin`, so the NOPASSWD rules keep winning until the role removes them. A run that stops between the two leaves sudo as it was.
- **When the agent gives no signature, the check fails after about a minute:** on bailout and on mail, `sudo -n -k -v` waited about 62 s and failed with `sudo: a password is required`. The play stopped before the NOPASSWD removal and before AIDE's refresh. A rerun with the operator at the agent passed, and its refresh consumed the failed run's records, which `aide_written` had kept on the controller.
- **A host's `ansible_become` outranks a task's `become: false`:** the check task sets `vars: ansible_become: false` so that it runs `sudo` itself as the login user rather than under become.
- **A regex backreference in a folded scalar stayed literal:** `map('regex_replace', '^(.+)$', '/etc/sudoers.d/90-\\1-nopasswd')` inside a `>-` scalar rendered as `90-\1-nopasswd`. A `{% for %}` loop with `append` builds the list instead. A `--check --diff` run caught it, as the paths it would remove.
- **FreeIPA's sudo rules bypass the local files:** riko's `sudo -l` showed `(ALL : ALL) NOPASSWD: ALL` from the `Admins` rule's `!authenticate` option even with the local NOPASSWD files gone. `ipasudorule` with `action: member` and `state: absent` removes just the listed options, and once SSSD's cached rules on riko had refreshed, sudo there refused without an agent.
- **opc's launch key stays in OpenTofu:** OCI refuses changes to an instance's `ssh_authorized_keys` and `user_data` metadata after launch, so `tofu/oracle` keeps the key it launched with, and base's image-user task replaces opc's `authorized_keys` in the guest.
- **Builds installed:** `pam-rssh 1.2.0-1` from the APT repositories (dodo on Debian, vkasm and doppelgangerhq.com on Ubuntu), and `pam-rssh-1.2.2-1` from the EL testing channel (el9 on bailout, livekit, mail and tailscalerouter, both x86_64 and aarch64; el10 on pihole2 and riko). It loads under SELinux enforcing with no policy change.
