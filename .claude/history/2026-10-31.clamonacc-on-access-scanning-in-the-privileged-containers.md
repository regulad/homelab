# clamonacc: on-access scanning in the privileged containers (2026-10-31)

- Inside tsexit, root of a privileged container (`uid_map 0 0 4294967295`, `CapEff 000001fcfdfcffff`), clamonacc's own `fanotify_init(FAN_CLASS_CONTENT | FAN_UNLIMITED_QUEUE | FAN_UNLIMITED_MARKS, O_LARGEFILE | O_RDONLY)` and an inode mark with its mask without prevention (`FAN_ACCESS | FAN_OPEN | FAN_EVENT_ON_CHILD`) both succeed, and an open delivers its event with a descriptor. clamonacc then ran in immich, ncsusplitt, qb, timemachine, tsexit and tvheadend (Ubuntu 26.04's 1.5.4), each through the role unchanged. In tsexit, EICAR written to `/tmp` was found and moved within the second and mailed at the next minute; [#1883](https://github.com/Cisco-Talos/clamav/issues/1883)'s duplicate came twice, as `<name> (deleted)` and `<name> (deleted).001`.
- Each container's `ansible_host` lists `privileged_containers` or `unprivileged_containers`, from the container's `unprivileged`. Ansible applies a pattern's unions first, then `:&` intersections, then `:!` exclusions, whatever their order, so `debian:ubuntu:rhel:!proxmox_containers:privileged_containers` would drop the privileged containers too; the play excludes `unprivileged_containers` instead.
- clamonacc 1.5.4 (`clamonacc/client/protocol.c`) streams a file's size as `fstat` gives it, then, when it would quarantine, reads one byte more; a file still being written yields one, and clamonacc logs "File size exceeds StreamMaxLength; refusing to send a truncated quarantine stream" whatever the size. Ansible's module payloads in `/tmp`, scanned at open while still being written and gone before the close's scan, log it at every run.
- What else could watch files in an unprivileged container: inotify (names only, no descriptor or pid, so a watcher cannot tell its own scanner's opens from others' and can scan only on write); unprivileged fanotify since 5.13, which 6.18's `fanotify_user.c` limits to notification groups reporting file handles, inode marks, a bounded queue and marks, no descriptors, and a pid of 0 for any process but the listener; reopening a handle needs `open_by_handle_at`, which needs `CAP_DAC_READ_SEARCH` in the initial namespace and LXC's seccomp profile denies. ClamFS 1.3.1, a FUSE filesystem that denies infected files, passes clamd each descriptor (`nFILDES`), so it needs a clamd on the same host.
- 6.18's `kernel/audit.c` serves auditd and auditctl only from the initial user namespace and the initial pid namespace, so auditd runs in no container, privileged ones included.
- Debian's and Ubuntu's `clamdscan` package depends only on `clamav-base` and `libclamav12`, with `clamav-daemon` merely suggested; Enterprise Linux's `clamav` package carries clamdscan beside clamonacc. clamd's defaults are `StreamMaxLength` 100M, `MaxFileSize` 100M and `MaxScanSize` 400M, and the shared clamd sets none. `clamdscan --stream` sends a larger file's first `StreamMaxLength` bytes for a plain scan, and refuses the file as an error when it would move or remove it.
- qBittorrent 5.3.0 (`torrentimpl.cpp`, `application.cpp`) moves a finished torrent from its download path to its save path before it runs the "on torrent finished" program, which it starts detached, without waiting for it.
- `tofu/gonkputer/prepare.sh` refuses a decrypted `secrets.auto.tfvars.json` that is merely out of date, as after `pubsub_ipv6_cidr` joined `secrets.sops.json` on 2026-10-29, as it refuses local edits; comparing the two files' keys and values tells which.
