# dodo's root moves onto LUKS on an interim rbd disk, unlocked from its vTPM by clevis (2026-11-20)

- **OpenTofu adopts a disk added with `qm set` from its configuration alone.** `qm set 101 --virtio1 rbd:238,discard=on,iothread=1` hot-plugged `rbd:vm-101-disk-0` while dodo ran. bpg/proxmox 0.122.0 plans a disk that is live but not in state as `+ disk`, and applies it through its path for an existing disk: it keeps the volume and sends only options. Its `vmPlanDiskLocationAndSizeChanges` walks only the disks already in state, so nothing is moved or resized. The options include its defaults `aio=io_uring`, `cache=none`, `backup=1` and `replicate=1`. A change of `aio` or `queues` needs a restart, so with `reboot_after_update` at its default of true the provider shut dodo down through the guest agent and started it again, in 39 s. aboriginal sets `reboot_after_update = false`, so the provider won't restart it for the same change.
- **clevis's initramfs-tools hook logs only to the console.** The journal has nothing from it (`journalctl -g clevis` is empty), and cryptsetup's "already active" doesn't always appear. A root on `/dev/mapper/root` with no prompt at the console shows the vTPM unsealed the key. systemd-cryptsetup logs that it ignores crypttab's `initramfs` option, which only initramfs-tools reads.
- **btrfs moved the mounted root onto LUKS.** `btrfs device add` trims the whole new device first. `btrfs device remove` ran under `systemd-run`, so it didn't depend on the SSH session, and moved about 66 GiB onto `rbd` in ten minutes. The swapfile is off during the move, because it pins its extents and needs a single-device filesystem. A bare `swapon /swap/swapfile` ignores fstab's options: it came back at priority -2 without `discard`, and `swapon --all` reads them.
- **With the root on LUKS, `update-grub` takes GRUB's font from `/boot`.** `grub.cfg`'s `search` lines then name only `/boot`'s UUID, as GRUB cannot open the volume.
- **AIDE took in the move through its daily report.** dodo's report about 20 minutes after its first boot from the new disk mailed the move's writes in 2.5 KB, and the relay's acceptance moved the baseline, so no `aide-accept` was needed. `/boot` is not watched on dodo, as Secure Boot is on.
- **`ansible-generated` in a new worktree needs each root's decrypted inputs.** The inventory's `tofu-<root>` wrappers read `tofu/gonkputer`'s and `tofu/oracle`'s `secrets.auto.tfvars.json`, and the `restic` role's `tf_output` lookup reads `tofu/backblaze`'s state, which fails with "Could not get Terraform outputs" until `tofu/backblaze/prepare.sh` has written its inputs.
