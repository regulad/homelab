# AIDE explains kernel updates and rebuilt caches, and leaves /boot to Secure Boot where it is on (2026-11-03)

- **rpm never verifies a `%ghost` file's contents, and aide-report took that as vouching.** `rpm --verify` skips a ghost's digest, size, mtime and link target, so a ghost it lists nothing for was explained, whatever it held: a rewritten `/boot/vmlinuz-<release>` on an Enterprise Linux host would have been left out of the report. aide-report now reads each file's flags (`%{FILEFLAGS:fflags}`, `g` for a ghost) and vouches for no ghost; a path one package lists as a ghost and another installs is the latter's. bailout lists 17,206 ghosts, mail 19,648.
- **Enterprise Linux's kernel files in `/boot` are copies.** kernel-install copies `vmlinuz`, `System.map`, `config` and `.vmlinuz.hmac` from `/usr/lib/modules/<release>/` into `/boot`, and links `symvers-<release>.gz` to the one there; the kernel package (`kernel-uek-core` or `kernel-core`) lists the copies only as ghosts, and the files they copy as its own. aide-report explains a copy that holds the same bytes as, or links to, a file its package verifies. Its mode differs from the ghost's, so `rpm --verify` also flags `System.map` and the initramfs.
- **What a kernel's installation generates is explained by its release.** dracut's initramfs (a ghost of the kernel package), kdump's, initramfs-tools' `initrd.img` and its record in `/var/lib/initramfs-tools`, the boot entry `/boot/loader/entries/<machine-id>-<release>.conf`, depmod's `modules.*` indexes in `/usr/lib/modules/<release>/`, and `/usr/share/doc/kernel-keys/<release>`: each is explained when it appears with a kernel package installed since the baseline, or is gone with one removed since. The release's package is the owner of `/usr/lib/modules/<release>/vmlinuz` or `/boot/vmlinuz-<release>`. Lost: a file tampered with between the install and the next report. A later change, such as an initramfs rebuilt for a kernel already installed, as `update-initramfs -u` does after many package updates on Debian and Ubuntu, stays in the report.
- **A rewrite may change its SELinux label's user.** On bailout, dnf-automatic rebuilt `/etc/ld.so.cache` (`ldconfig`, the dynamic linker's index of shared libraries) and `/usr/lib64/gconv/gconv-modules.cache` (`iconvconfig`, glibc's index of its character-set converters) with the same bytes; their labels went from `unconfined_u` to `system_u`, the user of whoever wrote them last (a login, then a service), with their types (`ld_so_cache_t`, `lib_t`) as the policy assigns. aide-report's rewritten rule now accepts a label changed in its user alone, and extended attributes changed in that label alone.
- **Both caches are checked by rebuilding them.** When AIDE reports either changed, aide-report rebuilds it into `/run/aide-report/rebuilt` (`ldconfig -i -X -C`: no auxiliary cache, no library links touched; `iconvconfig -o`) and explains it only if the bytes match. Every rebuild matched, twice each, run as a transient systemd service (`unconfined_service_t` on Oracle Linux, no SELinux denials) on glibc 2.34 (Oracle Linux 9, x86_64 and aarch64), 2.39 (AlmaLinux 10, Ubuntu 24.04 aarch64), 2.41 (Debian 13) and 2.43 (Ubuntu 26.04, VM and container): 0.3 to 3 s for ldconfig's first build, under 0.1 s after, about 0.01 s for iconvconfig. The 32-bit `/usr/lib32/gconv/gconv-modules.cache` is not one the native `iconvconfig` builds, and is left out; on Debian and Ubuntu packages ship both gconv caches (`libc6`, `libc6-i386`), so dpkg vouches for them, and only `ld.so.cache` is rebuilt there. A hook refreshing the baseline whenever the cache is written was rejected: it would accept a crafted cache, which can point any library name at any path.
- **Replayed through the new rules,** bailout's report of its UEK update (6.12.0-207.111.5.4 out, 208.112.5 in, by dnf-automatic, whose `installonly_limit` keeps three) went from 29 entries to none.
- **`/boot` is left to Secure Boot where it is on.** aide-report reads `SecureBoot-8be4df61-93ca-11d2-aa0d-00e098032b8c` in `/sys/firmware/efi/efivars` at each run (four bytes of attributes, then 1 while on) and, while it is on, excludes `aide_exclude_paths_secure_boot`, `/boot`. It is on for prodingus, aboriginal and dodo. vkasm boots by BIOS. The OCI instances boot by UEFI without it, and cannot have it: OCI's Shielded instances support VM.Standard3.Flex, the E3 to E6 Flex shapes, VM.Optimized3.Flex and some bare-metal shapes, not VM.Standard.E2.1.Micro or VM.Standard.A1.Flex, and are chosen only at launch ("You cannot migrate a non-shielded instance to a shielded instance").
