# rsshub runs a pull request's head from GHCR, built by regulad/RSSHub's ci branch (2026-11-11)

- regulad/RSSHub, the fork that DIYgod/RSSHub#23860 (ASUS's ROG products and driver feed) comes from, has an orphan `ci` branch, its default branch, as regulad/nssm has: `.github/workflows/build.yml` builds a source ref with RSSHub's own Dockerfile, the image without Chromium, for linux/amd64, and on a manual run with `push` pushes it to `ghcr.io/regulad/rsshub:<full source commit hash>`. `.github/settings.yml` there asserts `default_branch: ci`. A push to `ci` builds master without pushing.
- Upstream's `docker-release.yml` runs only where `vars.DOCKER_USERNAME` is set, and its manifest step reads the per-platform digests from Docker Hub, so a fork without Docker Hub cannot use it.
- The fork had never run a workflow, and had none registered; `build.yml` registered and ran at the first push to `ci`, with nothing to enable. Right after the first push, GHCR served `ghcr.io/regulad/rsshub` to anonymous pulls, so the Quadlet needs no registry login.
- RSSHub's prek hooks refuse a commit where the branch has no `.pre-commit-config.yaml` or `prek.toml`, as on `ci`; `PREK_ALLOW_NO_CONFIG=1` lets the commit through.
- rsshub's image is `ghcr.io/regulad/rsshub:5352d8039df228ef466f0b979b60e504a6e7cf84`, the pull request's head, until upstream merges it; then `docker.io/diygod/rsshub:latest` again (the FIXME in its `services.yml`). The tag never moves, so `AutoUpdate=registry` changes nothing until a rebuild of the same commit.
