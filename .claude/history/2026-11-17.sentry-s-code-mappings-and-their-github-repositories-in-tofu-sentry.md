# Sentry's code mappings and their GitHub repositories in tofu/sentry (2026-11-17)

- `jianyuan/sentry` 0.16.0 manages code mappings (`sentry_organization_code_mapping`, imported as `<org>/<id>`) and repositories (`sentry_organization_repository`, imported as `<org>/github/<integration id>/<repository id>`). It has no repository data source, so a mapping's repository is adopted as a resource. Deleting that resource removes the repository from Sentry. The integration comes through the `sentry_organization_integration` data source, by `provider_key` and the account name.
- `organizations/<org>/integrations/` answers 404 on the region host `us.sentry.io` and only answers on `sentry.io`, the provider's default; repositories and code mappings answer on both. The internal integration's Organization: Read covers reading all three. Whether changing a mapping needs more than that is not yet known.
- The repository list includes disabled repositories. picture-triangulator's is disabled in Sentry, and its GitHub repository is archived; the provider still reads and imports it. Sentry generated three of the four mappings itself; a mapping's empty `stack_root` or `source_root` is the same as leaving it out.
- Data scrubbing is beyond 0.16.0. Upstream merged it after that release, in jianyuan/terraform-provider-sentry#995 (6dc3061): `data_scrubber`, `data_scrubber_defaults`, `scrub_ip_addresses`, `sensitive_fields`, `safe_fields` and `relay_pii_config` on `sentry_project`, all optional and computed, and a new `sentry_organization_data_scrubbing`. That resource resets every attribute it leaves out, and destroying it resets them all. Writing it needs Organization: Read & Write, which the integration lacks. It has no `store_crash_reports`. Live, the organization requires the data scrubber, the default scrubbers and IP-address scrubbing, with no sensitive or safe fields and no advanced rules; the projects' own settings were unchanged since their adoption.
