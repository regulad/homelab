# kernel_params gives Enterprise Linux its arguments by grubby (2026-11-04)

- **`kernel_params_mode`** is `debian` on Debian and Ubuntu, and `grubby` on Enterprise Linux, each set in its OS group's group_vars. `/etc/default/grub` is upstream GRUB's, and Enterprise Linux's `grub2-mkconfig` sources it too; the drop-ins in `/etc/default/grub.d` are Debian's, sourced by its own `grub-mkconfig` after it, and `update-grub` is `grub2-common`'s `exec grub-mkconfig -o /boot/grub/grub.cfg`. The sets in `kernel_params_grub_dropins` and `99-audit` are the same data for both; with grubby a set's name is a label alone.
- **What grubby rewrites,** read in grubby-bls 8.40 on Oracle Linux 9: `--update-kernel=ALL --args=…` rewrites the `options` line of every entry in `/boot/loader/entries`, by `sed -i` whether it changes or not; `GRUB_CMDLINE_LINUX` in `/etc/default/grub` where it is set; `kernelopts` in the grubenv only where that is set, which the OCI images' is not; and `/etc/kernel/cmdline`, made from the newest entry where it is missing. It regenerates `grub.cfg` only on s390, ppc64le with OPAL firmware and Xen PV guests. `update_args` takes out every instance of an argument's name, whatever its value, before appending it, so one call converges a changed value too.
- **Kernels installed later** take their options from `/etc/kernel/cmdline` (kernel-install's `20-grub.install`, then `/usr/lib/kernel/cmdline`, then `/proc/cmdline`), so the arguments carry over to them.
- **The role runs grubby only when an argument is missing** from an entry, the rescue entry included, or from `/etc/kernel/cmdline`, read by `grubby --info=ALL` and the file itself. Containers declare no arguments, so the play never calls grubby in wako.
- **`aide_writes` and `aide-report --refresh` take `*`** for any part of one name: grubby's task declares `/boot/loader/entries/*.conf`, which the refresh matches as a regular expression, covering entries there now and at the baseline. The four Oracle Linux instances have no Secure Boot, so AIDE watches their `/boot`.
- **A backreference in a folded YAML scalar is `'\1'`.** YAML leaves a block scalar's backslashes alone, and ansible-core 2.21's templating kept `'\\1'` as two of them, so `regex_replace` put out a literal `\1`.
