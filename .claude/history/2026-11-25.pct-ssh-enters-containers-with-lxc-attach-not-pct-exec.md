# pct_ssh enters containers with lxc-attach, not pct exec

- Timed on prodingus (pve-container 6.1.20), 20 runs each of `true` in container 124 (tsexit): `pct exec 124 -- true` took 556 ms a call, `lxc-attach -n 124 -- true` 4 ms, and `lxc-attach … -- /bin/sh -c true` 4 ms as well. Entering the container's namespaces costs milliseconds; nearly all of `pct exec`'s half second is its Perl and PVE modules starting, before it calls `lxc-attach`. Every task in a container paid it once a command.
- `pct exec` (`PVE/CLI/pct.pm`, its `exec` method) loads the container's configuration to check it is on this node and running, calls `clean_environment()`, which deletes `SSL_CERT_FILE` and `SSL_CERT_DIR` (variables Proxmox's own Perl sets for its Rust libraries), and then `exec`s `lxc-attach -n <vmid> --keep-env -- <command>`. `--keep-env` is its default until, by its own FIXME, a later release switches to `--clear-env`. `pct_ssh` now runs that same `lxc-attach` command under `env -u SSL_CERT_FILE -u SSL_CERT_DIR`, pinning `--keep-env` itself; `lxc-attach` fails on a stopped or absent container as `pct exec`'s check would.
- A container's check of about 100 tasks saves about 55 s of `pct` startup this way, roughly a tenth of a 67-minute ansible-generated check run 10 forks wide: an estimate the next full run measures.
