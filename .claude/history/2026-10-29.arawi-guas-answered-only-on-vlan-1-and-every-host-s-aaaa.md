# arawi: GUAs answered only on VLAN 1, and every host's AAAA records kept through Kea's lease file cleanup (2026-10-29)

- Kea's lease file cleanup moves older lines out of `/var/db/kea/dhcp4.leases` into `.2`, and `ndp-aaaa.php` read the file itself alone. A host whose lease had moved, and whose ARP entry had expired, could not be matched to its A record, so its AAAA records vanished until it next spoke IPv4 to arawi: 28 ULA and 32 GUA records were published, against 41 and 41 once every file is read. Kea loads them at startup as `.completed`, or else `.2` then `.1`, and the file itself last (`memfile_lease_mgr.cc`); the script now does the same.
- Every AAAA record was global local-data, so the tailnet and OCI got hosts' GUAs, which they reach only across the internet. The GUA prefix is the ISP's and may change, so nothing keys on it: the global file holds the ULAs' AAAA records and every PTR, and `/var/unbound/view-local-aaaa.conf` holds every AAAA record, included inside the "local" view's clause (an `include:` is textual, valid anywhere) under `local-zone: "regulad.internal." typetransparent`. With `view-first: yes`, a typetransparent zone answers only the types it holds and leaves the rest, A records among them, to the global zone; a plain transparent zone would answer NODATA for A once a name has any AAAA in the view. "local" now holds only VLAN 1's clients, by `10.23.0.0/20` and its ULA /64; a new "remote" view takes the rest of `10.23.0.0/16`, the tailnet and OCI's pubsub subnet. Checked by direct queries: VLAN 1 gets both families' AAAA over IPv4 and IPv6; the tailnet, livekit and the VCN's resolver get the ULA alone.
- `unbound-checkconf` warns `duplicate local-zone regulad.internal.` on the live configuration too: the custom options' static zone beside the one pfSense writes for its system domain.
- The NDP table holds only the addresses a host has used on the link, so registering ULAs through it is inherently incomplete: arawi's held prodingus's GUA but not its ULA, so outside VLAN 1 prodingus had no AAAA record, only its A.
- From livekit, a query to arawi's ULA over IPv6 timed out while the same query over IPv4 answered; Unbound's access list allows `::/0` and would have refused rather than stayed silent.
- arawi's login shell is csh, which rejects `2>&1`: run commands there as `ssh arawi sudo sh -s < script`, the admins group having passwordless sudo.
- After `/reload-plugins` brought in alock 0.2.0, this session's `PATH` still put 0.1.0's shims first. 0.2.0's `ansible-playbook` shim, looking past its own directory for the real binary, ran 0.1.0's shim, which spun on the CPU for 35 minutes before `ansible-playbook` ever started. With 0.1.0's `bin` removed from `PATH`, the apply ran; a fresh session has only 0.2.0's.
