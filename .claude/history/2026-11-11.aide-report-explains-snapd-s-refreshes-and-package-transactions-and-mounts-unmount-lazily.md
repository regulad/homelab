# aide-report explains snapd's refreshes and package transactions, and mounts unmount lazily (2026-11-11)

- **snapd's signed records date and verify a refresh; its change log cannot.** A mounted `/var/lib/snapd/snaps/<name>_<revision>.snap` hashes, by SHA3-384 in unpadded base64url, to the name of its `snap-revision` assertion's directory under `/var/lib/snapd/assertions/asserts-v0/snap-revision/`, whose `active` file carries `snap-sha3-384`, `snap-id` and `snap-revision`. The snap's name is in `snap-declaration/16/<snap-id>/active`. The download cache holds the same file at `/var/lib/snapd/cache/<hex SHA3-384>`. snapd prunes its change log: aboriginal had no changes recorded at all.
- **Package transactions' windows:** apt's in `/var/log/apt/history.log*`, `Start-Date:` and `End-Date:` in local time with two spaces between date and time; dnf's in `/var/lib/dnf/history.sqlite`, table `trans`, `dt_begin` and `dt_end` in Unix seconds, alike on Oracle Linux 9 and AlmaLinux 10.
- **wtmp's boot records name the kernel each boot ran,** in the `ut_host` of each `BOOT_TIME` (type 2) record, so they date the boot a kdump image was built in.
- **Debian's `/etc/ssl/certs/java/cacerts` is JKS** (magic `FEEDFEED`) and holds the same certificates as `/etc/ssl/certs/ca-certificates.crt`.
- **oci-linux-config's `misc_updates.sh` runs `grubby --update-kernel ALL`,** which rewrites the boot entries and `/etc/default/grub`; grub2-tools owns that file but does not verify its digest.
- **Stopping a noexec bind that something holds open fails with "target is busy",** as the OCI monitoring agent held `/etc/unified-monitoring-agenttmp`. `systemd_service` disables before it stops, so the failure left the unit disabled and still mounted. A path bound over itself shows the same files once unbound, so the binds now unmount lazily, as do AppArmor's policy cache and aboriginal's bindfs remap. Lazy unmounting is wrong for `/tmp` (new files would land on the root's `/tmp`, outside noexec), for a writable overlay (a new mount could share its upper and work directories with one still detaching), and for a block volume (the volume could go before the filesystem lets go).
- **Some services require their noexec binds, by `RequiresMountsFor=`.** `/var/backups` is written only by `dpkg-db-backup.service` and `apt.systemd.daily`, which both `apt-daily.service` and `apt-daily-upgrade.service` run. A service with default dependencies already starts after local mounts; the drop-in also keeps it from running, or starts the bind first, when the bind is missing.
- **A rerun reloads systemd even where no handler fires.** The noexec role's "Paths mounted" task sets `daemon_reload`, so a rerun after an interrupted apply loads unit files the first run wrote. 13 containers reached through prodingus timed out in SSH authentication partway through a fleet run; a rerun limited to them finished the apply and AIDE's refresh.
- **A daily report that runs during an apply mails what the apply wrote,** as the refresh is the run's last play: matrix's 23:55 report listed the drop-ins and mount units written at 23:44. Its mail accepted them, and the refresh then passed over them as older than that acceptance.
- **A same-version reinstall is no package change to aide-report.** On orchard (Ubuntu 26.04.1), unattended-upgrades reinstalled about 150 packages at the versions they had (`Upgrade: libgpg-error0:amd64 (1.58-2, 1.58-2)`), with different contents, so nothing those reinstalls rewrote counted as a package's doing.
- **aide-common's chrony rules cover only `chrony.drift`.** Ubuntu's `chrony.conf` sets `ntsdumpdir /var/lib/chrony`, so chronyd also saves each NTS server's cookies there as `<address>.nts`.
