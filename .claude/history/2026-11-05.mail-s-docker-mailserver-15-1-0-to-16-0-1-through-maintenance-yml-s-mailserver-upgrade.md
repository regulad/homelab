# mail's docker-mailserver 15.1.0 to 16.0.1, through maintenance.yml's mailserver-upgrade (2026-11-05)

- docker-mailserver migrates no data of its own, and its documentation asks for no stepping through majors: a jump across several needs every skipped major's configuration changes made at once. Its major tag, `:16`, follows the minor and patch releases. 15 ships Debian 12's Dovecot 2.3.19.1; Dovecot's guide asks for the newest 2.3 before 2.4, which no docker-mailserver release carries.
- 16 moves to Debian 13 and Dovecot 2.4, which dropped the one-letter variables. `%n` became `%{user | username}` in `DOVECOT_USER_FILTER`, `DOVECOT_PASS_FILTER` and the home in `DOVECOT_USER_ATTRS`. 15 cannot read the new form, so `mailserver-upgrade` writes the configuration under `mailserver_dir` together with the unit. 16 still reads the filters' old names, as fallbacks for `DOVECOT_USERDB_LDAP_FILTER` and `DOVECOT_PASSDB_LDAP_FILTER`. `DOVECOT_USER_ATTRS` replaces the userdb's whole field block, so the mail path falls back to 16's global `/var/mail/%{user | domain}/%{user | username}`, the mailbox 15 used.
- 16's default LDAP passdb sets `user = %{ldap:uniqueIdentifier}`, which FreeIPA's entries lack. Dovecot 2.3 skipped the missing attribute; 2.4 failed every IMAP and ManageSieve login with `Failed to expand passdb_fields/user setting variables: ldap: No such attribute 'uniqueidentifier'`, for half an hour until the fix. Delivery went on throughout, as LMTP asks only the userdb. `DOVECOT_PASS_ATTRS==user=%{user}` keeps the login name as given. docker-mailserver's documented example, `uid=user`, would rename the user to the bare uid, whose mail path is `/var/mail//<uid>`. With `DOVECOT_AUTH_BIND=yes`, docker-mailserver drops the password field from the mapping.
- `doveadm auth lookup <user>` takes no password and binds as nobody but the service account, yet expands the passdb's fields as a login does, and fails where a login would. `mailserver-upgrade` now checks it after a start, beside the userdb lookup and the INBOX's GUID and UIDVALIDITY, which passed here.
- 16's image gives `_rspamd` UID 112, which was 111 in 15 and is now `redis`'s; its group stays 114, the syslog user 113 and vmail 5000. docker-mailserver's setup gave the DKIM keys to 112 at the upgrade; `dkim_signing.conf`, which it leaves alone, was redis's until host_files declared 112.
- 16 starts `changedetector` under `ACCOUNT_PROVISIONER=LDAP` too, and adds `dms-healthcheck`, which the Quadlet's `HealthCmd` now runs: every daemon the settings enable is `RUNNING`. `supervisorctl status` exits 3 while any program is stopped, as those of features turned off always are.
- From its start to "is up and running", 16 took 9 s. Rspamd's milter refused one submission connection in that window.
- The copy, 650 MB of data and the configuration, is made with `cp --reflink=never`. mail's data volume is XFS with `reflink=1`, and no file on it shared an extent before the upgrade. The copy's own directory, made by Ansible's file module, is labelled `unconfined_u`, which host_files' `restorecon -F` relabels `system_u`.
- webhookd is stopped for the upgrade, as Uptime Kuma's report of the outage would have it restart `mailserver.service` over the copy.
- `fail2ban-jail.cf.j2` uses host_files' `ip_network` filter, which Ansible loads only into runs that load host_files; the stage's `ansible.cfg` now names the role's `filter_plugins` for every play.
- alock refuses any `ansible-playbook` run without `--check` from a worktree with uncommitted changes, a playbook against localhost included.
