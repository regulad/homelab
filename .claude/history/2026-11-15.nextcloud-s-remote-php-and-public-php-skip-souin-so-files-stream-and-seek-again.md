# Nextcloud's remote.php and public.php skip Souin, so files stream and seek again (2026-11-15)

- Souin v1.7.9 (cache-handler v0.17.0) removes `Range` from the request it passes upstream (`req.Header.Del("Range")` in `pkg/middleware/middleware.go`), then serves the range from the whole buffered body through `http.ServeContent`. A 2-byte probe therefore waits for the entire file, and every seek fetches it again. The maintainer calls this a temporary fix in darkweak/souin#667. Neither v1.7.9 nor v1.7.10 has a setting to stream a response: `max_cacheable_body_bytes` is checked after buffering and only decides whether to store it.
- Nextcloud-iOS 35.2.2 plays video through direct links, `/remote.php/direct/<token>`, with AVFoundation, which first asks for `Range: bytes=0-1` and gave up after about 3 seconds. Between 11-01 and 11-15 ingress logged 37 aborted or cancelled responses on direct links, all from 11-11 on, and 29 on `/remote.php/dav/files`.
- Nextcloud 35's direct endpoint is a Sabre DAV GET of the opened file; it answers `Range` itself and sends no `Cache-Control`. Its links last 8 hours by default, 24 at most. A share's `/s/<token>/download` redirects to `/public.php/dav/files/<token>/…`, with `?accept=zip` for a folder, so remote.php and public.php carry every file body Nextcloud serves.
- A site's own `cache { … }` block takes each setting it leaves unset from the global `cache` block, setting by setting (`FromApp` in cache-handler's `httpcache.go`), so the backend timeout and `default_cache_control` carry over; only `api` must be global. `regex { exclude … }` is matched against the request URI, query included; a bypassed response carries `Cache-Status: Souin; fwd=bypass; detail=EXCLUDED-REQUEST-URI`.
- Souin passes server-sent events through only when `Accept` is exactly `text/event-stream`; any other `Accept` is buffered like a page.
- ingress's own Caddy validates a Caddyfile without a file on ingress when the input is piped inside the container: `ssh prodingus "pct exec 121 -- sh -c 'cat | /usr/local/bin/caddy adapt --adapter caddyfile --config /dev/stdin'" < <file>`. Without the inner `cat`, Caddy cannot open `pct exec`'s stdin as `/dev/stdin` (permission denied).
