# maintenance.yml upgrades Nextcloud a major at a time (2026-10-31)

- Nextcloud cannot skip a major release. The image's entrypoint refuses an image more than one major ahead of the installed version ("It is only possible to upgrade one major version at a time"), and refuses a downgrade; Nextcloud's manual requires the newest point release of the current major before the next. `nextcloud-upgrade` therefore takes one major per run, from that patch.
- MariaDB 10.11 is supported from Nextcloud 32 through 35, which recommends 12.3.
- `occ upgrade` disables an enabled app with no release for the new major, and the entrypoint lists those it disabled under "The following apps have been disabled:". The App Store's listing for a platform (`/api/v1/platform/<version>/apps.json`) holds each app with a release for it: 593 apps and 16.6 MB for 33.0.0, so the play reads it on the host, in Python, rather than as an Ansible variable. On 2026-10-31 each of the nine enabled apps had a stable release for 33, 34 and 35.
- A rollback needs the code, config and apps volumes beside the database: `config.php` and the code volume's `version.php` both name the release, and the old image's entrypoint refuses to start on newer code.
