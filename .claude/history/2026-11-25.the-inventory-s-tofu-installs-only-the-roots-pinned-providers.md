# The inventory's tofu installs only the roots' pinned providers

- `cloud.terraform.terraform_state` runs `tofu init` in a temporary directory whose `main.tf` holds only the backend block (`write_terraform_config`, unchanged on upstream main), so `init` installs every provider the state's resources name, unpinned, at the newest version the registry offers (ansible-collections/cloud.terraform#222). On 2026-11-25 `bpg/proxmox` v0.124.0 was listed without a `linux_amd64` package, and every load of `gonkputer.terraform_state.yml` failed with "Incompatible provider version", while the same scratch `init` took `ansible/ansible` v1.5.2 against the root's `= 1.5.0`.
- `ansible-generated/bin/tofu-gonkputer` and `tofu-oracle` give that `tofu` a `TF_CLI_CONFIG_FILE` whose only installation method is a `filesystem_mirror` of `tofu/<root>/.terraform/providers` (`include = ["*/*/*"]`), the root's own unpacked providers, so the inventory reads state with exactly the root's pinned versions and downloads nothing; gonkputer's digest took 13 s.
