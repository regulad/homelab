# ncsusplitt: Duo passcodes from a TOTP secret, not pushes (2026-10-29)

- systemd's start limit is a fixed window from the first start job, so `ncsu-tun`'s DNS wait in `ExecStartPre` spends part of its 600 s. After the 2026-10-29 reboot, that window would have closed 72 s after the fourth start was refused; a slower resolver would have allowed further batches of three logins.
- Duo Mobile's activation, `POST https://api-<id>.duosecurity.com/push/v2/activation/<code>?customer_protocol=1`, takes the QR code's value, `<code>-<base64 of the API host>`, works once, and answers with `hotp_secret`, 32 lowercase hex characters. Duo refuses an old `app_version`; 4.115.0 worked.
- Despite the name, NC State's Duo checks such a device's passcodes as TOTP codes: 6 digits every 30 s, keyed by the secret's own bytes. HOTP codes for counters 0, 1 and 2 were each refused within 3 s.
- openconnect puts OATH codes in an AnyConnect form's `secondary_password`, and reads `--token-secret=@file` before it contacts the server, so a missing file fails without a login. In HOTP mode it writes the advanced counter back to the file before sending each code; in TOTP mode it never writes, so the secret can come through `LoadCredential`.
- alock locks every host that any play in `maintenance.yml` resolves to, whatever `--tags` selects, so a maintenance run needs `--limit` to its own hosts when others carry applies the branch lacks.
