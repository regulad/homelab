# hass-livingston.regulad.xyz back, on ingress's Caddy (2026-10-31)

- Its route had been the deleted `aboriginal` tunnel's `http://localhost:8123`. It is now a DNS-only CNAME to `ingress.regulad.xyz`, as ingress's other sites are; arawi's split-horizon RPZ rewrites that CNAME target for LAN clients, so the name needs no entry of its own there.
- Home Assistant 2026.10 keeps its HTTP settings in `.storage/http`, as a `stable` and a `pending` config. Its first start migrated `configuration.yaml`'s `http:` block once (`yaml_migration_done`), and later starts ignore the YAML, raising the repair `yaml_still_present_after_migration` while the block stays; the YAML stops working in 2027.2. The UI and the WebSocket command `http/config/set` stage a `pending` config, which the next start uses and reverts to `stable` five minutes later unless `http/config/promote` confirms it. With Home Assistant stopped, `stable` can be edited directly.
- With `use_x_forwarded_for`, a request whose peer is not in `trusted_proxies` gets a 400, and Home Assistant logs "Received X-Forwarded-For header from an untrusted proxy". ingress has no temporary addresses, so over IPv6 it connects from its EUI-64 GUA, which rotates with the delegated prefix and so cannot be listed. Its Caddy reaches Home Assistant over IPv4 alone, as it does Jellyfin, and the list names only ingress's reserved `10.23.2.31/32`, in place of the `127.0.0.1/32` cloudflared used.
- For six to seven minutes after each start, Home Assistant's process runs at 100% CPU and answers requests only in short gaps, `/manifest.json` and `/api/` alike, the first within seconds of the start; ingress's Caddy gives a 504 meanwhile. A single answer is no sign it is up; after the last start it answered every request only from about six and a half minutes in.
- `login_attempts_threshold` went from -1, which never bans, to 5. Home Assistant counts any request to its API without a valid token as a failed login, so polling `/api/` from the host banned `127.0.0.1` after five of them, and a ban answers 403 to every request, `/manifest.json` included. Bans are read from `ip_bans.yaml` at start, so lifting one means editing it with Home Assistant stopped. `/manifest.json` needs no token and counts for nothing.
