# Caddy is built weekly by caddy-build.timer, each plugin held to its release line (2026-11-05)

- xcaddy v0.4.7 checks every version that starts with `v` with Masterminds' `semver.StrictNewVersion`, which needs major, minor and patch, so a Go module prefix such as `@v0.17`, or `v2` as Caddy's version, is refused before `go get` sees it. A version that does not start with `v`, such as `latest` or a comparison like `<v0.18.0`, is passed to `go get` unchanged. Go's version queries take the highest release below a `<` bound, prefer releases to pre-releases, and skip retracted versions.
- Built with no Caddy version, xcaddy took the lowest Caddy its plugins required, v2.11.7, while v2.11.9 was out; `"<v3.0.0"` takes the newest v2.
- Souin is cache-handler's dependency, not a plugin of its own, so it moves only when a cache-handler release on the held line requires a newer one.
- The first build on ingress took 48 s of wall clock, 1 min 22 s of CPU and a memory peak of 1.3 GB. `caddy build-info` lists Go's version, every module with its version and hash, and the build flags (`-trimpath=true`, `CGO_ENABLED=0`), which caddy-build compares to decide whether a build is new.
- `/usr/local/bin/caddy` stays watched by AIDE, so a build that changes it appears in ingress's next report.
