# tofu/cloudflare adopts the Cloudflare account, its OCI records fed by tofu/oracle (2026-11-04)

- Cloudflare's API takes only bearer secrets. An account-owned token (its value begins `cfat_`) answers the account endpoints; a user token (`cfut_`) fails them, and lists no zones unless it is granted them. An account-owned token cannot read user tokens, and the Page Rules API refuses it outright, so page rules stay unmanaged. The Cloudflare MCP connection, signed in as Parker by OAuth, could read neither API tokens nor R2 (HTTP 403).
- Which token a host holds shows without printing it: `/accounts/{account}/tokens/verify` and `/user/tokens/verify` return the token's ID, which matches a listed token's. That way Caddy on ingress was found to use the 2026 `Edit zone DNS` account token, certbot on mail `mailk`, and cloudflare-ddns on dodo and ingress, with certbot on dodo, one user token.
- Records that hold a GUA come from `tofu/oracle`'s outputs, `public_addresses` and `email_dkim`, through `terraform_remote_state`. Its encryption block names a `remote_state_data_source "oracle"` with a key provider `pbkdf2 "oracle"`, the same name as `tofu/oracle`'s own, which its state's encryption metadata records; a different name would need `encrypted_metadata_alias` on both sides. `prepare.sh` copies tofu/oracle's passphrase from its own SOPS file into the inputs.
- A consuming root can plan before the producing root applies its new outputs. A gitignored `*_override.tf` sets the `terraform_remote_state` data source's `defaults` to the producer's planned outputs, taken from `tofu show -json` of its saved plan (`.planned_values.outputs`). Delete it before applying.
- Zone settings were compared against `regulad.net`, created 2026-10-18 and never changed, as a new zone's. `regulad.xyz` differs in nine (`0rtt`, `always_use_https`, `browser_check`, `min_tls_version`, `pseudo_ipv4`, `replace_insecure_js`, `security_header`, `ssl`, `tls_1_3`); the other zones differ in none.
- Provider findings, v5.28.1:
  - An SRV record needs `priority` both at the top level and in `data`. Either alone plans an in-place update setting the other to null.
  - A TXT record's `content` is the string Cloudflare stores, quotes included, and a long value is split into quoted 255-byte strings.
  - Import IDs: `cloudflare_zone` and `cloudflare_zone_dnssec` take `<zone_id>`; `cloudflare_dns_record` and `cloudflare_zone_setting` `<zone_id>/<record or setting id>`; `cloudflare_ruleset` `zones/<zone_id>/<ruleset_id>`; `cloudflare_zero_trust_tunnel_cloudflared`, its `_config` and `cloudflare_account_token` `<account_id>/<id>`.
- alock lists the hosts a `tofu/oracle` apply locks with `ansible-inventory` from `ansible-generated`, so a worktree needs `ansible-generated/collections` linked from the main checkout; without it, the apply stops before it runs.
- Deleted: the TXT `_acme-challenge.dodo.regulad.xyz`, a certbot leftover from 2026-08-04; the `mastodon` tunnel and its CNAME; the 2025-02-07 `Edit zone DNS` account token, unused since 2025-06-13; and `regulad.xyz`'s `http_request_dynamic_redirect` ruleset, whose one rule redirected `redirector.regulad.xyz`, which no record answered for.
- Broken, and kept as it is: the `_mta-sts` TXT record is wrapped in curly quotes, so it does not begin with `v=STSv1`, and no `mta-sts` host serves a policy. Two of the three page rules never act, since a page rule acts only on proxied traffic and neither `regulad.xyz` nor `www` is proxied; only `t.regulad.xyz`'s does.
