# kodi-plugins publishes again: ingress admits SSH from the tailnet, and kodi-publish replaces www-data (2026-11-17)

- kodi-plugins had not published since 2026-09-24. Three separate things stood in the way; each showed only once the one before it was fixed.
  - **Auth key:** the hand-made `ci-kodi` auth key had no tags, so its runners joined as user-owned nodes with Parker's access. Its federated identity joins them as `tag:ci-kodi`, which the policy lets reach only ingress's SSH, and DNS.
  - **Firewall:** ingress's Proxmox firewall, given on 2026-11-04, admitted only web traffic. SSH timed out from the LAN too: a `/dev/tcp` probe from matrix showed 443 open and 22 silent.
  - **Shell:** the publisher logged in as `www-data`, whose key was placed by hand and whose shell was back to `/usr/sbin/nologin` ("This account is currently not available"), most likely reset by base-passwd's `update-passwd`. Its home still held a `.bash_history` from September.
- **Source addresses:** tailscalerouter (gonkputer) forwards the homelab's subnet routes with `snat_subnet_routes: false`, so a tailnet client reaches LAN hosts from its tailnet address. A Proxmox firewall rule for such traffic admits `module.shared.tailscale_cidrs`, not the router's LAN address.
- **Login users:** `host_files` creates only `nologin` system users. Its `host_files_login_users` makes a system user with a shell, `*` as its password and its whole `authorized_keys`. base-passwd's `update-passwd` touches only the static accounts in its master list, so a dynamic system user keeps its shell.
- **Directories:** `host_files_directories`' `recurse: true` hands a tree to a new owner, as `/srv/kodi` went from `www-data` to `kodi-publish`. Check mode cannot show it before the user exists.
- `gh run rerun <id> --failed` re-runs a publish after a fix on the host side without a new commit, and `gh run watch --exit-status` waits for it.
