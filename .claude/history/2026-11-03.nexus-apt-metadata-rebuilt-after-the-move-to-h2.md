# nexus: APT metadata rebuilt after the move to H2 (2026-11-03)

- **A migrated APT repository keeps its packages but not its metadata.** After the move from OrientDB to H2 on 2026-10-28, the `ios` hosted repository listed its 41 packages under `pool/` but had no `dists/` assets at all, so every `dists/stable/...` path answered 404. ingress's `cydia-sync`, which mirrors it, failed about 94 times a day from then on.
- **Sonatype's upgrade path** calls for the "Apt - Rebuild Apt metadata" task on each APT (and Helm and Yum) repository once a database is H2 or PostgreSQL, from 3.48.0. Nexus otherwise rebuilds a hosted repository's metadata only as its packages change.
  - The task's type is `repository.apt.rebuild.metadata`, with the properties `repositoryName` and `rebuildAptMetadataFullRebuild` (`RebuildAptMetadataTaskDescriptor` in nexus-public). It is created through ExtDirect, as the compaction tasks are.
  - A full rebuild of `ios` took seconds; the whole play 37 s. Requests may answer 503 while it runs.
- **Anonymous access** to Nexus's REST API lists repositories, components and assets, but answers 403 for a repository's settings.
