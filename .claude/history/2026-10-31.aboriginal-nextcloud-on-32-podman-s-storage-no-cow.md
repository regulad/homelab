# aboriginal: Nextcloud on 32; Podman's storage no-COW; inotify watches for clamonacc (2026-10-31)

- The "No space left on device" was inotify's, not the disk's. With Nextcloud's data moved into `/srv`, which clamonacc watches, its tree of over 467,000 directories needed more watches than `fs.inotify.max_user_watches` allowed, 249,909 by default here, and `inotify_add_watch` answers ENOSPC once they run out; systemd logged the same for its cgroup watches. The filesystem still had 79 GiB free in its data chunks. The limit is now 1,048,576, and clamonacc started with it.
- A reflink copy of `/srv/nextcloud`, which is no-COW, into an ordinary directory copied it in full, as btrfs clones a file only into one of the same kind. Before an upgrade only the database is copied.
- Podman's storage on aboriginal was ordinary COW, as were the volumes the move had made. The podman role now sets `+C` on Podman's storage root and its `volumes` and `overlay` directories on btrfs, which new volumes and layers inherit. `+C` does nothing to a file that already holds data, so Nextcloud's five volumes were rewritten: each `_data` moved aside, a new `_data` given `+C` and the old one's owner and mode, and the contents copied into it with `--reflink=never`.
- 32.0.3 to 32.0.15: the image's entrypoint ran `occ upgrade`, which sets the log level to debug for its run and puts it back, and updated contacts and mail from the App Store. `occ setupchecks` then reported missing optional indices, `.well-known` URLs that do not resolve, and a log it cannot read back from `/dev/stderr`.
