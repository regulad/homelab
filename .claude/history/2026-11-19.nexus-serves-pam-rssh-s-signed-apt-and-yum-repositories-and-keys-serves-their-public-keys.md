# Nexus serves pam_rssh's signed APT and YUM repositories, and keys serves their public keys (2026-11-19)

- **Nexus returns a repository's private signing key, but never its passphrase.** `GET /v1/repositories/<format>/<type>/<name>` includes `aptSigning.keypair` or `yumSigning.keypair` as stored, so every task that reads repositories is `no_log`. `nexus_repositories` compares the keypair, which Nexus returns byte for byte as sent, and adds the passphrase only to what it writes; a second run writes nothing.
- **A repository's privileges exist only once the repository does,** so the repositories play runs before `nexus_security`, whose roles name them.
- **The signing keys:** 11 Ed25519 keys, each encrypted with a passphrase of its own, were generated inside `sops edit` by an editor script, with GnuPG's home on tmpfs (`/dev/shm`), so no key reached disk decrypted. GnuPG exports a protected secret key still protected. Each was checked to refuse signing without its passphrase and to sign with it.
- **A new, empty APT hosted repository answers 404 for `dists/<distribution>/InRelease`,** so its signature can be checked only once packages are uploaded.
- **`uri` labels a raw body as form data.** Without its own `Content-Type`, it sends `application/x-www-form-urlencoded`, and Nexus answered 201 to such a PUT while storing an empty file. `nexus_repositories` sends raw files as `application/octet-stream`.
- **A raw repository's content type validation refuses armored public keys as `.asc`:** "Detected content type [text/plain], but expected [application/pgp-signature, application/pgp]", whatever `Content-Type` the upload carries. `keys` has validation off, as only svc-ansible writes there.
- **One key signs both iOS repositories:** the `ios` APT repository's key in Nexus, set by hand, is `cydia_signing_key` in ingress's SOPS, which cydia-sync signs the Cydia repository's flat files with. It's RSA 4096, fingerprint `0372A2434FB7030C9294AA20EE8592B68FF8E3F5`, served as `keys/ios.asc`. No other Nexus repository signs.
