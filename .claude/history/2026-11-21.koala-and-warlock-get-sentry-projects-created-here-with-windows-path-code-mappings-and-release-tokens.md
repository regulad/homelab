# Koala and Warlock get Sentry projects, created here, with Windows-path code mappings and release tokens (2026-11-21)

- **A project created by the provider gets Sentry's own key and alert** unless told otherwise: Sentry makes a key named `Default` and the "Send a notification for high priority issues" alert, and `sentry_key` and `sentry_alert` always create new ones, so modelling a new project on an adopted one leaves two of each. `default_key = false` makes the provider delete every `Default` key right after creating the project (in 0.16.0 and upstream master, only in `Create`), before the declared key exists; `default_rules = false` stops the alert. The issue-stream monitor comes either way: Sentry creates a project's default detectors on its first save (`workflow_engine/receivers/project_detectors.py`), and the data source, which depends on the new project, is read during apply.
- **The GitHub integration adds every new regulad repository to Sentry by itself:** Koala, Warlock and devourer were all there, so a `sentry_organization_repository` for one is an import. `organizations/<org>/repos/?query=<name>` gives its ID; the integration's `repos/` listing shows `isInstalled: true` for a repository Sentry already holds.
- **Code mappings match Windows paths literally.** `_map_frame_path_to_source_path` (`src/sentry/issues/auto_source_code_config/code_mapping.py`) requires the frame's `filename`, then `abs_path`, to start with the stack root, case and backslashes included, then writes `\` as `/` in the mapped path; a root ending in `\` is a directory mapping. The API takes backslashes (its pattern refuses only whitespace and quotes). GitHub's `windows-latest` runner checks out to `D:\a\<repo>\<repo>`, as both repositories' Check runs show.
- **The stack-trace link endpoint confirmed every mapping before any event:** `projects/<org>/<project>/stacktrace-link/` with `file`, `absPath` and `platform=native`, each a Windows path, gave the right repository, branch and file for both checkouts, with each submodule's path sent to its own repository.
- **devourer's frame paths are unverified:** Warlock's `devourer-sys` builds devourer's C++ through CMake and MSVC, not rustc, so the slashes and case MSVC records may differ from the stack root. Check at its first event with a devourer frame.
- **Scrubbing is the organization's for every project:** `get_datascrubbing_settings` (`src/sentry/relay/datascrubbing.py`) ORs each organization requirement with the project's option. A new project's own `scrubIPAddresses` reads `false` in the API, though the organization's requirement applies.
- **Seer's "pull requests are ready" alert** is one organization workflow, listed under every project; a new project needs nothing for it.
- **Sentry organization tokens** (`sntrys_`) answer 403 on `organizations/<org>/` and 200 on `organizations/<org>/releases/`, which checks a new token without its settings page.
- **A secret in one element of a merged map is a valid `for_each`:** `merge()` keeps an element's sensitive mark off the map, so `github_actions_environment_secret` iterates the map directly, with no `toset(keys())`.
