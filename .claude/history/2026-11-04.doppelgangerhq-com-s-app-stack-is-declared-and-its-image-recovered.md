# doppelgangerhq.com's app stack is declared, and its image recovered (2026-11-04)

- The `nefum` organization no longer exists, and packages do not move with a transferred repository. `ghcr.io/nefum/doppelganger` went with it, by tag and by digest ("manifest unknown"). The repository is now `regulad/doppelganger`, and CI publishes to `ghcr.io/${{ github.repository }}` under `web-` tags (`web-latest`, `web-master`, `web-vX.Y.Z` from `v*.*.*` git tags). Its last successful publish, on 2025-11-01, was under `nefum`.
- The image the site ran, 5.1 GB, built from `c7e96a3`, existed only on the host. It was pushed as `ghcr.io/regulad/doppelganger:latest`, which took 3 s because ghcr.io still held its layers. GitHub linked the package to the repository only once `org.opencontainers.image.source` (and `url`) named `regulad`. A two-line Dockerfile of `FROM` and `LABEL` rewrote both labels, which changed the image's ID and manifest but no layer.
- GitHub Packages accepts only classic personal access tokens. Its token form ticks `repo` along with `write:packages`. The token copied from root's Docker config was dead (401 from GitHub's API); its `read:packages` replacement expires 2027-02-02.
- Compose recreated `web` and `redis` and left `cron`, whose image and resolved environment were unchanged, so its labels kept the old file's path until it was recreated by hand. Recreating `redis` kept its anonymous `/data` volume under the new tmpfs, until `--renew-anon-volumes` dropped it.
- `docker_compose_v2` cannot run in check mode before `host_files` has placed the compose file. `docker compose config --quiet` on a copy with its env files stubbed, and `up --dry-run`, show what the apply will do.
- Against `c7e96a3`'s Git blob hashes, the checkout's only change was `docker-compose.yml`'s `/opt/doppelganger` bind. `.env.local` and a stray `nproc` were untracked. With `.env.local` in SOPS and the compose file declared, the checkout was deleted.
- In `sops decrypt | script <(ssh …)`, the substituted `ssh` inherits the pipe as its stdin and can read the decrypted file before the script does. `ssh -n` keeps it off the pipe.
- Watchtower (`containrrr/watchtower`) is archived, and Docker 29 rejects its API version ("client version 1.25 is too old"). The fork `nicholas-fedor/watchtower` is maintained, but it holds Docker's socket, and by default it would also update the devices' containers. `doppelganger-update.timer`, which pulls and runs `up` on this one project, does the same work as `podman-auto-update`.
