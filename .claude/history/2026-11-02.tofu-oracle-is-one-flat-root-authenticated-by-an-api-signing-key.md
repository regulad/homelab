# tofu/oracle is one flat root, authenticated by an API signing key (2026-11-02)

- OpenTofu loads no subdirectories into a module: each one is a separate module that only a `module` block brings in. That is why `tofu/oracle` is flat, its files grouped by name prefix rather than in folders. Upstream, folder-structured modules ([opentofu/opentofu#1971](https://github.com/opentofu/opentofu/issues/1971)) were closed as a duplicate of an `include` statement ([#1767](https://github.com/opentofu/opentofu/issues/1767)), which is still open, labelled `needs-community-input`.
- Of the former `legacy` and `wahlecloud` modules' contents, only Email Delivery was tied to neither VCN. The bronze backup-policy OCID was written in both; it and the platform images are now one map each in `locals.tf`. The agent-plugin lists differ between web and the Oracle Linux instances, so they stay separate.
- Reversing a move fails: `moved` blocks from the root into a module plus blocks back out form a cycle. Resources whose only move was into a module just lost that block, because states from before the modules already hold the root address. In OpenTofu 1.13, `CanChainFrom` chains a resource-level move only from another resource-level move, and an instance-level move only from another instance-level one. A resource-level move followed by an instance-level one for the same address is still ordered correctly, through `NestedWithin`. Two moves to the same destination are rejected as ambiguous, so older generations reach the root by chaining through their former module addresses, one instance at a time. A scratch configuration of built-in `terraform_data` resources, planned against hand-written states of each generation, checked the chains with no provider and no real state.
- The modules' inputs were declared `sensitive`, so the availability-domain names reached resources marked sensitive. The root now wraps its map in `sensitive()`, which keeps them redacted in plans.
- An OCI session token lasts an hour, and `oci session refresh` extends it to at most 24 hours. `--session-expiration-in-minutes` works only with `--no-browser`, at 60 minutes at most. Anything longer needs an API signing key.
- The key is a 2048-bit RSA key generated in memory, written only into `tofu/oracle/provider.sops.env`, with Parker's user OCID taken from the `sub` claim of an expired session token. SOPS's dotenv format stores the PEM's newlines and writes them back as `\n`, and the provider's `private_key` replaces `\n` with newlines before parsing. A single-line `OCI_PRIVATE_KEY` therefore works, whether it is exported by `prepare.sh` or set by `sops exec-env`. The provider reads `OCI_USER_OCID`, `OCI_FINGERPRINT` and `OCI_PRIVATE_KEY` from the environment.
- For 10 to 15 minutes after its upload, the new key worked only some of the time. Four plans in a row had a scattering of requests rejected, 20, 6, 5 and 11 of about 84, on unrelated resources across Core, Identity and Object Storage. Most were `401-NotAuthenticated`, and a few were `401-IdcsConversionError, Client is unauthorized`. Running serially (`-parallelism=1`) made no difference, and the local clock matched OCI's. After a five-minute wait the next plan had no errors. The key evidently reaches each identity-domain endpoint separately, so allow about 15 minutes before relying on a freshly uploaded key. Oracle's API-key page does not mention this delay.
