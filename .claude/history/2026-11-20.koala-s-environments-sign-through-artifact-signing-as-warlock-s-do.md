# Koala's environments sign through Artifact Signing, as Warlock's do (2026-11-20)

- **Identity token subjects:** regulad/Koala (repository ID 1465174461), created after Warlock, also uses GitHub's immutable subject: `GET repos/regulad/Koala/actions/oidc/customization/sub` gives `use_default: true`, `use_immutable_subject: true` and the prefix `repo:regulad@52430642/Koala@1465174461`. A federated credential written as `repo:regulad/Koala:environment:<name>` would never match. Read each new repository's prefix from that endpoint rather than writing the name form.
- **An empty repository takes environments:** before Koala's first push, with no branches, GitHub created its environments, branch and tag deployment policies, and environment secrets through the API, and the policies' patterns need no matching ref to exist.
- **Fresh policies get real IDs:** created where no Probot Settings sync had made them first, each `github_repository_environment_deployment_policy` recorded its live ID and the next plan was clean, unlike the ID 0 entry Warlock's adoption left.
- **Order:** `tofu/github` reads each environment's client ID from `tofu/azure`'s state, so its plan can be made only after `tofu/azure`'s apply. Both go before the repository's first signing run, which would otherwise create the environment it names with no deployment policy.
