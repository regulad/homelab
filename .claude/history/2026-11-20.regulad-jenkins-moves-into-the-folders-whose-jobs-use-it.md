# regulad-jenkins moves into the folders whose jobs use it (2026-11-20)

- **One App, a credential per folder.** Each folder whose jobs work on GitHub holds its own `regulad-jenkins`, a `GitHubAppCredentials` of the same App with the same ID, so a `Jenkinsfile` always binds `regulad-jenkins` and its folder decides what the token may do. The `regulad` organization folder's has every repository and every permission the App has, as the system store's had; `z4yx`'s reads `regulad/jobs` alone. Before, nothing outside `regulad` named the credential but `z4yx/pam_rssh`, which a script-console scan of every item's `config.xml` confirmed.
- **What github-branch-source 1986 mints:**
  - `repositoryAccessStrategy`: `specificRepositories` (owner and repository names) mints for exactly those repositories, or for every repository of the owner when the list is empty. `inferOwner` and `inferRepository` mint only where the job's context names an owner: a multibranch or organization folder's SCM source, or a "GitHub project" property, which Pipeline builds ignore unless `ALLOW_UNSAFE_REPOSITORY_INFERENCE` is set. A plain `pipelineJob` such as `z4yx/pam_rssh` has no context, so only `specificRepositories` works there.
  - `defaultPermissionsStrategy`: `INHERIT_ALL` (every permission of the installation), `CONTENTS_READ` or `CONTENTS_WRITE`; there is no way to ask for other permissions, nor for none.
  - Configuration as Code's `owner:` still works, through a setter kept for it that sets `specificRepositories` with no repositories and raises the plugin's migration monitor. The folders' credentials name the strategy instead.
- **Job DSL and the App's credential:** the dynamic DSL calls it `gitHubAppCredentials` (its descriptor has no symbol; Configuration as Code calls it `gitHubApp`). `privateKey` is a `Secret` and takes no string, so it is passed as `hudson.util.Secret.fromString('''${github_app_private_key}''')`. Configuration as Code puts the PEM into the script before Job DSL runs, so the key's several lines need a `'''` string; a dry run showed them back intact after Jenkins encrypted and decrypted the key.
- **A changed folder loads at a start.** Unlike a folder Configuration as Code creates at a start, which needed `/configuration-as-code/reload`, new properties on the existing `regulad` and `z4yx` were in effect after the restart. Tokens minted from each folder's credential in the script console reached all 241 of regulad's repositories and `regulad/jobs` alone, and both read `z4yx/pam_rssh`'s releases. The root seed job `jobs` sees no App credential.
