# koala-vcam gets a Sentry project for Koala's virtual camera DLL (2026-11-21)

- **A PDB uploaded to Sentry shows the frame paths before any event does:** `projects/<org>/<project>/files/dsyms/` lists a project's debug files, and `?id=<id>` on the same endpoint downloads one with the `homelab-tofu` token; `strings -n 8` over the PDB gives its source paths. Warlock's release PDB, built on `windows-latest`, records its own source as `D:\a\Warlock\Warlock\crates\...`, with an uppercase drive and backslashes only, and MSVC's devourer sources in the same form, `D:\a\Warlock\Warlock\third_party\devourer\...`. Rust's standard library comes out as `/rustc/<hash>/library/std\src\...`, with mixed separators, and crates.io's as `C:\Users\runneradmin\.cargo\registry\src\index.crates.io-<hash>\...`, so no Koala or Warlock root matches either.
- **The stack-trace link endpoint keeps an earlier mapping's error:** for a path that only a project's second mapping matches, `projects/<org>/<project>/stacktrace-link/` returns the correct `sourceUrl` and `config.stackRoot` with `"error": "stack_root_mismatch"` still set from the mapping it tried first. koala, koala-vcam and warlockctl all answer this way for their development checkout, so trust `sourceUrl`, not `error`.
- **Release health has no project switch:** a Sentry project has no setting that turns sessions on or off; a project shows release health only if its SDK sends sessions, so leaving it out is the client's choice.
