# aboriginal: Home Assistant on 2026.10; upgrade copies keep the config directory's no-COW (2026-10-31)

- aboriginal's Home Assistant and Jellyfin config directories on the SSD are no-COW (`chattr +C`) on purpose, sparing their writes the latency of COW's write amplification. A file takes the attribute when it is created, so Home Assistant's recorder database, older than the attribute, is still COW, while the 494 files made since, such as `.cache/brands` and the database's WAL, are not; in Jellyfin's, all but 7 of 16,526 files are.
- btrfs clones a file only into one of the same kind, and no-COW files carry no checksums, so `cp --reflink=always` into an ordinary directory failed with EINVAL (`failed to clone ... Invalid argument`) on each of them. The first upgrade rolled back at the copy: it was incomplete, so nothing was put back, and Home Assistant ran 2026.6.4 again on its untouched directory. Jellyfin's upgrade made the same copy.
- Both upgrades now give the copy's directory the config directory's attribute, which everything `cp` creates in it inherits, and copy with `--reflink=auto`, which copies in full what cannot be cloned. Home Assistant's copy shared 5.7 MiB and copied 549 MiB in full, mostly the database.
- From 2026.6.4 to 2026.10.4, the only error not in the 2026.6 run's log was one failed NUT fetch, which recovered at the next poll.
