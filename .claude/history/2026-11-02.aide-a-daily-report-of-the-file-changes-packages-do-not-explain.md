# aide: a daily report of the file changes packages do not explain (2026-11-02)

- **Versions.** The releases' AIDE is 0.18.6 (Ubuntu 24.04), 0.19.1 (Debian 13) and 0.19.2 (Ubuntu 26.04, Oracle Linux 9.8, AlmaLinux 10.2). All have `report_format=json`, from 0.18.
  - The JSON's attribute names are AIDE's field names, not its config letters: `modify_time`, `change_time`, `access_time`, `link_count`, `block_count`, `growing_size`, `link_name` and `file_type`, not `mtime`, `lname` and the like.
  - JSON escapes only backslashes, so a path with a quote or newline breaks it. aide-report then mails the report unfiltered.
- **The packages' own checks.**
  - Debian and Ubuntu ship `dailyaidecheck.timer`, whose built-in filter (`FILTERUPDATES`) drops every file of a package upgraded since the database's date, whatever the file now contains. Their `/etc/cron.daily/dailyaidecheck` exits when systemd runs.
  - Enterprise Linux ships `aide-check.timer`, which runs `aide --check` and mails nothing.
  - Upstream has no package-manager integration: [aide#30](https://github.com/aide/aide/issues/30), open since 2019.
  - Both distributions' timers are masked, and aide-report filters with the package manager instead.
- **The filter.**
  - rpm's per-file query needs `%{=TAG}` for the package's own fields inside `[...]`; without it rpm refuses the format ("array iterator used with different sized arrays").
  - dpkg records its files' contents alone, so the mode of a file a package installed since the baseline is not checked; on rpm it is.
  - dpkg's records under `/var/lib/dpkg/info`, maintainer scripts among them, are explained by their package's version rather than excluded.
- **Rules.**
  - AIDE cannot restrict a rule to a filesystem type or one filesystem, so aide-report writes `!<mount point>(/|$)` for every mount point but `/`, `/boot`, `/boot/efi`, `/usr` and `/var`, and `!<file>$` for each swap file in `/proc/swaps`, before each run.
  - AIDE does not walk into a directory a negative rule excludes, whatever a deeper rule selects: with `!/var/cache(/|$)`, a `/var/cache/apparmor` rule in either order found nothing on 0.18.6 and 0.19.2, against a control without the exclusion.
  - Entries for paths the configuration has since excluded are reported as removed.
- **Debian and Ubuntu watch more.** Their rules end in a catch-all, `/ 0 Full`, so service data anywhere on the root filesystem is watched, as softether's `/usr/local/vpnserver` logs and saved configuration were. So are home directories: aboriginal's first baseline was still hashing after more than 1.5 hours, through about 80 GB of `/srv/nextcloud`, `/home/regulad` and `/home/linuxbrew`, at 460 MB resident. Enterprise Linux's rules watch system directories alone.
- **Noise sources excluded:**
  - the rpm database (`rpmdb.sqlite-shm` changes on every query);
  - dnf's history and caches, `/var/cache`, apt's lists, sysstat's data, `/tmp`, `/var/tmp` and `/var/crash`;
  - Ansible's scratch files under `~/.ansible/tmp`, which every task creates, the wait for `aide-accept`'s new baseline among them, and `/tmp/ansible_*` payloads where `/tmp` is on the root filesystem.
- **AppArmor's compiled cache.** It sits under `/var/cache`, so hosts with AppArmor set `skip-cache` in `/etc/apparmor/parser.conf`. Every load is then a cache miss, nothing is written, and each profile logs "Failed to create cache", as the boot script still passes `--write-cache`.
- **Refresh after each run.**
  - `aide --update --limit REGEX` re-records only the matching entries and carries the rest over. The regex is anchored at the start of each path.
  - The `aide_written` callback hands the run's written paths to the final play through an environment variable that the forked workers inherit.
  - Its `DOCUMENTATION` must be valid YAML: a line with "word: " in it stopped every playbook from loading.
  - In a folded YAML scalar, Jinja's `split('\n')` doesn't split on newlines; `.splitlines()` does.
- **Costs.**
  - A baseline took about a minute on wako and one to two on the Ubuntu containers; a report took from 19 s to 2 minutes.
  - AIDE's own RSS was about 65 MB. The unit's memory peak, 460 to 875 MB, is mostly page cache charged to its cgroup.
  - In unprivileged containers AIDE logs "Failed sending audit message", harmlessly.
