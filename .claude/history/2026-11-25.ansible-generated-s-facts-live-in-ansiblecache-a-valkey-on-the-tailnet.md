# ansible-generated's facts live in ansiblecache, a Valkey on the tailnet

- Facts are not results of the comparison a check makes. `setup` runs on the host and reports what the host is (distribution and release, CPUs, addresses, mounts); the controller then compiles the declared state from the repository's inventory, variables, roles and templates, reading those facts where a role or variable needs them (`when: ansible_facts.distribution_release == …`, doppelgangerhq.com's `ansible_processor_vcpus`, cachefilesd's `mounts`); only then does each task's module compare that declared state with the host's, on the host. A fact cache saves only the first of the three, one `setup` per host, and none of the comparisons that make up nearly all of a check's time. It was thought to cache comparisons, which is why importing the existing local cache was planned and then dropped.
- What the roles read of facts changes only outside Ansible's runs (a hand edit, a reboot, a resize, a point release) or through an apply, which re-gathers its hosts' facts (`ansible-common/playbooks/facts.yml`); the cache keeps them two days, and an apply to an inventory source's root clears ansible-generated's.
- `community.general.redis` connects with `StrictRedis(host, port, db, password, ssl=…)`: it logs in as the default user, as it passes no username, and `tls://` verifies against the system's trust store alone, with no option for a CA of our own. Tailscale Serve's TLS-terminated TCP (`tailscale serve --tls-terminated-tcp=<port> tcp://…`), which presents the node's publicly trusted certificate for its `ts.net` name and renews it itself, satisfies that with no certificate files; its status lists such a port under `TCP` with `TCPForward` and `TerminateTLS` (`TCPPortHandler`, `ipn/serve.go`), which `tailscale_node` now reads and converges.
- The plugin needs the `redis` package in the Python that runs Ansible, which collections cannot provide: `ansible-generated/python-requirements.txt` pins it by hash, resolved with `uv pip compile --generate-hashes --exclude-newer`, and `ansible-generated:init` installs it into `.task/python`, which `tasks/ansible.sh` puts on `PYTHONPATH`; redis-py is pure Python, so the controller's Python does not matter.
