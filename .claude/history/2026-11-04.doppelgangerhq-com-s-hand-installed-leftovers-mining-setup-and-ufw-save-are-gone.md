# doppelgangerhq.com's hand-installed leftovers, mining setup and ufw save are gone (2026-11-04)

- Ubuntu's `firewalld.service` has `Conflicts=netfilter-persistent.service`. When firewalld first started on doppelgangerhq.com on 2026-10-30, it stopped `netfilter-persistent`, which has not started since. From the next boot, the image's `iptables-persistent` save no longer loaded, and with it went Oracle's `InstanceServices` rules and the old ufw chains. `iptables -S` then showed only Docker's rules. Oracle's rules are now firewalld direct rules from `files/shared/oci/direct.xml`, as on the other OCI instances.
- The image, built 2025-09-21, had diverted `/etc/default/netfilter-persistent` to `.diverted` with a local dpkg diversion, to set its restore options. Purging the packages left the diversion and both files behind; `dpkg-divert --local --remove` cleared them. Purging ufw left `/etc/ufw` holding only the application profiles of openssh-server, nginx-common and postfix, which those packages own.
- Purging the hand-installed packages with `--autoremove` removed 117. `linux-headers-generic` takes `linux-generic`, which depends on it, and with that `ubuntu-kernel-accessories` (bpftrace, bpfcc-tools), which `linux-generic` recommends. `linux-image-generic` stays, manual and in `host_files_packages`, so new kernels and binder still arrive. `fuse3` stays: snapd depends on `fuse3 | fuse`, so purging it makes apt install FUSE 2 (`fuse`, `libfuse2t64`) instead. In `apt-get -s` output, an `Inst` line shows such a swap.
- Parker's own xmrig miner and `websocat-proxy.service`, which forwarded `127.0.0.1:3333` to an ngrok tunnel, were removed along with their `miner` user.
- The direct rules' owner and comment matches and REJECT targets load `xt_owner`, `xt_comment` and the REJECT modules when firewalld first applies them. At boot, firewalld starts before Docker and the Android containers that empty `/proc/sys/kernel/modprobe`, so they still load then.
