# AIDE explains microcode_ctl's and weak-modules' links for each kernel (2026-11-04)

From tailscalerouter's report after dnf-automatic installed kernel-core 5.14.0-687.65.1 and kernel-uek-core 6.12.0-208.112.5 and removed 5.14.0-687.58.1 on 2026-11-04.

- **Each kernel on Enterprise Linux gets two trees no package owns.**
  - **microcode_ctl** (20260812) makes `/usr/lib/firmware/<release>/`, holding `intel-ucode/` links into its own `/usr/share/microcode_ctl/ucode_with_caveats/` and five `readme-intel*` files: 167 entries per kernel on tailscalerouter.
  - **weak-modules** links an installed kmod's modules into `/usr/lib/modules/<release>/weak-updates/` for each kABI-compatible kernel. Here that was kmod-kvdo's `kvdo.ko`, built for 5.14.0-687.3.1: 3 entries for the RHCK kernel, none for UEK.
- **What it explained before:** aide-report explained neither tree, so the report held all 507 of them and nothing else; the mail stopped at its 400 lines. It now explains both as it does a kernel's initramfs and depmod's indexes, by their release: added with a kernel package installed since the baseline, or gone with one removed since. Replaying the report explained all 507.
- **Not covered:** a change to these trees for a kernel installed before the baseline stays in the report.
