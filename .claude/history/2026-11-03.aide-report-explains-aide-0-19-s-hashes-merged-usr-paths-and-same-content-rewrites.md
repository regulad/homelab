# aide-report explains AIDE 0.19's hashes, merged /usr's paths and same-content rewrites (2026-11-03)

A survey of every host's report, each run once as its timer would with the mail printed instead, after the fleet-wide apply of the engine checks.

- **AIDE 0.19 added three hashes.** Its JSON names them `sha512-256`, `sha3-256` and `sha3-512` (the last column of `attributes[]` in `src/attributes.c`), beside the new `fs_type`. aide-report's `CHECKSUMS` held 0.18's names alone, so on Debian 13 and Ubuntu 26.04 no file whose contents a package update changed was vouched for: prodingus's report held 1,106 changes on the morning unattended-upgrades brought Ceph 19.2.7 and a new pve-qemu-kvm. rpm hosts vouch by `rpm --verify`'s flags, without `CHECKSUMS`, and were unaffected.
- **Merged /usr.** dpkg records each path as its package lists it, `/sbin/mount.ceph` or `/lib/systemd/system/tailscaled.service`, and dpkg 1.22 does not resolve the links: `dpkg -S /usr/sbin/mount.ceph` finds nothing. AIDE does not follow `/bin`, `/sbin` or `/lib*` and reports the path below `/usr`. aide-report now maps the paths dpkg lists, the failures `dpkg --verify` reports and an older manifest's paths through the links the host has.
- **AIDE's summary tells what it compared.** A changed entry's summary has a column per attribute in `report_attrs_order` (`src/report.c`), the same in 0.18.6 and 0.19.2: column 1 is the link target and column 12 the hashes. `.` means AIDE recorded the attribute at both ends and found it unchanged; a space means the entry's rule does not record it. aide-report now leaves out a file whose hashes, or a symlink whose target, show `.` and whose only changes are its timestamps and inode: a rewrite with what it held, such as `/etc/passwd` after `adduser`, `ld.so.cache`, the timers' stamps and APT's periodic stamps. A rule without hashes leaves the column blank, so such a file stays in the report.
- **A database is not an accepted baseline.** Ubuntu's package built `/var/lib/aide/aide.db` when it was installed on pihole, so the role's first baseline, keyed on the database, never ran, and pihole's report compared against that install-time database (7,353 changes). The role and aide-report now key on aide-report's manifest, which only `--baseline` writes.
- **Debian's own rules cover Debian's packages.** `aide.conf.d` has rotation-aware rules for those packages' logs and the stamps of their timers, and none for Proxmox's, Ceph's, Tailscale's, certbot's or the homelab's own (`aide-report.timer`, `restic-*.timer`, `podman-auto-update.timer`). What those write as they run is excluded instead, in the role for every host and in host_vars per service.
- **Noise found and excluded:**
  - Tailscale's `tailscaled.log1.txt` and `log2.txt`, `derpmap.cached.json` and `dns-cache/`; `tailscaled.state` stays watched.
  - Postfix's spool, where its pid files and chroot copies of `/etc` also live, and `/var/lib/postfix/prng_exch`.
  - Ubuntu Pro's `apt-esm` copy of APT's lists and caches, unattended-upgrades' state and logs, apt-listchanges' records, DHCP leases, smartd's state, and clamonacc-mail's cursor.
  - Proxmox leaves `/var/lib/lxc/<vmid>` behind after `pct destroy` and rewrites it at each start; prodingus held nine for containers long gone.
  - certbot keeps up to 1,000 logs and renames each one along at every run (livekit held about 640, doppelgangerhq.com more); on livekit each keeps the SELinux label of the run that wrote it, `cron_log_t` or `var_log_t`.
  - Wings keeps the game servers' volumes, archives, backups and its own database in its default root, `/var/lib/pterodactyl`.
  - Caddy on ingress keeps its data in `/caddy`: its unit runs it as root without HOME, and Caddy then falls back to `./caddy` (`AppDataDir` in `storage.go`), from the unit's working directory `/`.
- **Ansible's scratch files are in the home of the user it connects as.** On dodo and doppelgangerhq.com the operator's SSH configuration names that user, not the inventory, so the exclusion built from `ansible_user` named root's instead; aide-accept's wait for the new baseline would have put its own scratch directory into it. The role now reads the connecting user's `$HOME` with `become: false`.
- **A leftover overlay probe counts as damage.** c/storage's overlay driver makes `opaque-bug-check<N>` in its store to test native diffs and removes it with `defer` (`drivers/overlay/check.go`); one left behind, as on uptime, makes `podman system check` report "layer in lower level storage driver not accounted for".
- **ClamAV's `--move` leaves a lock behind at each stop.** clamonacc creates `.clamav-quarantine-lock.<pid>.<n>` in the quarantine and removes it only through `atexit` (`common/actions.c`, 1.5.4). Its unit stops it with `SIGKILL`, as upstream's does, so each restart leaves one: aboriginal's `/root/quarantine` held 81.
- **Surveying the fleet.**
  - Ansible's `script` module through `proxmox_pct_remote` ran the check in a locale the containers lack, `en_US.UTF-8`. AIDE treats any output on standard error from an `@@x_include` script as a failure ("execution failed (exit status: 0)"), and Debian's scripts run bash, which warns about the locale, so every container's check failed. The timer runs with the host's own locale and was unaffected; the `shell` module sets `C.UTF-8`.
  - An SSH session that printed nothing for half an hour, while dodo's and doppelgangerhq.com's checks ran, was dropped on the way, and ssh gave up on it only about two hours later. Ad hoc `-B`/`-P` (async with polling) keeps the connection busy.
