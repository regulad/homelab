# AIDE's refresh covers the links a unit's [Install] names, Alias= and Also= among them (2026-11-04)

- **Enabling a unit makes more links than its own name.** On ncsusplitt, where systemd-resolved was installed but disabled beside unbound, the `resolved` role's `systemctl enable` made four links at once, from the `[Install]` of Ubuntu 26.04's systemd-resolved 259: `sysinit.target.wants/systemd-resolved.service` (`WantedBy=`), `dbus-org.freedesktop.resolve1.service` (`Alias=`), and `sockets.target.wants/` links to `systemd-resolved-varlink.socket` and `systemd-resolved-monitor.socket`, which its `Also=` names and each of which is `WantedBy=sockets.target`. The refresh, by the unit's own name, covered only the first, and AIDE mailed the other three.
- **The packages explain a unit's links only after an install.** aide-report vouches for the links a unit file's `[Install]` names only when its package was installed or upgraded since the baseline. A unit that Ansible enables from a package already there depends on the refresh.
- **`aide-report --refresh --units` now reads each unit's file,** as `systemctl enable` finds it: the first of its name in `/etc/systemd/system`, `/run/systemd/system`, `/usr/local/lib/systemd/system`, `/usr/lib/systemd/system` or `/lib/systemd/system` that is not a mask, followed through links. An instance with no file of its own takes its template's, with the links named for the instance. A unit given by an alias, such as `sshd` for Debian's `ssh.service`, takes the file the alias links to, with the links named for that unit. It covers every link the `[Install]` names, with each `.wants`, `.requires` or `.upholds` directory that holds one, and the same for each unit an `Also=` names, followed until none is new.
- **Not covered:** specifiers such as `%i` in `[Install]` values, and the `DefaultInstance=` links of a template enabled by its template's name. No homelab role enables such a unit.
