# doppelgangerhq.com's legacy VCN routes and admits IPv6 egress (2026-11-04)

- doppelgangerhq.com had an IPv6 address but no IPv6 path out. The legacy VCN's default route table sent only `0.0.0.0/0` to the internet gateway, and its default security list allowed egress only to `0.0.0.0/0`. Both were needed: the route table and the security list now cover both families through `local.dual_stack_internet_cidrs`, as wahlecloud's do. Afterwards, `curl -6` from the host connected to Oracle's auth endpoint and to Google in about 4 ms.
- An address without a route is worse than no IPv6 at all: clients that prefer IPv6 time out on it before trying IPv4. The OCI Unified Monitoring Agent (Ruby 3.3, net-http 0.9.1, no Happy Eyeballs) tried the IPv6 addresses of the dual-stack `auth.us-ashburn-1.ds.oci.oraclecloud.com` first. Its 60 s `open_timeout` ran out on the first address before any IPv4 address was tried ("Failed to open TCP connection … (execution expired)"). `unified_monitoring.json` logged `LAST_CP_REFRESH_STATUS` `FAIL` on every run since at least 2026-06-06, about 68 a day. Postfix's 30 s wait on mail's AAAA, in the 2026-10-30 clamonacc entry, had the same cause. No Unified Agent configuration targets the host, so even a successful refresh downloads nothing, as on mail.
- The security list also admits ICMPv6 Packet Too Big (type 2) from `::/0`, as wahlecloud's does. Without it, IPv6 path MTU discovery fails and large packets are dropped silently.
- The OCI provider shows a security list's or route table's rules as a set. Rules whose `description` is unset show as removed and re-added in a plan whenever any rule in the resource changes, because `description` is optional and computed. The contents are unchanged, and the update replaces the whole list in one API call.
