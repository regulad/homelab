# syncthing-join runs its first full pass whatever the uptime (2026-11-20)

- **`time.monotonic()` counts from boot on Linux** (`CLOCK_MONOTONIC`), so `0.0` is no "never" for it. syncthing-join kept its last full pass's time as `0.0` at start and after Syncthing's API dropped out, and so skipped the pass due then for the first `FULL_PASS_INTERVAL` (600 s) of the host's uptime: at aboriginal's boot, a device waiting since before it joined only at its next connection's event, or ten minutes in. The time is now `None` until a pass runs.
- **The tests set serve()'s clock themselves.** `test_a_restart_cutting_off_a_long_poll_is_survived` read the real clock, and failed, blocking commits through pre-commit's `tests` hook, while the machine running it had been up less than ten minutes, as WSL often has. `ServeTest` now patches `time.monotonic` to a clock starting at 5 s, which the old code fails at.
