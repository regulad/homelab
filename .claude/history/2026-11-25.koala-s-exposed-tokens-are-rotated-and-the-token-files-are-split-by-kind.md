# Koala's exposed tokens are rotated, and the token files are split by kind

- Four credentials `tofu/github` passes to Koala were printed in an agent session: its Dependabot token, `terraform-koala--notifications`, regubot's `terraform-koala--winget` and its Sentry organization token. The three GitHub tokens were reissued under the same names; all five Sentry organization tokens were reissued under new names, `terraform-<repository>`, matching GitHub's, and the old ones revoked.
- `tofu/github-user`'s `personal.sops.yaml` and `bot.sops.yaml` keep classic tokens under `pat` and fine-grained ones under `fine_grained`. The kind shows in the value: a classic token starts `ghp_` and is 40 characters, a fine-grained one starts `github_pat_` and is 93. Every token's earlier `# Token:` comment matched its prefix.
- The Sentry organization tokens moved to `tofu/sentry/org-tokens.sops.yaml`, under `org_tokens`, which `tofu/github`'s `prepare.sh` reads as `sentry_auth_tokens`. Each is 191 characters and starts `sntrys_`.
- A SOPS file can be restructured without its plaintext touching disk or output, comments included: `sops decrypt <file> | yq '<transform>' | sops encrypt --filename-override <file> --input-type yaml --output-type yaml /dev/stdin`, writing to a temporary file that then replaces the original, and comparing digests of the decrypted JSON before and after. yq keeps each key's head comment through `with_entries`, and `(.map["key"] | key) head_comment = "…"` sets a new key's.
- `sops set --value-stdin` reads a JSON-encoded value, so a token is written as `printf %s "$t" | jq -Rs . | sops set --value-stdin <file> '<path>'`.
- After a key in a SOPS file a `prepare.sh` reads is renamed, that `prepare.sh` refuses the old `secrets.auto.tfvars.json` as having local edits; delete the file, which is only ever generated, and run it again.
- pre-commit's `tofu validate` hook for a root fails with "no package … cached in .terraform/providers" when the root was never initialized. A commit that touches that root needs `tofu init` first, which takes the root's state passphrase as well as the backend's credentials.
