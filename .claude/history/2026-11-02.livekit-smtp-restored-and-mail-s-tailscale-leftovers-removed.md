# livekit: SMTP on localhost restored; mail: Tailscale's leftovers removed (2026-11-02)

- livekit's hand-written `/etc/postfix/main.cf`, from before the `mail_relay` role, set no `compatibility_level`. Postfix ran at level 0, where `smtpd_relay_restrictions` is empty, and `smtpd` died on every start ("specify at least one working instance of: reject_unauth_destination, …"), with the master throttling it.
  - Mail submitted through `sendmail` or `mail` still went out, since it never touches `smtpd`. dnf-automatic's mail, sent over SMTP to localhost, failed with "Connection unexpectedly closed: timed out".
  - The visible sign was a non-zero Recv-Q on the port-25 listening socket: connections were accepted by the kernel but never by Postfix.
  - `mail_relay` now fails a host whose `main.cf` sets no `compatibility_level`.
  - Four more hosts set up by hand before the role had the same gap: tailscalerouter, whose `smtpd` had died 373 times in a week, and aboriginal, dodo and prodingus, where nothing had connected over SMTP yet. Each now sets its package's level. Packages write `2` on Ubuntu 24.04 and 26.04 and on Oracle Linux 9, and Debian 13's `/usr/share/postfix/main.cf.debian` writes `3.9`. On Ubuntu, level 2 logs a notice that Postfix is using backwards-compatible defaults; the hosts whose `main.cf` came from the package log it too.
- On Enterprise Linux, `/etc/postfix/main.cf.proto` is not the package's `main.cf`. It leaves the installation parameters empty, and copied over `main.cf` it stops Postfix ("bad string length 0 < 1: setgid_group ="). The package's own `main.cf` sets them:
  - `setgid_group = postdrop`, `html_directory = no`.
  - `sendmail_path = /usr/sbin/sendmail.postfix`, `newaliases_path = /usr/bin/newaliases.postfix`, `mailq_path = /usr/bin/mailq.postfix`.
  - `manpage_directory = /usr/share/man`, `sample_directory = /usr/share/doc/postfix/samples`, `readme_directory = /usr/share/doc/postfix/README_FILES`.
- livekit's `main.cf` is now the package's, plus those settings and the role's. With `inet_protocols = all` from the package, Postfix also listens on `[::1]:25`; the hand-written file had `ipv4`.
- tailscalerouter's hand-written file also set `inet_protocols = ipv4`. The role now sets `all`, the packages' value. On the hosts whose `main.cf` had no such line, that adds one and restarts Postfix once, with no change in behaviour.
- `smtp_address_preference` stays at its default, `any`, so Postfix picks IPv6 or IPv4 for the relay at random when both resolve. livekit and tailscalerouter reach `mail.regulad.xyz:465` over both. bailout reaches it only over IPv6: its IPv4 connections time out, so when Postfix picks IPv4 there, delivery waits for the timeout before the next address.
- mail had Tailscale installed by hand on 2026-02-06 and removed on 2026-08-16, leaving `tailscale.repo`, Tailscale's RPM key, dnf's cache of the repository and `/var/lib/tailscale`, including `tailscaled.state` with the node's keys. All of it was removed; mail does not set `tailscale_enabled`.
- A dnf query run without `become` uses a per-user cache with no repository keyring, so on a host with a `repo_gpgcheck` repository it stops at a prompt to import the key. Root's dnf, which dnf-automatic uses, has the key. Read-only dnf probes should run as root, with `-C` to stay on the cache.
