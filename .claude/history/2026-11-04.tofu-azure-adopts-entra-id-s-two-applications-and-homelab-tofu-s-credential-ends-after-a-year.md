# tofu/azure adopts Entra ID's two applications, and homelab-tofu's credential ends after a year (2026-11-04)

- `homelab-tofu` is an Entra ID application with a service principal, made in Cloud Shell, whose one credential is the certificate `tofu/azure/service-principal-tofu.crt`. Its key pair was generated locally and the private key went straight into SOPS, so Entra ID never had it. It holds Owner on the subscription and Graph's Directory.Read.All and Application.ReadWrite.All, but not AppRoleAssignment.ReadWrite.All, with which an application can consent itself to any permission; consent stays manual.
- `az ad app credential reset --cert` ends the credential one year after it is added, not when the certificate does: `--years` defaults to 1, whatever the certificate's own validity. `homelab-tofu`'s credential ends 2027-11-05, its certificate 2036-11-02. It is left to be extended when it is needed, by a new `credential reset` with `--end-date` or `--years`.
- In Cloud Shell, `az ad app permission admin-consent` fails: "Audience 74658136-14ec-4630-ad9b-26e160ff0fc6 is not a supported MSI token audience". Cloud Shell's managed-identity token cannot reach the API that command calls. Consent works in the portal, under the app's API permissions, with Grant admin consent.
- Signing in needs no `az`. A client assertion signed with `openssl dgst -sha256 -sign` (RS256), whose header's `x5t` is the base64url SHA-1 thumbprint of the certificate, with `aud` the tenant's v2.0 token endpoint and `iss` and `sub` the client ID, exchanges by `client_credentials` for a token to `https://management.azure.com/.default` or `https://graph.microsoft.com/.default`.
- The providers decode `ARM_CLIENT_CERTIFICATE` with `software.sslmate.com/src/go-pkcs12` v0.7.3, which reads OpenSSL 3's default PKCS#12 encryption and an empty password, so `openssl pkcs12 -export -passout pass:` needs no legacy options.
- Provider findings, azuread v3.10.0 and azurerm v5.12.0:
  - `azuread_service_principal` imports as `/servicePrincipals/<object ID>`; the bare object ID its docs show fails to parse. `azuread_application` imports as `/applications/<object ID>`, and `azurerm_role_assignment` by the assignment's full resource ID.
  - Parker's Owner assignment carries Microsoft's description from retiring Classic Administrators, which a config without it would plan to remove.
  - `azurerm` v5 registers no resource providers by default (`resource_provider_registrations = "none"`).
- `az ... -o table` drops any column named `id`, so an account list queried for name, ID and state shows only name and state.
- Cost Management's query API (`POST .../providers/Microsoft.CostManagement/query`, `ActualCost` grouped by resource) shows whether anything was ever billed, deleted resources included; a new service principal is throttled hard at first (HTTP 429, with `Retry-After` near 30 s). The Consumption API's billing periods list is empty for this subscription. A directory's own service principals besides its apps', its delegated consents and its deleted objects show what else it ever held: here, only Microsoft's first-party service principals.
- The `Pay-As-You-Go` subscription holds no resource groups or resources, and was never billed from 2020 on. Its three policy assignments are Microsoft's, `sys.mfa-write`, `sys.mfa-delete` and `sys.blockwesteurope`, assigned at the tenant root management group. The directory holds one user and no groups; of its app registrations, `regulad rclone` (rclone's OneDrive login) is kept, and `filefly.ai` and `filefly.ai dev`, whose secrets expired in February 2025, are deleted.
