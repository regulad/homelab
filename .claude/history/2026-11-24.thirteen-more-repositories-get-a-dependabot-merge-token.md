# Thirteen more repositories get a Dependabot merge token

- parkerwahle, ml4webedit, RosellaView, Koala, Warlock, SupIR, tinyxnb, lime, http-docker-cron, terraform-provider-onesignal, opentofu-registry, dotfiles and kodi-plugins each get a fine-grained token, `terraform-dependabot--<repo>` in `tofu/github-user`'s `personal.sops.yaml`, set by `tofu/github` as the Dependabot secret `DEPENDABOT_MERGE_TOKEN`, for their `dependabot-auto-merge` workflows. Those of the three repositories that update only GitHub Actions (dotfiles, opentofu-registry, kodi-plugins) also have Workflows read and write, which merging an Actions update needs.
- GitHub limits a token's name to 40 characters, so the longer names are cut there (`terraform-dependabot--terraform---provid`), and the SOPS key follows the token's name on GitHub.
- Each token was checked read-only: `/user` names regulad, its own repository's contents and pull requests answer 200, and the private `regulad/vs` answers 404. A fine-grained token's permissions can't be read through the API, so write access shows only at its first merge.
- dotfiles had pull requests turned off in GitHub's settings (`has_pull_requests: false`, not in its `settings.yml`), so the pulls API answered 404 to any credential, and Dependabot could open none. They are on again, through `gh api -X PATCH repos/regulad/dotfiles -F has_pull_requests=true`.
- The validate hooks of `tofu/github` and `tofu/github-user` run on the selected workspace, so a fresh clone selects `personal` or `bot` after `init` before it can commit to either root, or to `personal.sops.yaml`.
