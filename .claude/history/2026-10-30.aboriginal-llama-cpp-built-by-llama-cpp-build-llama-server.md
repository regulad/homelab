# aboriginal: llama.cpp built by `llama-cpp-build`; llama-server downloads its model where it is missing (2026-10-30)

- regulad/llama.cpp's `aboriginal` branch is upstream master at `792fcf4e` plus the RDNA2 clamp. The patch from the hand build at `458681e1d` no longer applied to that master as it stood; `git apply --3way` took it cleanly, still one changed line. Upstream's `.pre-commit-config.yaml` came with the fork, and its hook built hook environments on the first commit; the clone's hook is removed, so commits there run no hooks.
- CMake writes the build tree's absolute `bin` into the binaries' `RUNPATH`. The hand build, made in `/opt/llama.cpp/build` and moved aside by the play's first run to `build-458681e1d5d4`, still loads its libraries from `/opt/llama.cpp/build/bin`, so it runs correctly only while `build` links to it, as the play's rollback does. The play's own builds are made at their final paths, so each loads its own libraries.
- Ubuntu's ROCm builds HIP with its own LLVM; `hipconfig -l` names it (`/usr/lib/llvm-21/bin`), and CMake needs its `clang` as `CMAKE_HIP_COMPILER`.
- `hf` comes from huggingface_hub, whose base install carries the CLI (click); the extras are not needed. With `--local-dir`, it downloads each file under `.cache/huggingface/download` in that directory and moves it into place only when it is whole, so a file present at its path is complete. The unit tests for both files before calling it, so a start needs no network once they are there.
- community.general.pipx (13.5.0) looks an application up by its name exactly as declared, while pipx lists each under its normalized name, so `huggingface_hub==2.2.0` was never found installed: every run reported a change and ran `pipx install` again. Declared as `huggingface-hub==2.2.0`, it is found.
