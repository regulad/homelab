# Container images update without a cooldown (2026-11-01)

- `podman auto-update` has no minimum-age or cooldown option. With `AutoUpdate=registry` it pulls whenever the tag's remote digest differs from the local one, so the `podman-auto-update.timer` run at midnight picks up a push from a minute earlier.
- Upstream declined the feature: [podman#28425](https://github.com/podman-container-tools/podman/issues/28425) was closed as not planned on 2026-05-31 and then locked. The maintainer's reasons:
  - Registries expose no push time, and an image's creation date comes from its config, which whoever pushes the image controls.
  - Tracking when each digest was first seen would make the command stateful. It would also hold back every update, security fixes included.
  - `auto-update` is only a `podman pull` and a unit restart, so any other pull or restart brings in the newer image.
- Podman's repository moved from `containers/podman` to `podman-container-tools/podman`; `gh` reports the old name as not found.
- We don't wrap `podman auto-update` in a homegrown cooldown, such as a script that tracks digests and retags images; it would be fragile.
- If a cooldown becomes necessary for security, re-evaluate what upstream suggests: pin each image by digest in `services.yml` and let Renovate's `minimumReleaseAge` propose digest updates. That replaces the tag-tracking `AutoUpdate=registry` convention in `AGENTS.md`. First verify that Renovate gets a release timestamp from each registry in use, since `minimumReleaseAge` depends on one.
