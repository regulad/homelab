# Ansible connects without the operator's SSH configuration, and names hardware hosts by their full hostnames (2026-11-22)

- **What the SSH configuration had been supplying:** each OpenSSH host's user (`Host * User regulad`; root on prodingus, ubuntu on doppelgangerhq.com), the addresses behind the short names prodingus, turk, overture and JPE18280417, overture's `RemoteCommand`, and the key, through `Match User regulad` tagging `id_rsa3072` with `IdentitiesOnly`. Without that pinning, the agent offers all its keys in turn. Every host Ansible reaches accepts `id_rsa3072` alone, so the others are refused before anything signs.
- **`-F /dev/null` skips the system configuration too.** On the Fedora controller that is crypto-policies' include, whose order puts `rsa-sha2-256` first and so needed the dotfiles' `PubkeyAcceptedAlgorithms ^rsa-sha2-512` for Bitwarden's agent, which signs RSA with SHA-512 whatever it is asked for. OpenSSH's own default already puts `rsa-sha2-512` first. The system file there sends only `COLORTERM`, no locale.
- **Which plugins read what:** paramiko in `proxmox_pct_remote` never reads `~/.ssh/config`. libssh does, on its own, but values Ansible sets explicitly win, as the SG300s' `svc-ansible` does over the configuration's `User regulad`. Both still read only `~/.ssh/known_hosts`.
- **Checking a host's key, user and accepted keys without a signature:** `ssh -F /dev/null -v -o BatchMode=yes -o IdentityAgent=none -o IdentitiesOnly=yes -i <copy of a .pub with no private key beside it> -o HostKeyAlias=<inventory name> -o UserKnownHostsFile=<stage>/known_hosts -o StrictHostKeyChecking=yes <user>@<address> true` verifies the host key and logs `Server accepts key` for an authorized key, then fails, since it has nothing to sign with. It never logs in.
- **IPv6 from WSL:** the controller has no IPv6 route, so the resolver leaves out AAAA records and `ssh` goes straight to IPv4. doppelgangerhq.com needs no `AddressFamily`.
- **Identities that use the short name:** Orchard's service account and worker name must match the controller's `worker-overture`, so they use `inventory_hostname_short`. restic's keys are looked up by the short name already. AIDE's, ClamAV's and restic's timer minutes hash the inventory name, so the renamed hosts' timers move at their next `site.yml`.
