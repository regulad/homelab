# mail gets a data volume labelled for containers, and SELinux enforcing is declared (2026-11-04)

- mail's data volume, `tofu/oracle`'s `mail_data`, appeared at `/dev/oracleoci/oraclevdb` 25 s after its attachment, with no rescan. It is XFS, as mail's root filesystem is, labelled `mailserver`, and mounted at `/mnt/mailserver` by `mnt-mailserver.mount` with `_netdev,nofail`. Its directories `mail`, `state` and `log`, for `/var/mail`, `/var/mail-state` and `/var/log/mail`, keep the image's owners: 5000, root, and its syslog user 113.
- `host_files` creates directories before it starts units, so directories on a volume it also mounts must come in a later run; in the same run they land on the root filesystem under the mount point and are hidden.
- A freshly made XFS filesystem is `unlabeled_t` until relabelled. The rule `/mnt/mailserver(/.*)?` → `container_file_t`, at `s0` with no categories, lets any container's MCS categories read and write it, and a relabel keeps it. Podman's `:Z` instead gives files the container's own categories, which `restorecon` would strip.
- In permissive mode, mail logged 32,860 denials in a week, nearly all `container_t` writing to docker-mailserver's bind mounts under `/root` (`admin_home_t`). The others: docker-mailserver reading `/etc/letsencrypt` (`cert_t`), which the `container_read_certs` boolean allows; supervisord's `associate` on `proc_t`, once at each container start; and Oracle's dhclient hook's curl reading the CA bundle, a gap in `oci-linux-config`'s `oci-dhclient` module, which reaches the metadata service over plain HTTP. livekit, enforcing on the same package, logged no denials in the same week.
- `ausearch` reads stdin when it is not a terminal, so in `ssh host 'bash -s' < script` it consumes the rest of the script. Run the script from a file on the host with stdin from `/dev/null`, or give `ausearch` `--input-logs`.
- bailout, livekit and tailscalerouter run enforcing, as their images ship. mail ran permissive, and a local `fcontext` rule labelled the miner's `xmrig` `bin_t`; the rule is removed.
