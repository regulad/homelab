# aboriginal: podman-auto-update running again; llama.cpp's RDNA2 change kept (2026-10-30)

- A podman-compose stack without `x-podman: in_pod: false` runs in a pod with no infra container, and `podman auto-update` then stops at its container with "looking up pod's systemd unit: pod has no infra container", exiting 125, the whole run with it, as on the first night after jellyfin's stack started. With `in_pod: false` the container carries `PODMAN_SYSTEMD_UNIT` itself. `podman-compose down` leaves the old pod behind, empty; `podman pod rm` removes it.
- ggml-org/llama.cpp#23310 is a discussion, still open on 2026-10-30. Two pull requests clamping `max_blocks_per_sm` (#16633, #27787) were closed unmerged, a maintainer calling the clamp the wrong fix, and master still asserts `max_blocks_per_sm > 0`. In #27674, a user traced the zero to Fedora 44's distribution build of ROCm 7.1.1, whose `comgr` reports `TotalNumVGPRs=256` for gfx10 where AMD's reports 1024; with AMD's ROCm 7.2.1 the same query gives 2. aboriginal links against Ubuntu's ROCm (`libamd-comgr3 7.1.1+dfsg-0ubuntu1`, `libamdhip64 7.1.0`), not AMD's.
- llama.cpp's `ghcr.io/ggml-org/llama.cpp:server-rocm` is built daily on `rocm/dev-ubuntu-24.04:7.2.1-complete`, for targets including gfx1030, with HIP alone; it is tagged `server-rocm` and `server-rocm-bNNNNN`, and its documentation says the GPU images are only built, not tested.
