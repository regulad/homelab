# The pipeline becomes a Taskfile run with `go tool task`, and dependents re-plan from digests of what they read

- go-task runs a task's `deps` concurrently and its `task:` calls in `cmds` in order, so `plan` walks `STEPS` through `cmds`. A task its up-to-date check skips still runs its `deps` first, which is what lets a step refresh its upstream signal before go-task compares checksums. Checksums live in `.task/` of each checkout, so a new worktree plans every step once.
- go-task v3.54.0 declares Go 1.26.4, which `go.mod`'s `go` directive matches, rather than the 1.27.4 that `go mod init` wrote from the local toolchain. The first `go tool task` built it in about 75 s; later runs come from Go's build cache.
- `cloud.terraform.terraform_state` (regulad's fork at `4d748cb`, `plugins/inventory/terraform_state.py` lines 750–754) sets every attribute of each resource its `provider_mapping` selects as a host variable, so `compose` does not bound what a stage reads. Its cache entry is exactly that selection (`resources_to_cache`), which is why an inventory source's signal is a digest of a cache the plugin builds into a private directory (`ANSIBLE_INVENTORY_CACHE_CONNECTION`), not a filter of ours.
- `ansible-generated--memory` exists because memory's host_vars read `tofu/authentik`'s outputs while `tofu/authentik` signs in to the authentik `ansible-generated` brings up; with memory as its own step after `authentik`, no step reads one that reads it.
- A task sourcing a root's `prepare.sh` inside its own process ran in a worktree session without the guard's refusal that sourcing it directly meets. Claude Code's auto-mode check refused one command running five roots' `init` together, and `gcp:init` alone until Parker named gcp in his approval; each then ran as its own command.
- `uv run --python 3.9` downloads a missing Python when `python-downloads` is left at its default, `automatic`, which the `tests` hook now relies on in place of `--no-python-downloads`.
