# AIDE leaves certbot's renewal configuration on doppelgangerhq.com alone (2026-11-03)

- **certbot's snap writes renewal-information state into the renewal configuration.** On doppelgangerhq.com (the certbot 5.x snap), `/etc/letsencrypt/renewal/doppelgangerhq.com.conf` has an `[acme_renewal_info]` section with `ari_retry_after`, the next time the ACME server's renewal information is to be fetched, and each run of `snap.certbot.renew.service`, twice a day, rewrites the file with a new value. AIDE watches whole files, so it reported the file changed at every check. livekit's certbot 4.2.0, from EPEL, writes no such section: its renewal configuration was last written at its renewal.
- **The tradeoff taken: the whole file is excluded, on doppelgangerhq.com only.**
  - Lost: the renewal settings in the file (`account`, `authenticator`, `installer`, `server`, `key_type`, and the certificate paths) go unwatched, and so would a `pre_hook`, `post_hook` or `renew_hook` added to `[renewalparams]`, which certbot runs as root at the next renewal. None was set when it was excluded.
  - Kept: the hook directories under `/etc/letsencrypt/renewal-hooks/` (empty), the certificates in `archive/` and `live/`, and certbot's snap stay watched.
  - Rejected: accepting it, which puts the file in every daily report; excluding `/etc/letsencrypt/renewal` whole, which is wider for no gain; and aide-report keeping its own copy of the file to compare it without `[acme_renewal_info]`, a bespoke layer for one key on a host to be retired at Ubuntu 24.04's end of life. Revisit the exclusion if certbot on another host starts writing the section, or if a hook is ever wanted in the file.
- **The Unified Monitoring Agent's status file is excluded on every OCI instance.** On mail, livekit and doppelgangerhq.com, `unified-monitoring-agent_config_downloader.timer` (every 15 minutes, up to 10 more at random) rewrites `/etc/unified-monitoring-agent/unified_monitoring.json`, which holds only the time and result of the last download from OCI's control plane. Its configuration, in `conf.d/`, stays watched. bailout and tailscalerouter do not run the agent. On doppelgangerhq.com the status was `FAIL` with 0 bytes downloaded; on mail and livekit, `SUCCESS` with 0 bytes.
- **Enterprise Linux's AIDE rule for `/etc` records no contents.** Oracle Linux's `/etc/aide.conf` selects `/etc PERMS` (permissions, owner, group, ACL, SELinux label, xattrs and type), with content rules only for the files it lists itself, so a rewrite of any other file in `/etc` never appears in a report on the rhel hosts. `aide -p f:<path>` shows the rule a path gets.
