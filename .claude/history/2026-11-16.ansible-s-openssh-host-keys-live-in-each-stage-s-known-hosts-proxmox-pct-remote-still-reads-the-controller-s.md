# Ansible's OpenSSH host keys live in each stage's known_hosts; proxmox_pct_remote still reads the controller's (2026-11-16)

- **Where the keys are.** Each stage's `known_hosts` holds the keys of the hosts it reaches over OpenSSH, under their inventory names. `group_vars/all.yml` sets `ansible_ssh_extra_args` to `-o HostKeyAlias={{ inventory_hostname }} -o UserKnownHostsFile={{ inventory_dir }}/../known_hosts -o GlobalKnownHostsFile=/dev/null -o StrictHostKeyChecking=yes`.
  - The extra arguments are a separate variable from `ansible_ssh_common_args`, so overture's `RemoteCommand=none` stays.
  - The file sits beside `inventory/`, not in it: the stage's inventory is that directory, and Ansible parses every file in it.
  - With `UserKnownHostsFile` overridden, OpenSSH turns `UpdateHostKeys` off, so nothing writes to the file.
- **Where they came from.**
  - The keys of hosts Ansible already reached are the controller's: `ssh -G <address>` gives each address's `hostname`, `hostkeyalias`, `port` and `userknownhostsfile`, and `ssh-keygen -F` finds hashed entries in those files.
  - riko's key matches FreeIPA's record of it, from `sss_ssh_knownhosts riko.regulad.internal` on wako (container 203).
  - pihole2 is neither enrolled in FreeIPA nor on the tailnet itself (it does not set `tailscale_enabled`). Its key came from `ssh-keyscan` from the controller, whose route to it stays inside the tailnet.
- **Listing what Ansible connects to.** `ansible all -m ansible.builtin.debug -a 'msg=...'` prints each host's `ansible_connection`, `ansible_host` and `ansible_user` without connecting.
- **Still undone: containers.** `proxmox_pct_remote` connects with paramiko, which loads only `/etc/ssh/ssh_known_hosts` and `~/.ssh/known_hosts` and has no option for another file. Every container's connection through `prodingus.tail11540.ts.net` is still checked against the controller's `~/.ssh/known_hosts`. The fork of community.proxmox that `requirements.yml` pins could take such an option.
- **Still undone: switches.** The three switches connect through `network_cli` with libssh: pylibssh 1.4.0 with libssh 0.12.2.
  - pylibssh applies only the keywords in its option map, so the `config_file` that netcommon's libssh plugin passes is silently dropped. A config whose `UserKnownHostsFile` was empty still connected, from `~/.ssh/known_hosts`.
  - pylibssh's `knownhosts` or `ssh_dir` keyword would work, but the plugin passes neither.
  - No upstream request for either plugin turned up.
- **The tailnet from WSL.** WSL's own `tailscaled` is logged out; the controller reaches the tailnet through Windows' Tailscale, so `tailscale` in WSL cannot look up peers.
