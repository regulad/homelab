# The nextcloud role declares Nextcloud's config.php, apps, settings and Mail provisioning (2026-11-12)

- Nextcloud writes `config.php` with PHP's `var_export` under a fixed header comment, leaving a space at the end of each `'key' => ` line that opens an array. A template kept in that form renders byte for byte what Nextcloud itself writes for the same values: the role's first check run reported `config.php` unchanged right after `occ config:import` had rewritten it. Templates under `ansible-generated/files/` keep those spaces, as the whitespace hooks skip that tree.
- The image's entrypoint copies its own `*.config.php` (apcu, apps, apache-pretty-urls, redis, reverse-proxy, s3, smtp, swift) only into an empty config directory, and afterwards just warns at each start where one differs from the image's. aboriginal's were the copies of its June 2023 install. Nextcloud merges every `*.config.php` over `config.php`, so the three that set keys unconditionally overrode `config.php`'s own; the rest read environment variables the compose file does not set.
- `config.php` also held `app.mail.accounts.default`, an old Mail release's default account, which Mail 5.12.6's code no longer reads, and `user_backend_sql_raw`, the hook of an app that is not installed, naming `/var/www/nextcloud/user_provisioning.sh`, a path the container does not have.
- Nextcloud enables a shipped app by itself, at install and at each upgrade (`Installer::installShippedApps`), when its code's `core/shipped.json` lists it as `defaultEnabled` or `alwaysEnabled` and its `enabled` is not `no`. In 35.0.2 that is 46 and 15 of 57 shipped apps. aboriginal had 13 of the defaults disabled, and 5 shipped apps outside them enabled: admin_audit, encryption, files_external, suspicious_login and user_ldap.
- `occ config:import` stores app values through the legacy `setAppValue`, as strings, and refuses booleans and arrays for apps. `occ config:app:set` without `--type` keeps a stored key's type, laziness and sensitivity, and under `--no-interaction` never changes them. `config:import` reads stdin non-blocking (`stream_set_blocking(STDIN, 0)`), so input piped through `podman exec -i` can arrive too late; a file in the container's tmpfs `/tmp` is read reliably.
- user_ldap stores its bind password base64-encoded (`s01ldap_agent_password`). svc-nextcloud's password there is also Nextcloud's SMTP password.
- Mail 5.13.0 (2026-11-02) added `occ mail:provisioning:create|update|list|delete|apply` (nextcloud/mail#13670, backported as #13817); `list --json` never prints a master password. Mail provisions a user's account, brings it in line with its configuration and stores the user's login password for it on every request to Mail (`ProvisioningMiddleware`), so `apply` is needed only to give accounts to users who have not opened Mail.
- A provisioning configuration whose templates use `%LDAP:<attribute>%` gives no account to a user of another backend (`resolveLdapPlaceholders` returns null), so one configuration covers LDAP users alone. Nextcloud's LDAP users here are named by `ipaUniqueID`, so `%USERID%` is not their uid; Dovecot looks users up by the login's local part (`uid=%{user | username}`), and each user's address is `<uid>@regulad.xyz`. regulad is a local user, which the LDAP filters exclude by `(!(uid=regulad))`.
- The `nextcloud.admin` collection (2.4.0) runs `php <nextcloud_path>/occ` on the managed host itself, after switching to the owner of `occ`, and has no container option; `containers.podman`'s connection plugin runs `podman` on the control node. The image has `python3` only as rsync's dependency.
- The MariaDB password of Nextcloud's `nextcloud` user had been its own name. It is now generated: `config.php` took it first, through `occ config:import`, whose own database connection was already open, and `ALTER USER` followed, so only connections opened in between could fail.
