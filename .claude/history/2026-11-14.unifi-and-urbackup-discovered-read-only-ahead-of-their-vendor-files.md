# unifi and urbackup discovered read-only, ahead of their vendor files (2026-11-14)

- The probes are one script, in the operator's local `docs/snapshot/cloud-init-vm-probes.sh`, run per section as `ssh <host> 'sudo -n bash -s -- <section>' < cloud-init-vm-probes.sh`, with each section's output passed through an on-host Perl filter. The filter replaces every run of 40 or more `[A-Za-z0-9+/_-]` characters, so long paths, such as Podman's volume mountpoints and `uosserver.service`'s `ExecStart`, come out as `<blob>` too; harmless values are fetched separately with their `/` spaced out. `/etc/urbackup` holds `luks.key`, so the script lists that directory and prints only `backupfolder`.
- A Proxmox VM with `cicustom` but no cloud-init drive, as `initialization.datastore_id = ""` leaves urbackup, gets cloud-init `disabled-by-generator`: ds-identify finds no datasource.
- On Ubuntu 26.04 the cloud image names the NIC `ens18`, and dracut's initramfs writes `/run/systemd/network/zzzz-dracut-default.network` (`DHCP=yes`, DHCPv4 client ID by MAC), which configures any link that no netplan file matches. `networkctl status <link>` names the file in use, and `resolvectl mdns <link>` shows mDNS per link where `resolvectl status` shows it globally.
- On unifi, the service restarts after unattended-upgrades' libc6 upgrade of 2026-11-13 stopped `watchdog.service` and started `wd_keepalive`, which kept the `i6300esb` fed; nothing started the daemon again. urbackup took the same upgrade the next morning and rebooted (`Automatic-Reboot "true"`), so its daemon came back.
- `sha256sum -c` against the repo's snippet, run on the host with the hash piped in, compares a VM's `/var/lib/cloud/instance/vendor-data.txt` without printing it: unifi's matches `ubuntu-vendor.yaml`.
- UniFi OS Server's installer creates the `uosserver` user (lingering, rootless Podman), `/var/lib/uosserver` with its own `pasta`, `discovery` and the two services' binaries, `/usr/bin` and `/usr/local/bin` `uosserver{,-purge}`, `uosserver.service` and `uosserver-updater.service`, and `/etc/sysctl.d/99-uosserver.conf`. Its `containers.conf` puts `/var/lib/uosserver/bin` first among Podman's helper binaries. The container's version is its `APP_VERSION` environment variable, which its updater moves forward (5.1.21 installed, 5.1.42 now).
