# tofu/github sets the repositories' secrets, and tofu/vercel adopts the Vercel projects (2026-11-18)

## tofu/github

- **Adopting secrets:** GitHub never returns a secret's value, so an imported secret has none in state. The adoption plan showed `+ value` and nothing else on each of the 29, and the apply wrote every one again from SOPS.
  - Import IDs are `<repository>:<NAME>` for Actions and Dependabot secrets and `<repository>:<environment>:<NAME>` for an environment's.
  - The `github_rest_api` data source with `repositories/<id>` gives a repository's current name, so files can be keyed by ID.
- **The App's permissions:** GitHub's "permissions required for GitHub Apps" page lists environment secrets under Environments, not Secrets, and Dependabot's under Dependabot secrets; Actions secrets are under Secrets. `regulad-homelab` has those three at read and write, and Metadata.
- **The App's key:**
  - integrations/github requires `app_auth`'s `pem_file` to be set even for `tofu validate`, which never reads it. The pre-commit hook passes a placeholder through `env`.
  - In the dotenv file the PEM is one line, each newline written as `\n`.
  - A JWT signed with `openssl dgst -sha256 -sign` and sent to `GET /app` and `GET /app/installations` confirms that a key, the App ID and the installation belong together.
- **PATs:** each is stored under its token's name on GitHub, `terraform-<word>--<word>`. A three-line comment gives its type, its repository access (`*` for classic) and its permissions.
  - Checked read-only: a fine-grained token starts `github_pat_`, a classic one `ghp_`. A fine-grained token answers 404 for repositories outside its list. `x-oauth-scopes` on `GET /user` lists a classic token's scopes.
  - The Dependabot merge tokens are PATs because a merge made with `GITHUB_TOKEN` starts no workflows on the default branch.
- **Nexus CI users:** `nexus_security` adopted `svc-redroid` and `nx-aaoracled` with new generated passwords and added `svc-doppelganger-ci`, which may only browse and read the `maven-central` proxy.
  - Privileges are named `nx-repository-view-<format>-<repository>-<action>`; `GET /service/rest/v1/security/privileges` lists them.
  - `/service/rest/v1/status/check` answers 403 for a login that works without its privilege, and 401 for a wrong password.
  - Each repository's secrets were set by hand right after the Nexus apply, so CI never ran with a rotated-away password.
- **Committing one root beside another:**
  - tflint runs over every directory under `tofu/`, untracked ones too, so an unfinished root fails another root's commit; stash it first.
  - A stash taken with a pathspec while other files are staged records them too. Applying it after those files were committed and one was deleted brought the deleted `imports.tf` back.

## tofu/vercel

- **Discovery:**
  - The Vercel MCP server's `filter_project_envs` returns the values of `plain` variables. `vercel api <path> --raw | jq` keeps them out of the output.
  - The team has no shared variables, Edge Configs, stores or integrations. Each project's `*.vercel.app` domain, which Vercel assigns itself, is not declared.
- **Tokens** are Full Account, Team or Project scoped, with no finer permissions. The one in `provider.sops.env` is Full Account and expires 2027-11-18.
- **Secret variables** (type `sensitive`) are write-only, so import leaves `value` null and the first apply writes it from SOPS.
  - A variable's change reaches only deployments built after it. `POST /v13/deployments` with the latest production `deploymentId` and `"target": "production"` rebuilds one with the same commit; github-readme-stats was redeployed so that `PAT_1` took effect.
- **Generated configuration:** `tofu plan -generate-config-out=generated.tf`, gitignored by `generated*.tf`, wrote all 11 resources. It is not valid as written: `build_machine_type = ""`, an empty `custom_environment_ids` and a null sensitive `value` are refused. Dropping the unset attributes, and `team_id`, which the provider's `team` supplies, left a plan of the imports and `PAT_1`'s value alone.
- **Signatures:** OpenTofu's registry holds no GPG key for `vercel/vercel`, so `tofu init` skips the signature check; the locked checksums pin it.
