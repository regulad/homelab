# aboriginal's resolved caches no unicast DNS, so Nextcloud gets rsshub.regulad.xyz's public records (2026-11-11)

- Correcting 2026-11-06: the passthru holds only for a resolver that sends the whole query to arawi. systemd-resolved caches each record of a CNAME chain on its own, and given a cached CNAME without its target's records, asks for the target by name. Nextcloud's `DnsPinMiddleware` calls `dns_get_record` for A, then AAAA, one after the other: the A lookup left `rsshub.regulad.xyz CNAME ingress.regulad.xyz` cached with only the A, and the AAAA lookup then asked arawi for `ingress.regulad.xyz` itself, which the split horizon rewrites to `ingress.regulad.internal`'s ULA. Every update of News's RSSHub feeds failed this way, 111 in a row. `resolvectl query` and `getaddrinfo` ask A and AAAA at once, each sent whole, so they showed the public records throughout.
- Nextcloud's container resolves through aardvark-dns (`10.89.0.1`), and it through aboriginal's resolved stub. With resolved's cache off, the same A-then-AAAA lookups from the container get only the public records, on every pass.
- On systemd 259, `Cache=no` stops resolved caching unicast DNS and LLMNR answers (`dns_transaction_cache_answer`), while mDNS, which calls `dns_cache_put` itself, keeps its cache. From 261, `dns_cache_put` refuses everything under `Cache=no`, mDNS included; `DNSCacheSize=0`, new in 261, is the setting that leaves mDNS its cache.
- aboriginal's systemd-resolved package (259.9-0ubuntu0.1) ships `/usr/lib/systemd/resolved.conf.d/cache-no-negative.conf`, `Cache=no-negative`. Drop-ins apply in file-name order across directories, so the role's `host.conf` comes after it and wins; a drop-in whose name sorts before `cache-` would lose to it.
- Only aboriginal's cache is off. The other LAN hosts that resolve through resolved still cache, so one that has just resolved `rsshub.regulad.xyz` can answer for `ingress.regulad.xyz` with its public records, and one that has just resolved a rewritten name can answer for rsshub with the ULA.
- News keeps a feed's failures in `oc_news_feeds.update_error_count` and `last_update_error`, not in `nextcloud.log`. `resolvectl show-cache` lists resolved's cache by scope.
