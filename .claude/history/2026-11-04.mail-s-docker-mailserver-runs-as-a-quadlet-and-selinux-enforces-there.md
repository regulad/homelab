# mail's docker-mailserver runs as a Quadlet, and SELinux enforces there (2026-11-04)

- docker-mailserver is one container, with Postfix, Dovecot, Rspamd and the rest under supervisord. Its Quadlet, `mailserver.container`, carries over the compose project's settings. Its network, `mailserver.network`, which Podman names `systemd-mailserver`, keeps the compose network's subnets, `10.89.0.0/24` and `fd8a:ced2:727b:8489::/64`. `docker compose down` removes `mailserver_default`, and must run first, before the Quadlet's network claims the same subnets. The image follows `:15` with `AutoUpdate=registry`, so `podman-auto-update` now updates and restarts mail within 15.x.
- The `quadlet` role gained `quadlet_networks` and per-service `hostname`, `add_capabilities`, `stop_timeout`, `health_*` and `environment_files`. `environment_files` names a file another role writes, here `host_files`' template of `mailserver.env`, where `env_file` takes SOPS content.
- Podman's `--env-file` keeps quotes as part of a value. `mailserver.env`'s only quoted value is `POSTGREY_TEXT="Delayed by Postgrey"`, inert while Postgrey is off.
- The configuration moved from `/root/mailserver` to `/etc/mailserver`, mode 0700, with a file-context rule labelling it `container_file_t`. Everything under `/root` is `admin_home_t`, which `container_t` may not touch; under permissive those denials were nearly all mail logged. `container_read_certs` lets the container read `/etc/letsencrypt` and the CA anchor, both `cert_t`.
- The FreeIPA CA is bound from `ca_trust`'s anchor, `freeipa-home.arpa.crt`, in place of `/root/ipa-ca.crt`: the same certificate by its SHA-256 fingerprint, in a different PEM encoding. The runtime creates an empty `ipa-ca.crt` in `/etc/mailserver/config` as the bind's mountpoint.
- Quadlet adds `RequiresMountsFor=` for every bind source, so the drop-in that ordered `podman-restart.service` after `/mnt/mailserver` is gone. `podman-restart.service` is disabled, without `--now`: its `ExecStop` is `podman stop --service --all`. `podman.socket`, which served compose its Docker API, is disabled. `podman-docker`, Docker's `docker-compose-plugin` and `docker-buildx-plugin`, the `docker-ce-stable` repository and Docker's RPM key are removed, as is `/root/mailserver`, with a backup of `mailserver.env` holding an old LDAP bind password. `aide-report` checks Docker only where `dockerd` runs, so it does not need `podman-docker`. Removing the plugins left `/usr/libexec/docker/cli-plugins` behind, empty and unowned; it is removed too.
- webhookd's hook, `/usr/local/sbin/restart-mailserver.sh`, runs `systemctl restart mailserver.service`, under the same sudo rule.
- The `quadlet` role started a new service and then its restart handler restarted it mid-startup, because the unit was new. The handler now skips the services the start task just started. From `docker compose down` to the Quadlet's start took 4½ minutes, most of it the `host_files` and `podman` plays before `quadlet`.
- Under permissive, supervisord's open of `/dev/stdout`, the FIFO conmon hands it (`container_runtime_t`), and `start-mailserver.sh`'s open of `/dev/fd/63`, from bash's process substitution, logged `associate` on `proc_t` (class `filesystem`). Under enforcing, no denial is logged and every daemon starts. Under permissive, Oracle's dhclient dispatcher (`NetworkManager_dispatcher_oci_dhclient_t`) was also denied reading `/etc/pki/tls/openssl.cnf` (`cert_t`) as Podman created the network's interfaces; nothing like it has been logged under enforcing, nor on bailout.
- On the tailnet and in the VCN, `mail.regulad.xyz` resolves to mail's private IPv4 address alone. Tests of the public path connect to the addresses public DNS gives (`dig @1.1.1.1`): IPv4 from outside OCI, IPv6 from doppelgangerhq.com in the legacy VCN.
- `host_files`' `restorecon` passes over, in a check run, a directory the role would create.
- mail's `/etc/hosts` was rewritten with the same contents and a new inode 16 seconds after a restart of the container; what rewrote it is not known. AIDE reports the new inode.
- `rpm -qf` given many paths prints a line for each package that owns a path, so pairing its output with the paths, line by line, shifts after the first path with two owners. rpm's Python bindings, `rpm.TransactionSet().dbMatch("basenames", path)`, answer one path at a time.
