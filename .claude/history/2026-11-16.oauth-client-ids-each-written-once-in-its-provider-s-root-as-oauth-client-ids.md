# OAuth client IDs, each written once in its provider's root, as oauth_client_ids (2026-11-16)

- `tofu/gcp` and `tofu/azure` each export `oauth_client_ids`. Google's IDs are literals in each project's file, as no API lists clients; the output checks that each begins with its project's number, which a Google client ID always does. Entra's come from the `azuread_application` resources in state. `tofu/azure/locals.tf` keeps `homelab-tofu`'s client ID as a literal, as the providers sign in with it before any state is read, and the output checks it against the application.
- `tofu/supabase` reads `tofu/gcp`'s output through `terraform_remote_state`, as `tofu/cloudflare` reads `tofu/oracle`'s: the remote state's key provider keeps the source root's name (`pbkdf2` `gcp`), which its state's encryption metadata records, and `prepare.sh` merges the source root's passphrase into the inputs from its own SOPS file. An output the reader names must be applied to the source's state before the reader can plan.
- `clientauthconfig.googleapis.com`, the console's back end, now answers `400 INVALID_ARGUMENT` to `homelab-tofu` for every project, by number or by ID, so a project's clients are read from its Google Auth Platform → Clients page.
- pre-commit sets aside unstaged edits while its hooks run, but not untracked files: `tflint`, which lints all of `tofu/`, then saw a new file whose use was in a set-aside edit, and failed on an unused declaration. A commit a hook fails leaves its files staged, so the next commit takes them too. Committing one root while another has uncommitted edits needs those edits stashed first.
