# prodingus: webhookd declared, after an upgrade left it stopped and unconfigured (2026-10-29)

- azlux's webhookd package lists `/etc/default/webhookd.env` in `DEBIAN/conffile`, a name dpkg ignores (it reads `conffiles`), so dpkg does not know it as a conffile and every upgrade replaces it with the commented sample. The 1.22.0 to 1.22.1 upgrade by unattended-upgrades on 2026-10-23 06:30 EDT replaced the hand-set settings that way. The settings now live in `/etc/webhookd.env`, which the unit reads after it, and which the package creates (with `WHD_SCRIPTS="/opt/scripts"`) only when missing and removes only on purge.
- Its `prerm upgrade` stops webhookd, and its `postinst` restarts it only when `$1` is `upgrade`, which dpkg never passes (`postinst configure <old-version>`), so every upgrade leaves it stopped. An APT `DPkg::Post-Invoke` hook, `/etc/apt/apt.conf.d/80webhookd-start`, starts it after each dpkg run while it is enabled.
- It stayed stopped until prodingus's reboot on 2026-10-29, then listened on the default `:8080` without TLS, auth or hooks, so Uptime Kuma's notifications to `:8108` timed out.
- The old settings were rebuilt from evidence, as restic's `weekly 2` retention had pruned prodingus's root snapshots from before the upgrade: `addr=:8108` in every startup line, `timeout=120` on a killed hook (the default is 10, and a container reboot through the hook took 12 s), no `WHD_SCRIPTS` deprecation warning before the upgrade (1.22.0 already warns), and Kuma's `https://` URLs. webhookd's defaults for `WHD_HOOK_SCRIPTS` and `WHD_PASSWD_FILE` are `scripts` and `.htpasswd`, relative to the unit's `WorkingDirectory=/etc/webhookd`.
- PepperCord's start fails very intermittently, which is why the cordpepperer and peppercord hooks reboot their containers: a reboot through the hook at 02:25 EDT on 2026-10-23, after the move to podman-compose, left cordpepperer's health at `starting`, while one at 19:43 on 2026-10-29 had it connected within a minute. `main.py` runs `bot.start()` as a task it awaits only at shutdown, so a failed start never surfaces: the process stays up, idle, logging nothing.
