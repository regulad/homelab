# ingress's mTLS trusts only arawi's regulad.internal CA (2026-11-05)

- The `mtls` snippet that gates gonkputer, immich and openclaw.regulad.xyz trusted `/etc/ssl/certs/ca-certificates.crt`, so the handshake listed 125 acceptable issuers and a client certificate from any public CA passed. It now uses `trust_pool file` with regulad.internal's anchor, `/usr/local/share/ca-certificates/regulad.internal.crt`, which `ca_trust` installs; the handshake lists that CA alone.
- regulad.internal issues the client certificates, `dotfiles` and `uptime`. arawi's server certificates (pihole, unifi, prodingus, mail) carry clientAuth too, so the homelab's other roots, which sign server certificates, are left out.
- Caddy 2.11.9's `file` pool reads each `pem_file` with `os.ReadFile`, with no globs, and a missing file fails `caddy validate`. `trusted_ca_cert_file` is deprecated in its favour. With a trust pool, `mode` defaults to `require_and_verify`.
- `ca_trust_trusted` is a role default in another play, which `host_files` templates cannot read, so the Caddyfile names the anchor itself.
- `caddy validate` needs the Cloudflare token from `/etc/caddy/cloudflare.env` in its environment, as the host_files entry's `validate` sets; a candidate file validates on ingress through `pct exec 121 -- sh -c 'set -a; . /etc/caddy/cloudflare.env; set +a; /usr/local/bin/caddy validate --adapter caddyfile --config -'` with the file on stdin.
