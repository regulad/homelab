# Jenkins is configured as code, signs in to GitHub as the regulad-jenkins App, and pins its plugins (2026-11-18)

- **Configuration as Code reads the secrets it names from files.** `${name}` in a file under `CASC_JENKINS_CONFIG` resolves to the content of `/run/secrets/<name>`, its default `SECRETS` directory, read as it is, so a secret file carries no final newline. `GET /configuration-as-code/export` prints the live configuration as YAML, with secrets in Jenkins's own encryption, so keep exports out of the repository and delete them after use. `POST /configuration-as-code/check` with a YAML body validates it without applying; `[]` means no errors.
- **`remotingSecurity` no longer does anything:** Jenkins 2.580.2 logs a stack trace from `AdminWhitelistRule`, which "no longer has any effect", at each start while the configuration sets it, so it was removed.
- **Job DSL run by Configuration as Code needs no script approval:** its `jobs:` scripts go through `JenkinsDslScriptLoader`. A script can be tried first in the script console with a `JenkinsJobManagement` subclass that records the XML it would write without writing it. Job DSL cannot describe `jenkins.branch.OrganizationChildTriggersProperty`, an organization folder's trigger for the projects it finds, so the folder writes it in a `configure {}` XML block, and clears `healthMetrics` there to match the live folder.
- **The GitHub App credential takes only a PKCS#8 key.** GitHub hands out an App's key as PKCS#1, whose PEM header names an RSA key. It was converted with `openssl pkcs8 -topk8 -nocrypt` straight from the download into the SOPS dotenv, on one line with each newline written as `\n`, which the `host_files` entry turns back into newlines. The download was then shredded on Windows, unread. The script console can confirm the credential: `GitHubAppCredentials.password` mints an installation token, `ghs_…`.
- **The regulad folder scans through the App,** credential `regulad-jenkins`. Its first full organization scan through the App took 12 minutes.
- **community.general 13.5.0's IPA client fails a group-member change that succeeded:** FreeIPA's `result.failed` lists no failures as a dict of empty lists, which `_post_json` treats as an error. Fixed in community.general PR 13188 and backported to stable-13 in PR 13206, neither in a 13.x release yet. The `jenkins` role's `ipa_group` task carries a FIXME for it.
- **`community.general.jenkins_plugin` checks a pinned plugin by downloading it** on every run, and in check mode reports every installed plugin as changed. The role reads `/pluginManager/api/json?depth=1&tree=plugins[shortName,version]` first and passes only plugins whose version differs from the pin, or which are missing. `curl` needs `--globoff` for that URL's brackets.
- **`github-organization-folder` is not a loaded plugin:** `jenkins_home/plugins` holds version 1.6 unpacked without its `.jpi`, so Jenkins does not load it and it is not pinned.
