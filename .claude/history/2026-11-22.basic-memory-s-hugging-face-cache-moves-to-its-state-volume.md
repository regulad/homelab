# basic-memory's Hugging Face cache moves to its state volume (2026-11-22)

- **basic-memory embeds each note as it writes it,** and on first use downloads its embedding model, `bge-small-en-v1.5`, through huggingface_hub's Xet transfer. Xet caches under `HF_HOME`, by default `~/.cache/huggingface`, which is on the container's read-only root, so every `bm_write` saved its note to the data volume and then failed with "Previous task error: I/O error: Read-only file system (os error 30)". The notes were never at risk.
- **With `HF_HOME` on the state volume,** the model downloaded at the first write after the restart: about 65 MB in `fastembed_cache`, and 68 KB of Xet's own cache. basic-memory then embedded the notes written before the fix by itself, with no reindex: every chunk in `search_vector_chunks` reads `embedding_status` `ready`, and no note lacks chunks.
- **basic-memory's index can be read without changing it:** Python's `sqlite3` on `file:/app/.basic-memory/memory.db?mode=ro` inside the container. `search_vector_embeddings` is a sqlite-vec virtual table that plain SQLite cannot open, so `search_vector_chunks` is the place to count embeddings.
