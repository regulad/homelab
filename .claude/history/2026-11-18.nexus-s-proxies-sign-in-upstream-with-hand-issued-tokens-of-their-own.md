# Nexus's proxies sign in upstream with hand-issued tokens of their own (2026-11-18)

- **Docker Hub tokens can't be minted by OpenTofu here:** a Docker Hub personal access token cannot manage other tokens; the API answers `token issued from personal access token is not allowed`, as a Docker maintainer put it on `docker/terraform-provider-docker`#84: "You can't manage PATs with PATs." The `docker/docker` provider's password sign-in, `POST /v2/auth/token`, cannot answer a second factor. So with two-factor authentication on, only a short-lived token from the Docker CLI's browser sign-in, read from Docker's credential store, could run a `docker_access_token` resource. `tofu/dockerhub` therefore holds only `dockerhub_pats`, issued by hand, as `tofu/github` holds `github_pats`.
- **ghcr.io takes classic tokens alone,** and a classic `read:packages` token reads every package its owner can, organizations' included. Through Nexus's `ghcr-io` proxy, whoever reads that repository can do the same, anonymous users and the `knownguest` login shared in dotfiles among them. Parker chose a token of the regulad account for it. The four regulad packages the homelab pulls are public. `gh`'s token lacks `read:packages`, so which packages are private is not known here.
- **Checking a token without exposing it:** `https://auth.docker.io/token?service=registry.docker.io&scope=repository:library/alpine:pull` and `https://ghcr.io/token?service=ghcr.io&scope=repository:<owner>/<name>:pull` answer 200 to a valid login. ghcr.io answers 403 to a wrong password. Feed the login to `curl --config -` on stdin.
- **Nexus never returns a proxy's password:** `httpClient.authentication.password` (and `bearerToken`) are `writeOnly` in Nexus's OpenAPI document. A read gives the type and username only, and a `PUT /v1/repositories/docker/proxy/<name>` takes the whole repository, which `GET` returns with `format`, `type` and `url` besides. The `nexus_repositories` role compares everything but the password, so `site.yml` writes a proxy only when its settings or username differ. `maintenance.yml --tags nexus-proxy-logins` writes them regardless, for a rotated token.
- **Nexus's `docker-io` proxy** had no upstream login before this, and `ghcr-io` a `regulad` login of unknown age. `ghcr-io`'s `docker.pathEnabled` reads `null`, `docker-io`'s `false`.
