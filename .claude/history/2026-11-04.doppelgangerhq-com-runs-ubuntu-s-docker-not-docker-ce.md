# doppelgangerhq.com runs Ubuntu's Docker, not Docker CE (2026-11-04)

- Docker CE from download.docker.com (29.9.3, `containerd.io` 2.4.2, Compose plugin 5.7.0, buildx 0.38.1) was replaced by noble-updates' `docker.io` 29.1.3, `containerd` 2.2.1, `runc` 1.3.4, `docker-compose-v2` 2.40.3 and `docker-buildx` 0.30.1. Both sides had been updating automatically: `auto_updates` gives unattended-upgrades `Origins-Pattern "origin=*"`, which takes third-party repositories too.
- Docker kept its images with `overlay2` under `/var/lib/docker`, not in containerd's image store, so containerd's downgrade from 2.4 to 2.2 touched no image. Images, containers and volumes carried over unchanged.
- apt's resolver fails unless the same command names Docker CE's six packages for removal (`docker-ce-`, `containerd.io-` and so on). `--no-install-recommends` keeps out `docker.io`'s recommends: `git`, `ubuntu-fan`, `bridge-utils`, `dnsmasq-base` and `netcat-openbsd`. Ubuntu's packages ship nothing under `/etc`, so Docker CE's leftover conffiles do not collide with them.
- The swap ran as a transient unit (`systemd-run --wait -p Type=oneshot`), so a dropped SSH session could not stop apt with Docker down. It took 25 s. The containers with `always` and `unless-stopped` policies came back on their own, and the site answered 502 for a few seconds while the app started.
- Don't purge `docker-ce` or `containerd.io`. Their purge scripts run `deb-systemd-helper purge` on `docker.service`, `docker.socket` and `containerd.service`, the units Ubuntu's packages now use. They stay in dpkg's `rc` state, with `/etc/default/docker`, `/etc/init.d/docker` (ignored beside the native unit) and `/etc/containerd/config.toml`. Ubuntu's containerd still reads that file, whose `disabled_plugins = ["cri"]` keeps the CRI plugin off.
- Docker's APT source, `/etc/apt/sources.list.d/docker.list`, and its key, `/etc/apt/keyrings/docker.asc`, are deleted.
