# firewalld on every own-kernel Linux host, zones declared or not (2026-10-30)

- The CVE stopgap's nftables tasks moved from the firewalld role into `cve_2026_98432`, so firewalld manages only firewalld; the table keeps its name, file and unit.
- firewalld now runs on every Linux host with its own kernel but Proxmox nodes. A host that declares no zones gets the package's default zone (public: SSH and DHCPv6; Oracle Linux adds cockpit). Docker's and Netavark's published ports pass on their own, so only what a host serves outside them needs declaring: Wings' API and SFTP (8080, 2022) and the node's allocations on dodo, and nginx's 80 and 443 on doppelgangerhq.com. Wings runs game servers with host networking, so their ports are the host's own, outside Docker's zone; the panel defines the allocations, 45500-45599 on dodo.
- On doppelgangerhq.com firewalld exited within a second of starting: `nft` answered "No such file or directory" for its first `ct state` rule. The Android containers' init writes an empty `/proc/sys/kernel/modprobe`, which is the whole kernel's setting, so no module loads on demand. `/etc/modules-load.d/firewalld.conf` loads `nft_ct`, `nft_fib_inet`, `nft_reject_inet` and `nft_chain_nat` at boot instead; masquerading, logging or rate-limiting would need `nft_masq`, `nft_log` or `nft_limit` there too. To find a rejected rule, extract firewalld's JSON batch from its journal and bisect it with `nft -c -j -f -`, which checks without applying.
- Stopping Docker for firewalld's first start took Kasm Workspaces down on vkasm: `kasm.service` requires Docker, and its stop script removes its containers. The role restarts only units it saw `running`, and a oneshot reads `exited`, so kasm.service stayed inactive until it was started by hand; its start script recreates the stack. The role's `docker start` also named container IDs that Wings and Kasm had already replaced. Both remain to fix.
- aboriginal's eth0 and wlan0 are both trusted, so firewalld filters nothing there: Home Assistant and the Matter server take UPnP event callbacks, SSDP replies and Matter subscription reports on ports chosen at run time. A zone's `remove` takes out entries the module would otherwise keep, here the hand-added samba. smbd had not run since aboriginal booted on 2026-10-29: it requires `mnt-media.mount` and `mnt-cephfs.mount`, and one failed.
- mail's firewalld is described as the image and hand edits left it: its default zone, the `allow-mail-out` policy and Oracle's `direct.xml`, both byte copies. Netavark adds its networks to `trusted` at run time only, never to the permanent zone. Tailnet clients cannot reach aboriginal's LAN address, as it answers over tailscale0, so test its services from another LAN host.
