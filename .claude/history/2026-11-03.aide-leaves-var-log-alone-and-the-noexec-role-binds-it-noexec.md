# AIDE leaves /var/log alone, and the noexec role binds it noexec (2026-11-03)

- **AIDE no longer watches `/var/log` on any host.** The narrower log exclusions it replaces are gone from the aide role's defaults (sysstat, letsencrypt, the Oracle Cloud Agent, unattended-upgrades) and from the host_vars of vkasm, matrix, dodo, pterodactyl and prodingus. Lost: AIDE no longer sees a log truncated or removed, or anything else put there, and auditd's records will go unwatched with them, in `/var/log/audit`, once it runs.
- **`/var/log` is bound over itself with `noexec`, by a mount unit.** The `noexec` role renders `/etc/systemd/system/var-log.mount` (`What=` and `Where=` the path, `Type=none`, `Options=bind,noexec`, `WantedBy=local-fs.target`) for each of `noexec_paths`, named by `systemd-escape --path --suffix=mount`. util-linux applies `bind,noexec` in one `mount` call. Mount flags belong to the mount, so `noexec` holds for every file at any depth on that filesystem; a filesystem mounted below the path keeps its own options. `systemd-analyze verify` (systemd 259) finds no cycle in a unit whose `What=` is its own `Where=`.
- **What `noexec` stops and what it doesn't.** It refuses `execve` of any file there and `mmap` with `PROT_EXEC`, so a program cannot be run, nor a library loaded, from there, not even through `ld.so`. An interpreter reading a script (`sh`, `python3`) still works, as does copying the file somewhere executable. Bind mounts of a path below it carry the flag, such as aboriginal's Docker bind of `/var/log/jellyfin`.
- **`systemctl enable` writes what AIDE's refresh does not see.** The link it makes, `/etc/systemd/system/<target>.wants/<unit>`, and the directory when it is new, come from `systemd_service`, which the aide_written callback does not record, so the next report lists both as added. The noexec role makes them with `ansible.builtin.file`, taking the target from the same variable as the unit's `WantedBy=`, and `systemd_service` then finds the unit enabled. Any other role that enables a new unit through `systemd_service` leaves the same two entries in the next report.
- **A path with an `/etc/fstab` line is refused.** A unit in `/etc/systemd/system` takes precedence over the one systemd-fstab-generator writes to `/run/systemd/generator` under the same name, so it would hide that filesystem's own mount. No host had `/var/log` as its own filesystem: every reachable host keeps it on its root filesystem (XFS on the Oracle Linux instances, ext4 on prodingus, doppelgangerhq.com and vkasm, btrfs on aboriginal and dodo), and no container declares a mount point there. turk was not checked.
- **Containers may mount it.** All 29 gonkputer containers have nesting, so Proxmox gives them LXC's generated AppArmor profile with `allow_nesting`, which carries a bare `mount,` rule; the kernel lets a container's root add flags to a mount in its own namespace.
- **Other roles see the same files.** clamav-scan walks a mount point whose major:minor matches the scan's, which a bind of the same filesystem shares. restic reads btrfs snapshots or read-only non-recursive binds of each filesystem, both of which hold `/var/log`'s files. aide-report already excludes every extra mount point.
- **A bare `tailscalerouter` is the container.** From the operator's machine, the resolver's search list includes `regulad.internal`, so `ssh tailscalerouter` reaches `tailscalerouter.regulad.internal` (VMID 122), whose host key differs from the OCI instance's. Ansible reaches the instance as `tailscalerouter.pubsub.wahlecloud.oraclevcn.com`.
