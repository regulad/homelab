# mail delivers each address once, to its owner's mailbox (2026-11-05)

- docker-mailserver's generated alias map, `ldap-aliases.cf`, returned every `mail` value of the directory entry an address matched. Mail to one address of an entry with several fanned out to all of them, and Dovecot, whose LMTP looks users up by `uid=%n`, rejected each whose local part was not the uid (`550 5.1.1 User doesn't exist`) after Postfix had accepted the message, bouncing it to the sender. The logs then held 18,367 bounced LMTP deliveries against 4,062 delivered. One entry, the owner's, had more than one `mail` value; three others had none at `<uid>@regulad.xyz`.
- The map now returns one address per entry, `<uid>@regulad.xyz` (`result_attribute = uid`, `result_format = %s@regulad.xyz`), from an override `ldap-aliases.cf` in docker-mailserver's config directory, which it copies over its own. It then fills only the lines that already exist and that its `LDAP_` settings name, through `_replace_by_env_in_file`, so the override leaves `server_host`, `bind_dn`, `bind_pw`, `search_base`, `query_filter` and `start_tls` empty and they stay in `mailserver.env`.
- Clients log in with `<uid>@regulad.xyz`: 2,155 IMAP and 10,934 SMTP logins had a domain, against 11 and 3 without. Dovecot keeps mail in `maildir:/var/mail/%d/%n`, so a login with the domain reaches `/var/mail/regulad.xyz/<uid>`, where LMTP delivers, and a bare uid reaches `/var/mail/<uid>`, another mailbox. Each user's home is `/var/mail/<uid>` (`user_attrs` `home=/var/mail/%n`), and holds their Sieve script: the owner's forwards to Gmail. Three mailbox directories under `regulad.xyz/` are not named for a uid, with one or two messages each.
- One message to two addresses of the same entry made two LMTP deliveries in one transaction, as Postfix keeps recipients whose original addresses differ; Dovecot saved it once.
- The sender check, `smtpd_sender_login_maps`, looks in the users map before the alias map, so the change leaves who may send as which address as it was.
- A map can be tried against the live directory without a deployment: copy the generated `.cf` inside the container, change it, and query it with `postmap -q <address> ldap:<copy>`.
