# mDNS is systemd-resolved's, except where Avahi reflects it (2026-11-04)

- **Ubuntu 26.04's systemd turns mDNS off in a drop-in.** It ships `/usr/lib/systemd/resolved.conf.d/00-disable-mdns.conf` (`MulticastDNS=no`), which overrides `/etc/systemd/resolved.conf`: ingress's hand-set `MulticastDNS=yes` there had had no effect since its release upgrade. A drop-in named after it, `/etc/systemd/resolved.conf.d/mdns.conf`, wins.
- **What answered mDNS before** (a read of UDP 5353 on every homelab host): resolved on aboriginal, beside Home Assistant's and matterjs-server's own responders (their podman-compose stack, host network); avahi-daemon on cordpepperer, peppercord and vaultwarden (the `avahi` role's reflector), on prodingus (installed by hand on 2026-05-12 with avahi-utils, near its defaults), and inside timemachine's image. unifi's cloud-init snippet writes its networkd drop-in for `eth0`, but its interface is `ens18`, so its mDNS is off; cloud-init does not run there again.
- **Proxmox writes a container's network and resolver.** At each start it writes `/etc/systemd/network/eth0.network` and `/etc/resolv.conf`, the latter from its node's (`nameserver 10.23.0.254`, `search regulad.internal`). Drop-ins in `eth0.network.d` survive the rewrite; `/etc/.pve-ignore.resolv.conf` keeps `resolv.conf` from it (as `.pve-ignore.eth0.network` keeps ingress's hand-made `eth0.network`, with its routes through the upstream router).
- **resolved's own DNS servers are not Proxmox's.** From DHCP and router advertisements each link learns 10.23.0.254, arawi's ULA and the upstream router's global address; the last knows nothing of `regulad.internal`, and none gives the search domain. With resolved's stub as the containers' resolver, each `eth0` takes arawi's addresses, IPv6 then IPv4, both so that the resolver can fall back between families, and arawi's domain (`pfsense_setup.domain`) to search, with `[IPv6AcceptRA] UseDNS=false`.
- **Why resolved rather than Avahi** (AGENTS.md): it converges on systemd, and programs that skip NSS, such as Go's and Rust's resolvers, query `resolv.conf`'s nameserver directly, which answers `.local` only when that is resolved's stub: `dig @127.0.0.53 prodingus.local` answers on the containers now. On the reflector hosts `.local` resolves through `nss-mdns` alone, so such programs do not get it there.
- **Answers to a multicast group pass no stateful firewall.** They come from whichever host answers, so conntrack matches none to its question, and a host behind input policy `DROP` neither resolves nor answers. `tofu/gonkputer`'s cluster security group `mdns` admits UDP 5353 to `224.0.0.251` and `ff02::fb`, referenced by the eight containers with firewalls; dodo and vkasm admit firewalld's `mdns` service; aboriginal's interfaces are in firewalld's trusted zone.
- **resolved answers on every link it does not see networkd configure,** by its global setting: Podman bridges and veths, `docker0`, `tailscale0`, `tun0`.
- **`nss-mdns`'s package configures `mdns4_minimal`,** which returns IPv4 addresses alone; `mdns_minimal` returns both families' (with scope ids on link-local and ULA answers).
- **ncsusplitt runs resolved beside unbound,** which listens only on eth0's and tailscale0's link-local addresses: resolved answers mDNS there with `DNSStubListener=no` (`resolved_settings_host`, written as `host.conf` before resolved first starts), and the host keeps Proxmox's `resolv.conf`. pihole keeps its own, blocky at 127.0.0.1, and answers mDNS too.
