# Pipeline checks cache facts and inventory, and a stage's signal follows alock's records

- One tagged check of one container (tsexit, `--tags base`) took 131 s through `go tool task`: 83 s of it was the `upstream` dependency, which `check` and `apply` never use (only `plan` decides whether to skip), and about 30 s the inventory, which the pipeline read uncached. Loading ansible-generated's inventory took 32 s uncached and 2 s cached. Without either, with facts cached, the same check took 12 s.
- `--flush-cache` clears the fact cache as well as the inventory cache, and `ANSIBLE_INVENTORY_CACHE` turns only the inventory's off. With bare applies denied, every change to the OpenTofu state comes through `<root>:apply`, which now clears the inventory cache, so the pipeline keeps it on.
- `ansible-common/playbooks/facts.yml`, imported first by the shared `site.yml` and `maintenance.yml` and last by each stage's, gathers facts only outside check mode: an apply's later plays and every later run read its hosts' facts from the cache, while a check gathers each host's once an hour. alock's host lock holds for the whole apply, so no other apply on that host reads its facts in between.
- alock names a host's record `refs/alock/host/<host>`, its target key URL-quoted (`libexec/alock/common.py`'s `encode_name`, at 0.2.0), which leaves a host name as it is; remote mode fetches origin's into `refs/alock-origin/`. A stage's signal is now a digest of both for its hosts, so an apply from any worktree or clone re-plans its dependents.
