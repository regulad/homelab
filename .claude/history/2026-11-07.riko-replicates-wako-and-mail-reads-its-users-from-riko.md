# riko replicates wako, and mail reads its users from riko (2026-11-07)

- riko is a CA-less FreeIPA replica of wako, from `freeipa_server`'s `freeipa_server_replica_of`: `ipa-replica-install --server=wako.regulad.internal --principal=admin`, with the admin password from wako's secrets. Oracle Linux 10.2's AppStream carries the same FreeIPA as wako's AlmaLinux, 4.13.4. wako's Proxmox firewall admits FreeIPA's ports from any source, so riko needed no rule there.
- At 2 GB, the installer refused to start: "Less than the minimum 1.2GB of RAM is available, 0.96GB available". The kernel shows 1.69 GB of the 2, and AIDE's first baseline held 167 MB at the time. It stopped before the client enrolment, leaving nothing on wako to clean up. riko runs at 4 GB, and A1 memory is at 18 GB.
- OCI resets an instance's hostname and `/etc/hosts` at boot. `PRESERVE_HOSTINFO=2` in `/etc/oci-hostname.conf`, from `oci-linux-config`, keeps both, as Oracle's guide to changing an instance's host name sets it. riko's `/etc/hostname` is `riko.regulad.internal`, and its `/etc/hosts` maps that name to its VCN addresses from OpenTofu state; both survived the resize's reboot.
- The OCI instances remove `nfs-utils`, `rpcbind` and `gssproxy`, each with everything that depends on it. `ipa-server` requires `gssproxy`, and `ipa-client` requires `nfs-utils`, which requires `rpcbind`, so a second `site.yml` run would have removed FreeIPA; a check run showed it. riko sets `host_files_removed_packages: []`.
- `riko.regulad.internal`'s A and AAAA records are on arawi, beside wako's system records, and on tailscalerouter's Unbound, in a transparent zone that still forwards every other `regulad.internal` name to arawi, so riko resolves in OCI while arawi is down. riko has no SRV records yet.
- Both replication agreements report "Incremental update succeeded", and wako's total update of riko "Total update succeeded". Binding as `svc-mail` from mail, both servers returned the same 102 mail users and the same 2,050 lines of the attributes mail's filters read. The mailserver container has no `ldapsearch`; mail's host does.
- mail's `LDAP_SERVER_HOST` is `ldaps://riko.regulad.internal`, from `mailserver_ldap_server`. Postfix's LDAP maps and Dovecot's user lookup answered from riko after the container's restart.
