# memory.regulad.xyz: basic-memory behind mcp-auth-proxy and a token-checking Caddy, on container 213 (2026-11-22)

- **Tailscale cannot hold an arbitrary DNS record:** "It's not possible to add arbitrary records to MagicDNS" (tailscale/tailscale#1543), and provider 0.30.0 has no such resource. None was needed: pihole, the tailnet's global resolver, answers `ingress.regulad.xyz` with ingress's LAN addresses, so a CNAME to it brings LAN and tailnet clients in from LAN ranges.
- **Ubuntu 26.04's `caddy` is 2.6.2, in universe.** Its header matcher expands placeholders in the value and compares exactly, but it has no `{file.*}`, only `{env.*}`. Its `caddy.service` runs `caddy run --environ`, which prints the whole environment to the journal at start, so a drop-in replaces `ExecStart` before any secret is put in its environment.
- **basic-memory 1.0.0's image** serves SSE on every address by default (`CMD`), and keeps its state in `~/.basic-memory` unless `BASIC_MEMORY_CONFIG_DIR` moves it. The image creates `/app/data` and `/app/.basic-memory` owned by its user, UID 1000, and a new named volume takes that owner, so neither needs `:U`. FastMCP 4.1.3, under it, refuses a Host that is not loopback's (421), which memory's Caddy meets with `header_up Host {upstream_hostport}` and mcp-auth-proxy by rewriting Host itself. It also refuses an Origin that does not match with 403, which `FASTMCP_HTTP_ALLOWED_ORIGINS`, a list of patterns, would relax; a request with no Origin is not checked.
- **mcp-auth-proxy 2.11.0** takes every flag as an environment variable (`OIDC_CLIENT_SECRET` among them), registers clients dynamically with no flag to turn it off, keeps its clients, tokens and keys under `DATA_PATH` in a bbolt file, and runs as root unless told otherwise: here as 65534, its volume `:U`. A request without a valid token gets its 401 with `WWW-Authenticate: Bearer resource_metadata="…/.well-known/oauth-protected-resource/mcp"`.
- **authentik's default `profile` scope carries `groups`,** the names of the user's groups, which the freeipa source syncs from FreeIPA. A sync starts at once with `POST /api/v3/tasks/schedules/<id>/send/` as a superuser; `memoryusers` was there 10 s later, rather than at the next two-hourly run.
- **A new host's first `site.yml` needs:**
  - its own `mail_relay_password`, which the `mail_relay` role asserts;
  - in a worktree, the decrypted inputs of every root whose outputs the run reads (`restic` reads `tofu/backblaze`'s for every host, keyed or not);
  - no `podman-auto-update.timer` in `host_files_units` on a Quadlet host. `host_files` enables its units before the Podman play installs Podman, and the `quadlet` role enables the timer itself.
- **community.general 13.5.0's `ipa_group`** reported a new group with a member as failed, as the jenkins role's FIXME says; a check run then showed it `ok`, created as asked.
- **The access check, from outside every allowed range** (an OCI instance, through ingress's public address), answered 403 with and without the client token; from the LAN, the client token reached basic-memory, and a wrong one fell through to mcp-auth-proxy's 401. From ingress, memory's Caddy answered 401 to a request without the backend token, and basic-memory refused connections on every address but `127.0.0.1`.
