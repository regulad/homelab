# AIDE repairs Podman's image store by a maintenance play, and explains dpkg's file triggers and kdump's first-boot image (2026-11-04)

From the reports of aboriginal, livekit, matrix, pihole, nexus and ingress on 2026-11-04.

- **`podman system check` has two false positives, both in c/storage's `check.go`** (Podman 5.7.0; the same code on container-libs' main). Neither has an upstream issue; podman#25101 is a third, directory mtimes after some `podman create` setups.
  - **An opaque whiteout can drop files from its own layer.** `headers()` sorts each layer's headers so that whiteouts come first, but its comparator does so only for entries in the same directory and orders the rest by full name, which is no consistent ordering. Go's stable sort then placed nine of `nexus3:3.70.5`'s layer-4 entries in `opt/sonatype/nexus/.install4j/` before that layer's `opt/sonatype/nexus/.wh..wh..opq`, which removed them from the expected tree, so each layer from 4 up reported them as added (`+`). A replay of Go's `stableCmpFunc` over the first four layers' tar-split lost the same ten files. Per the OCI layer spec, a layer's whiteouts apply only to the layers below it.
  - **Device nodes in an unprivileged container.** c/storage skips a tar entry for a block or character device when it counts itself rootless (`extractTarFileEntry` in `pkg/archive/archive.go`: "cannot create devices in a userns"), which root in an unprivileged container is, but the check expects every header. On ingress, linuxserver's Alpine base layer under `ldap-auth:3.4.8` lists `/dev/null`, `zero`, `random`, `urandom` and `console`, and every layer above it reports them missing (`-`), daily, until upstream changes.
- **A crash leaves an empty layer directory behind.** pihole's `overlay/<id>` held an empty `diff`, `link` and `lower`, made at 16:01:31 on 2026-11-01 as prodingus went down; layers.json never named it, so the check reports it "not accounted for".
- **What `--repair` removes.** Without `--force`, `podman system check --repair` removes the damaged images no container uses and the damaged layers, and removes an unaccounted layer at the driver; a damaged image a container uses stays. It then checks again, and exits non-zero with "damage in local storage still present after repair attempt" while anything is left (`check` in `cmd/podman/system/check.go`). `aide-report --repair-images` runs it, or `containers-storage check --repair` where Podman predates 5.2, and `maintenance.yml --tags podman-repair` runs that on the hosts given with `--limit`; aide-report's mail names that play.
- **dpkg rewrites `/var/lib/dpkg/triggers/File` on each upgrade of a package with a file trigger.** The package's lines move to the end: base-files' upgrade moved its three there on aboriginal. The list is exactly the `interest`, `interest-await` and `interest-noawait` lines naming a path in the installed packages' `/var/lib/dpkg/info/<package>.triggers`, as `<path> <package>[/noawait]`, the package with its architecture where dpkg's record names one (56 lines on aboriginal); a removed package's `.triggers` goes with its other records. aide-report now explains the file when it lists exactly those.
- **kdump builds a kernel's kdump initramfs at the first boot into it.** kexec-tools' `60-kdump.install` does nothing on `add` ("kdump initramfs is strictly host only and managed by kdump service"), and `kdumpctl` logs "No kdump initial ramdisk found" and rebuilds it at start. livekit's for 207.111.5.6 appeared at its boot on 2026-11-03, after a baseline later than the kernel's install. aide-report now explains kdump's image for the running kernel, of an installed package, written during this boot, when the boot began after the baseline (`btime` in `/proc/stat`).
- **A refresh moves the database's mtime.** aide-report's mail gave the database's mtime as the baseline's date, which every Ansible refresh moves; it now gives the manifest's, which only `--baseline` writes: livekit's mail said 2026-11-04 00:15 for a baseline of 2026-11-02 11:15.
- **The Unified Monitoring Agent's sockets are in `/etc/unified-monitoring-agenttmp`,** its unit's `SERVERENGINE_SOCKETMANAGER_SOCK_DIR`: ServerEngine makes `SERVERENGINE_SOCKETMANAGER_<UTC time>_<pid>` there at each start and never removes the directory. It is on livekit, mail and doppelgangerhq.com and not on bailout or tailscalerouter, though tofu/oracle enables Custom Logs Monitoring on all. Those three bind it noexec and leave it to AIDE, which lists every socket added or removed whatever its rule for `/etc` records.
- **`/var/backups` is left to noexec on Debian and Ubuntu.** `dpkg-db-backup.timer` copies dpkg's `status`, `diversions`, `statoverride`, `arch` and the alternatives there daily, as `.0`, rotated through `.6.gz`, and apt does so for `extended_states`. Debian's own `31_aide_dpkg` gives them rotation rules, says an exclusion handles them best, and its rules still list each rotation: matrix's report held 7 of them.
- **pipx logs each command.** `community.general.pipx` with `global: true` writes `/opt/pipx/logs/cmd_<time>.log` at every run and removes the oldest (matrix holds 11); matrix and aboriginal bind the directory noexec and leave it to AIDE, as ncsusplitt already did.
- **A compose stack's network file is rewritten at each restart.** `podman-compose@.service` stops with `podman-compose down`, which removes the project's networks, and `up` makes them again from the compose file, with a new `id` and `created` and the same subnets: aboriginal's `nextcloud_default.json` after systemd restarted the stack for libpcre2's upgrade.
- **Image cleanup.** `podman-auto-update.service` already runs `podman image prune -f` after each auto-update, which removes dangling images. A tagged image nothing runs stays, such as nexus's earlier releases; `podman image prune -a` would remove a stopped quadlet's image too, as quadlet removes the container when its unit stops.
