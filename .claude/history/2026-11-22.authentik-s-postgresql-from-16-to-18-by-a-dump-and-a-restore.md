# authentik's PostgreSQL from 16 to 18, by a dump and a restore (2026-11-22)

- **`authentik-postgres-upgrade` moved the database from 16.16 to 18.7** in one run, with no rollback: all 230 tables' row counts matched after the restore. The data directory is now `18/docker` inside the `authentik_database` volume, mounted at `/var/lib/postgresql`, and takes about the same 253 MB the old one did. The copy of the old data directory, the dump and the old compose file, 272 MB together, stay in `/var/backups/authentik-postgres-upgrade` until `authentik-postgres-upgrade-cleanup`.
- **The TCP readiness check waited out 18's first initialisation:** `pg_isready --host=127.0.0.1` retried once while the image's entrypoint ran `initdb` and its temporary socket-only server. Once it answered, `SHOW server_version_num` read 18, and the restore went through in one transaction.
- **`podman-compose up --detach postgresql`** starts that one service from the stack's project, with the `.env` it reads, so the new major initialises with the same user, password and database the stack declares. `podman-compose down` removes it again before the unit starts the whole stack.
- **The server answered its readiness check about 30 s after the stack started,** and nothing changed in `tofu/authentik`'s plan.
