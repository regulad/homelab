# doppelganger's Stripe webhook endpoint at API version 2026-10-28.endive (2026-11-17)

- **API version:** Stripe sets a webhook endpoint's `api_version` only when it creates the endpoint; the update parameters have none. The provider plans a change as a replacement, which brings a new endpoint ID and a new signing secret.
  - `create_before_destroy` keeps an endpoint in place throughout.
  - Events the new endpoint sends before `web.env` has its secret fail their signature check, and Stripe retries them.
- **Restarts:** `/etc/doppelganger/web.env` lists no units to restart, so `host_files` rewrites it without a restart. The web container takes the new environment from the `docker_compose` play (`site.yml --tags docker_compose`), which recreates the stack.
- **Checking the secret:** comparing the sha256 of the rendered secret with that of `tofu output -raw` shows the right secret arrived without printing it. Reading `web.env` or `docker ps` there needs `--become`.
- Docker's `{{.Names}}` format in an ad hoc `ansible -a` command is taken for a Jinja template; use `docker ps --filter` with its default columns instead.
- **Account default:** the Stripe account's own default API version stays at Parker's discretion. doppelganger sends its own `Stripe-Version` through stripe-node 23, and its endpoint has its own `api_version`.
