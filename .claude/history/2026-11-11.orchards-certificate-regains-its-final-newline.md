# Orchard's certificate regains its final newline (2026-11-11)

- **community.sops's vars plugin trims each decrypted file before Ansible parses it.** It calls `decrypt()` in `module_utils/sops.py`, whose `rstrip=True` default strips the decrypted YAML's trailing whitespace. When a file's last value is a `|` block scalar, it reaches Ansible without its final newline. Both `sops -d` and `sops -d --extract` keep that newline. Appending a key after such a value changes what Ansible renders, although neither the value nor its ciphertext changes.
- **How it showed on orchard**: `orchard_controller_cert` was the last key in `ansible-common/group_vars/all.sops.yml` when host_files first wrote `/etc/orchard/controller.crt`, so the file got 708 of the certificate's 709 bytes. Adding `orchard_service_account_tokens` after it made the next host_files run rewrite the file and restart `orchard-controller.service`.
- **Finding such values**: decrypt a file and parse the text with Ansible's own Python, once as it is and once after `rstrip()`, then compare the two results. On this date, only two values that Ansible reads were in that position: arawi's `arawi_u5g_ssh_private_key` and vaultwarden's `quadlet_env_files.vaultwarden`, each the last value in its host's `secrets.sops.yml`. The `private_key` values in `tofu/azure` and `tofu/gcp` are also last, but no Ansible stage reads those files.
- **`sops edit` keeps the ciphertext of every value it doesn't change**, so `git diff` on a SOPS file shows exactly which values changed.
