# firewalld shared by both stages, with tailscale0 trusted (2026-10-29)

- The `firewalld` role is in `ansible-common` and runs on `debian:ubuntu:rhel:!proxmox_containers:!proxmox_nodes`, but changes only hosts that declare `firewalld_zones`. bailout, livekit and tailscalerouter had `tailscale0` bound to no zone, so it fell into `public`; it is now in `trusted`. mail runs firewalld with nothing declared, and its `trusted` zone holds `10.89.0.0/24` and an IPv6 `/64` that Netavark added: Netavark 1.17 on EL9 uses its iptables driver and adds each Podman network to `trusted` when firewalld runs. aboriginal runs firewalld by hand: `tailscale0` and `eth0` trusted, `wlan0` public, Docker's bridges in `docker`.
- Docker and Netavark open firewalld for published ports themselves. Docker makes a `docker` zone (target ACCEPT, its bridges) and a `docker-forwarding` policy from any zone into it; Netavark puts its networks in `trusted`. mail's published SMTP and IMAP ports are in no zone. Both set this up as they start with firewalld running, so the role stops Docker and rootful Podman's containers (their units, where they have one) before firewalld first starts and starts them again after, in an `always:`.
- With the nftables backend firewalld flushes only its own table, and a drop in any table is final, so a table beside it applies on every interface, trusted ones included. `tasks/table.yml` loads one through `nft-table-<name>.service`, not `nftables.service`, whose stop runs `nft flush ruleset`. Rich rules cannot match an IPv4 header's length, and the direct interface is deprecated. `nft -c -f` accepts the file's `table`, `delete table`, `table { ... }` sequence even when the table does not exist yet, without touching the ruleset.
- linuxbrew's `ansible` bundles `ansible.posix` 2.2.2, so the hardware stage resolves it without an install into its `collections/`. In a worktree-isolated session `prepare.sh` cannot be sourced; `sh tofu/<root>/prepare.sh` writes the decrypted inputs, and the generated inventory runs as `sops exec-env ../tofu/shared/backend.sops.env 'PATH="$PWD/bin:$PATH" ansible-playbook ...'`; alock's shim still wraps it, being first on `PATH`.
