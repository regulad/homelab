# Doppelganger's Google project restored and adopted, and why OAuth clients stay out of OpenTofu (2026-11-16)

- `pure-toolbox-429813-a4` ("doppelganger", number 6822405828) holds "Doppelganger Production", the OAuth web client behind the Supabase project doppelganger's sign-in with Google. The 2026-11-04 cleanup of unused projects deleted it, which broke that sign-in; Parker restored the project and the client, and `tofu/gcp` adopted the project, its one enabled API and `homelab-tofu`'s Owner grant. It has no billing account.
- A Google client ID begins with its project's number. Google's sign-in page, `accounts.google.com/o/oauth2/v2/auth?client_id=…`, answers `Error 401: deleted_client` for a client of a deleted project, without signing anyone in; it still did after the restore. Google's restore documentation allows OAuth clients 1 to 3 days to work again after a project is restored, and support after that.
- No supported API manages Google's standard OAuth clients or consent screen: IAP's OAuth Admin API, which only handled internal brands, was shut down on 2026-03-19, and the Google provider 8.0.0 removed `google_iap_brand` and `google_iap_client`. `google_iam_oauth_client` serves Workforce Identity Federation only. `clientauthconfig.googleapis.com`, the console's own back end, is undocumented, and its list returns client secrets. Firebase's v1alpha `firebase:provisionFirebaseApp` can make a new web client with chosen redirect URIs, but turns Firebase on in the project and only ever adds URIs; a provider resource for it is requested in hashicorp/terraform-provider-google#30646.
- Entra's app registrations are fully manageable: `hashicorp/azuread` drives them through Microsoft Graph, and `tofu/azure` already declares one, `regulad rclone`, with a redirect URI. Only a client secret's value is limited: Graph returns it once, at creation, and existing secrets cannot be imported.
