# Tailscale DNS off on aameter, aboriginal, qb and uptime: NC State's split DNS is out of their reach (2026-10-30)

- The problem. `dns.json5` in `regulad/tailscale-acls` sends `ncsu.edu` and `ncstate.net` to NC State's own resolvers, vrd2 (152.1.14.12) and vrd1 (152.1.14.14), and adds `sd.ncsu.edu` to every node's search list. Both stay as they are, so that nodes on NC State's own network resolve its internal names without accepting routes. A Linux node that takes Tailscale's DNS (`accept_dns`, on by default) but not subnet routes (`accept_routes`, off by default on Linux) has no path to vrd1 or vrd2: tailscaled forwards their queries out the default route, and NC State drops them. On such a node an NC State name failed after 40 s, and every name that does not exist took 20 s, glibc's 5 s timeout × 2 attempts × 2 nameservers on the `sd.ncsu.edu` search domain. Of the hosts this repository puts Tailscale on, those were aameter, aboriginal, qb and uptime (`tag:server`, both settings left at their defaults); the others set `accept_dns: false`, and both tailscalerouters also accept routes.
- `accept_routes` is all or nothing, on Linux as elsewhere, and accepting every route breaks LAN hosts. The LAN's tailscalerouter advertises the LAN's own `10.23.0.0/20` and `fd83:b84c:aa57:1::/64`. tailscaled installs accepted routes in table 52, whose rule (priority 5270) comes before `main` (32766), so a LAN host would send its own LAN traffic into `tailscale0`. A reply to a connection the LAN opened leaves with the host's LAN address as its source, and WireGuard at tailscalerouter discards it, as the host advertises no routes that would allow that source; the host's outbound LAN traffic leaves from its tailnet address and fails LAN-only allowlists such as Proxmox firewalls admitting `dual_stack_lan_cidrs`. LAN traffic over GUAs, whose /64 is not advertised, would be untouched. tailscale/tailscale#1227, "When local route is available to a subnet, bypass tailscale subnet relay", has been open since 2021-01 and was locked in 2025-03; a maintainer declined low-priority subnets because a node cannot tell its own LAN from another network on the same prefix.
- The tailnet policy cannot narrow which routes a node installs: grants decide only what a router lets through (the policy's own comment on its first grant).
- Accepting routes and adding `ip rule`s ahead of table 52 that send the LAN's and the VCN's prefixes to `main` would leave only ncsusplitt's routes in effect, and would carry tailscaled's own queries: its DNS forwarder opens plain sockets on Linux (`net/dns/resolver/forwarder.go`; `initListenConfig` exists only in `macios_ext.go`, for the macOS and iOS network extension), not the `netns` sockets marked 0x80000 that rule 5210 sends to `main`. Not pursued in favour of turning Tailscale's DNS off.
- A kernel route into `tailscale0` without `accept_routes` goes nowhere: tailscaled leaves a peer's advertised subnet routes out of its WireGuard allowed IPs unless `Prefs.RouteAll` is set (`net/routemanager/routemanager.go`, `PeerAllowedIPs`), so no peer owns 152.1.14.12 and the packet is dropped inside tailscaled. A route through the LAN's tailscalerouter, which accepts routes, would carry it, with NC State's replies coming straight back from ncsusplitt's `eth0`. Not pursued either.
- Tailscale's DNS is tailnet-wide; nothing points one machine, tag or group at another resolver, so split DNS cannot send only these hosts to ncsusplitt's Unbound. Open feature requests: tailscale/tailscale#18985, "Per-group DNS resolver configuration in tailnet policy" (2026-03); #17932, "Per-device DNS / DoH configuration in Tailnet" (2025-11); #18379, "Make 'Override DNS servers' more than a global switch" (2026-01).
- The fix: `accept_dns: false` on the four. tailscaled then restores the `resolv.conf` it replaced, kept in `/etc/resolv.pre-tailscale-backup.conf` (arawi, `10.23.0.254`, on aameter, qb and uptime). aboriginal's resolv.conf was systemd-resolved's stub and its Tailscale DNS was already off, so its declaration changes nothing there. arawi forwards `tail11540.ts.net` and the tailnet's reverse zones to MagicDNS, so full tailnet names still resolve; a bare name resolves under `regulad.internal`, the same host by its guest name. A reverse lookup of a tailnet address through arawi returned nothing in one test. NC State's names now resolve to its public answers through arawi, and names only its internal view has, such as `ncsudrive.ncsu.edu`, not at all.
- With `accept_dns` off, `100.100.100.100` answers only the tailnet's names: tailscalerouter, which never took Tailscale's DNS, got SERVFAIL for an `ncsu.edu` name and nothing for `example.com`. A container copies the host's `resolv.conf` when it starts, so one started while Tailscale's DNS was on keeps asking `100.100.100.100` until it restarts.
- ncsusplitt's Unbound stays: NC State's names, with serve-stale, on its LAN and tailnet addresses, for whatever is pointed at it. Nothing is yet; an arawi domain override for `ncsu.edu` and `ncstate.net` would point every LAN host that uses arawi at it.
