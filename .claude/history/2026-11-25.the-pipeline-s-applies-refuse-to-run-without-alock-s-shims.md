# The pipeline's applies refuse to run without alock's shims

- On this machine alock had never been installed: `~/.claude/plugins/known_marketplaces.json` listed the `alock` marketplace, registered from `.claude/settings.json` on 2026-11-24, but `installed_plugins.json` held no `alock@alock`, `~/.claude/plugins/cache/alock` did not exist, and the clone's git config set no `alock.mode`. dotfiles' plugin list has never named alock.
- `tasks/alock-path.sh` put the missing `bin` on `PATH` and went on, so every `tofu` and `ansible-playbook` apply that day, through the pipeline or bare, ran without alock's lock or commit check. `tasks/require-alock.sh`, a precondition of each `<step>:apply`, now refuses an apply Claude Code runs unless the command resolves into alock's plugin cache. Claude Code sets `CLAUDECODE=1` in each Bash command it runs, which the check keys on.
- Committing a plugin to a repository's `enabledPlugins` enables it but does not download it: Claude Code's install docs leave `claude plugin install <name>@<marketplace> --scope project` to each clone.
