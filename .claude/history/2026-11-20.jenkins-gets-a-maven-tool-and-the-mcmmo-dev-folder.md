# Jenkins gets a maven tool and the mcMMO-Dev folder (2026-11-20)

- **Maven needs no plugin.** Jenkins core has the Maven installation and its installer, which Configuration as Code sets under `tool: maven:` and declarative pipelines name with `tools { maven '<name>' }`; the installer downloads the release named by its `id` onto the agent at the build's start, from the list `hudson.tasks.Maven.MavenInstaller` that the update site serves. Jenkins's `maven` installs 3.9.16.
- **The agents can compile.** `jenkins/inbound-agent`'s JDK 21 is a `jlink` image built with `--add-modules ALL-MODULE-PATH`, so it keeps `jdk.compiler`; it lacks Maven alone.
- **Configuration as Code checks a fragment without applying it:** `ConfigurationAsCode.get().checkWith(YamlSource.of(stream))` in the script console returns the issues it finds, an empty map for a valid one, and leaves the configuration as it was.
- **mcMMO has no release tags** since 2.0.0: a release is the commit whose `pom.xml` drops `-SNAPSHOT`. Its default build leaves out the tests in the `docker` and `stress` groups.
- **The new folder needed `/configuration-as-code/reload` again,** as `z4yx` did: after the restart `mcMMO-Dev` was on disk but not an item until the reload.
- **Job DSL names a class after each script,** so a script's file name must be a Groovy identifier: the seed refused `jobs/mcMMO-Dev.groovy` for its hyphen before applying anything, and `jobs/mcMMO_Dev.groovy` holds `mcMMO-Dev`'s jobs.
- **A pipeline job polls the repository of its Jenkinsfile too.** `mcMMO-Dev/mcMMO`'s `pollSCM` watches `regulad/jobs` beside mcMMO, though it reads its Jenkinsfile by a lightweight checkout, so a push to `regulad/jobs`'s `main` builds mcMMO's head again within the hour.
- **Each build downloads everything.** The agents start empty, so a build fetches Maven (into `/home/jenkins/agent/tools`) and every dependency anew: mcMMO's first build, of 2.3.003-SNAPSHOT, downloaded about 900 artifacts and took five minutes, 1885 tests included.
