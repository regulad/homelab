# doppelgangerhq.com's devices' data is on a block volume of its own (2026-11-04)

- `/opt/doppelganger`, 22 GB in 122,615 entries, moved from the boot volume to `tofu/oracle`'s `web_data`, a 50 GB Balanced volume attached paravirtualized. The volume appeared at once at `/dev/oracleoci/oraclevdb`, with no rescan. It is mounted by `opt-doppelganger.mount` from `host_files`, and Docker's drop-in `RequiresMountsFor=/opt/doppelganger` keeps Docker from starting the devices without it.
- At the next boot the kernel named the data volume `sda` and the boot volume `sdb`, the reverse of before. Only the `/dev/oracleoci/` names stayed with their volumes, so a unit or command on an OCI instance names those, never `/dev/sdX`.
- In a native mount unit, `Options=_netdev,nofail` keeps Oracle's meaning for fstab lines (systemd.mount(5), Default Dependencies). `_netdev` orders the mount after `network-online.target` as a network mount. `nofail` drops its `Before=remote-fs.target`, so a missing volume does not hold up the boot. `findmnt` does not show either option: both are read by systemd and mount(8), not by the kernel.
- rsync copied at 24.5 MB/s, the ceiling for 50 GB at Balanced (480 KB/s per GB), so the first pass took about 15 minutes. With the site up, a first pass and then a second meant the final pass, with Docker stopped, transferred nothing. That pass, a dry run finding no differences, and the swap to `/opt/doppelganger.old` took 20 s.
- After Docker restarted, the web container's PM2 (`pm2 start --no-daemon`) exited four times, about 30 s after each start, with `ERR_IPC_DISCONNECTED` from its PM2.io agent (`@pm2/agent` 2.0.4, `InteractorClient.js`), before it stayed up. `api.cloud.pm2.io` refused connections on 443 over IPv4. No PM2.io name has an AAAA record, so this was not the new IPv6 egress. After the reboot it started on the first try. PM2.io's key pair is in the app's `.env.local`, and PM2 prints it to the container log at every start.
- AIDE does not walk other mount points, so it no longer checks the devices' data. ClamAV's weekly scan still does, as `clamav_scan_paths_host` lists `/opt/doppelganger` itself.
