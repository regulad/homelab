# ClamAV ignores an overzealous signature, and ingress's Go module cache (2026-11-11)

- **`Ps1.Trojan.LNKBuilder-10060627-0` matches any archive of Ansible with its Windows collections.** It is a logical signature in `daily.ldb`, `Target:0` (any file), with condition `0&1&2&(3|4|5)` over the case-insensitive strings `CreateShortcut`, `MpCmdRun`, `-DownloadFile`, `RuntimeBroker.exe`, `imageres.dll,68` and `.IconLocation`. No single file in Ansible holds them all: `community.windows`'s `win_shortcut.ps1` has `CreateShortcut` and `.IconLocation`, `ansible.windows`'s `win_updates.ps1` has `MpCmdRun`, and its `win_get_url.ps1` has `-DownloadFile`. clamd scans an archive's decompressed stream as well as each member, so the gzipped tar and its 589 MB uncompressed tar both match, while every member streamed alone scans clean.
- **Where it hit**: the weekly scan moved five of Homebrew's `ansible` bottles (14.5.0 to 14.6.0) out of Nexus's `ghcr-io` repository, and on vkasm layer 7 of `kasmweb/terminal:1.19.0`, which installs Ubuntu's `ansible` package, out of containerd's content store. Homebrew fetches a bottle from ghcr.io by its blob digest, without a manifest, so no manifest in Nexus names these blobs.
- **The shared clamd ignores it** through `/etc/clamav/ignored.ign2`, mounted into its database directory. Each line is the signature's name and the MD5 of its database entry, so the ignore lapses when Talos changes the signature. The entry is the line `sigtool --find-sigs <name>` prints, without its `[daily.ldb] ` prefix and without a newline: `printf %s "$entry" | md5sum`.
- **The clamav image's entrypoint, `/init`, runs `chown -R clamav:clamav /var/lib/clamav` under `set -eu` at every start**, so a read-only mount below the database directory makes it exit, and `clamav.service` fails. The ignore list is mounted writable instead, owned by the image's `clamav` user and group, 100 and 101, which the chown leaves as they are. Podman creates an empty mount point for the file in the `clamav_db` volume.
- **Quarantining a content-addressed blob breaks its store.** Nexus keeps the asset and its `.properties` file but cannot serve it. containerd keeps the blob's metadata, so anything that reads the blob fails; containers run from the snapshots. A Nexus `.properties` file names the registry path with the digest (`@BlobStore.blob-name`), the repository (`@Bucket.repo-name`) and the blob's `sha1`, which identifies a quarantined copy and verifies it. Restored blobs go back with the store's ownership and mode: `200:200` and `0644` in Nexus's blob store, `root` and `0444` in containerd's.
- **Finding which part of an archive matches**: stream each member alone to the shared clamd with `zINSTREAM`, read-only through Python's `tarfile`, rather than extracting it on the host.
- **klauspost/compress ships a malformed zip among its test data**, `zip/testdata/FuzzReader-raw.zip`, which ClamAV flags as `Heuristics.Zip.OverlappingFiles` in each version's module and module zip. Upstream keeps it (klauspost/compress#1119). Caddy depends on it, so ingress's weekly scan leaves caddy-build's `GOMODCACHE`, `/var/cache/caddy/go/pkg/mod`, alone; Go checks each module against sum.golang.org as it downloads it. The quarantine had left the module cache incomplete, so it was cleared with `go clean -modcache` under caddy-build's environment, and the stale `/var/lib/caddy/go`, whose `pkg/mod` predates `GOMODCACHE`, was removed.
