# vaultwarden's admin token is kept as an Argon2id hash (2026-11-05)

- Vaultwarden's `ADMIN_TOKEN` takes an Argon2 PHC string, not bcrypt: `$argon2id$v=19$m=…,t=…,p=…$<salt>$<hash>`, in unpadded standard base64. Its bitwarden preset, `vaultwarden hash`'s default, is m=65540, t=3, p=4. A plain-text token logs a warning at every start; the hash, salted and adaptive, sits in plaintext `services.yml`. A `/data/config.json`, which the admin page writes when it saves settings, would override the environment; vaultwarden has none.
- OpenSSL 3.2 and later has Argon2 (`openssl kdf … ARGON2ID`), but its command line takes the password in argv. Python's `cryptography` runs the same code in-process, and libsodium through PyNaCl, in Homebrew's ansible venv, verifies PHC strings with p=4 independently.
- Quadlet copies an `Environment=` value as written into the generated `ExecStart=`, where systemd expands `$` and reads `$$` as `$`. The `quadlet` role doubles each `$` in `environment` values; env files, read by podman alone, take `$` as is.
- `/admin` answers from the internet through vw.regulad.xyz, and scanners probe it; the token is 64 random base64 characters.
