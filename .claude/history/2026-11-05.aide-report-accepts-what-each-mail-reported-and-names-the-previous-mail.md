# aide-report accepts what each mail reported, and names the previous mail (2026-11-05)

- Each change is now mailed once, not in every daily report until accepted. Every mail opens with the time (ISO 8601, with its offset) and subject of the previous mail aide-report sent from the host, recorded in `/var/lib/aide-report/mailed.json`, so a lost mail shows as a gap in the series.
- **`aide --update` is a check that also writes `database_out`**, in the same walk: exit codes as `--check` (1/2/4, 14 and up errors), and the same JSON plus `new_database`. aide-report checks with it and installs that database, with a manifest built from the same moment, only after the mail is sent and recorded, so a change after the walk waits for the next report. A failed mail records and accepts nothing; a failed accept after a sent mail leaves the next mail to list the same changes.
- **AIDE may exit 0–7 with a broken database.** 0.18.6's `write_tree` and `db_close` ignore write errors; 0.19 removes a partly written database and exits 18, but ignores a failed `gzclose`. 0.19 refuses a database without `@@end_db` (exit 24); 0.18 reads it to the cut with a warning.
- **Both mail clients wait for sendmail:** Debian builds bsd-mailx to (`#ifdef DEBIAN`, Bug#145379, and it exits non-zero on failure), and s-nail's `sendwait` is on by default. `mail` returning means postdrop has queued the message; that is what "sent" means.
- **Not accepted:** a report longer than `MAIL_LINES` (400), whose cut lines were never mailed, which says so and names `aide-accept`; no baseline; a failed check; a mail about container images alone.
- `aide-report.service` is a oneshot with no start timeout and no sandboxing. The last daily runs took 15 minutes on aboriginal, 13 on dodo, 6 on bailout and 4.5 on prodingus.
