# doppelgangerhq.com sends and receives mail through mail, and Doppelganger's Auth sends from noreply@doppelgangerhq.com (2026-11-20)

- mail accepts any domain at which an unlocked FreeIPA account has an address (`LDAP_QUERY_FILTER_DOMAIN`), so doppelgangerhq.com needed no domain list on mail, only its own DKIM key, `SRS_EXCLUDE_DOMAINS` and the reply filter.
- Postfix's `smtpd_sender_login_maps` are `ldap-users.cf`, `ldap-aliases.cf` and `ldap-groups.cf`, not `ldap-senders.cf`, whose empty `query_filter` fails every lookup. Postfix takes the first map that answers: `ldap-users.cf`, which returns the account's whole `mail` list for any of its addresses. A login, `<uid>@regulad.xyz`, may send as an address only when that list holds the login, as Parker's holds `regulad@regulad.xyz` and each `null-<host>` account's is its login alone; `ldap-aliases.cf`'s `<uid>@regulad.xyz` answer is never reached. `svc-doppelganger-supabase`, holding only `noreply@doppelgangerhq.com`, was refused with `553 5.7.1 … not owned by user` at `RCPT TO`, after `MAIL FROM` had been accepted, so a sender check must go as far as `RCPT TO`; the account now holds `svc-doppelganger-supabase@regulad.xyz` too. `postmap -q` against `ldap-users.cf` prints every address the account has, private ones included.
- Rspamd's public key files follow `rspamadm dkim_keygen`: the TXT record's first string is 255 characters, `p=` and 253 of the key's, then the rest. The Cloudflare record splits `v=DKIM1; k=rsa; p=…` at 255 characters, as regulad.net's does.
- Cloudflare's `GET /zones/{zone_id}/email/auth/dmarc-reports` created doppelgangerhq.com's configuration, with its `rua_prefix`, still disabled (`status: missing-dmarc-rua`). With the `_dmarc` record already naming that address, the `PATCH` with `enabled: true` left the record as it was, and tofu/cloudflare planned no change after.
- Oracle made `doppelgangerhq-iad-20261120` `ACTIVE` about 25 minutes after its CNAME appeared, from `NEEDS_ATTENTION`; its senders came in the next apply, once the domain joined `local.email_sender_domains`.
- Supabase's Management API takes `smtp_port` as a string (`UpdateAuthConfigBody`). Once the `auth` JSON holds a sensitive value, plans show the whole setting as `(sensitive value)`; review which keys change by parsing the before and after `auth` in `tofu show -json`, masking `smtp_pass` and `external_google_secret`.
- In zsh, `set -- $q` does not split `$q` into words; run such loops under `bash -c`. On the WSL workstation, `dig @<nameserver name>` timed out resolving the name through the local resolver, `10.255.255.254`; `dig @1.1.1.1` answered.
- A message from `noreply@doppelgangerhq.com`, submitted as `svc-doppelganger-supabase@regulad.xyz` on port 465 and delivered by mail itself, reached Gmail with `dkim=pass header.i=@doppelgangerhq.com header.s=mail`, `spf=pass` (mail's IPv6 address) and `dmarc=pass (p=REJECT sp=REJECT dis=NONE)`.
