# Nexus proxies crates.io, and lime's and matrix's cargo fetch through it (2026-11-21)

- **Cargo works on Nexus 3.97.3 Community Edition with H2:** the onboarding page lists Cargo as PostgreSQL-only, but this instance's swagger.json registers `/v1/repositories/cargo/{proxy,hosted,group}`, and the `nexus_repositories` role created `crates-io` through `POST /v1/repositories/cargo/proxy` without error.
- **Nexus speaks only the sparse protocol** (cargo 1.68 or later), so the proxy's remote is `https://index.crates.io/`, with its trailing slash. Clients name it `sparse+https://repo.regulad.xyz/repository/crates-io/`; a client without the `sparse+` prefix would read the URL as a git index.
- **Nexus rewrites the index's `config.json`** to `{"dl":"https://repo.regulad.xyz/repository/crates-io/crates","api":"https://repo.regulad.xyz/repository/crates-io"}`, so crate downloads go through the proxy too, not to static.crates.io.
- **Anonymous reads need no new privilege:** the anonymous user's `nx-anonymous` role holds `nx-repository-view-*-*-read` and `-browse`, which cover a new repository of any format.
- **Source replacement keeps crates.io's name:** a lockfile made through the mirror still says `source = "registry+https://github.com/rust-lang/crates.io-index"`, and the checksums the proxied index gives are crates.io's own, so `cargo install --locked` still holds against an upstream Cargo.lock.
- **`cargo install` reads only `$CARGO_HOME/config.toml`,** not a project's `.cargo/config.toml`, so each role writes the replacement into the cargo home it builds in: `/var/cache/lime/cargo` for lime, and `/root/.cargo` for matrix, whose state compressor build now sets `CARGO_HOME` to it explicitly.
- **A cargo home's first build through the mirror rebuilds everything once:** cargo keeps the mirror's crates in a registry cache and source tree of its own (`registry/{cache,src}/repo.regulad.xyz-c3b6cfeddac57740`, beside the old `index.crates.io-1949cf8c6b5b557f`), so lime's `cargo build`, which runs at every apply, downloaded every crate through Nexus and recompiled. The new binary differed from the old one, so lime restarted once. matrix's compressor builds only where its versioned binary is missing (`creates`), so its next build goes through the mirror when `matrix_compressor_version` changes. The old cache directories stay where they are; nothing reads them now.
- **Cargo has no fallback:** unlike Podman's mirrors, a replaced source is the only source, so while Nexus is down a build that must fetch fails.
