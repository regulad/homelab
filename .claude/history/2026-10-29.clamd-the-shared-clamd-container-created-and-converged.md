# clamd: the shared clamd container, created and converged (2026-10-29)

- Proxmox writes each container's `/etc/hosts` (`127.0.1.1 <name>.<search domain> <name>`) and its `resolv.conf` from the node's DNS settings at every start. prodingus takes its address by DHCP on `vmbr0`, and arawi sends the domain search list (option 119) although prodingus's `dhclient.conf` doesn't request it. `dhclient` renders it as `regulad.internal.`, with the root's dot, and `dhclient-script` writes that into `resolv.conf` at every renewal, so `pvesh set /nodes/prodingus/dns` or an edit to the file would last only until the next one. `hostname --fqdn` in any container started since returns a name ending in a dot, as in rsshub too, and Postfix refuses that as `myhostname` and stops. `mail_relay` now drops the dot, and `proxmox_cluster` installs a `dhclient` enter hook that drops it from the node's search list; `dhclient-script` sources enter hooks at every lease event, so the running `dhclient` needs no restart.
- prodingus's `/sbin/dhclient` is a wrapper that blocks `dhclient -6` and execs `/sbin/dhclient.orig`.
- On prodingus, a reset that a container sends back for an admitted port where nothing listens never reaches the client, whether from the host or over the tailnet, so the probe times out like a drop. tcpdump shows the reset leaving the guest's firewall bridge; `PVEFW-FORWARD` drops `ctstate INVALID` first, probably on the reset's second pass through conntrack. Ping and a listener's SYN-ACK come back normally, so test a guest's firewall against a port that listens, or watch `veth<vmid>i0`.
- Upstream's `stable_base` image (1.5.4) runs read-only with `clamd.conf` and `freshclam.conf` bind-mounted and logs to the journal, needing no tmpfs beyond Podman's. With December 2025's smaller signatures (main.cvd 63, 3.29 million signatures; daily 28168), the container had about 1.0 GiB in use once clamd had loaded them.
