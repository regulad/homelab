# The Orchard controller runs in a container of its own (2026-11-10)

- **Tart and Orchard moved to OpenAI**, which bought Cirrus Labs in April 2026: `openai/tart`, `openai/orchard`, and the Homebrew tap `openai/tools`. Tart from 2.33.0 is FSL-1.1-ALv2. Cirrus's channels stopped at the move: `ghcr.io/cirruslabs/orchard` at 0.55.0, the apt repository `apt.fury.io/cirruslabs` at 0.54.0. The image the release config pushes, `ghcr.io/openai/orchard`, refuses anonymous pulls, so the GitHub release binary (`orchard-linux-amd64`, with `orchard_<version>_checksums.txt`) is the one current Linux build. Images are tagged only `<version>` and `latest`.
- **Tart has no daemon or API**: `tart run` is the VM's process. Orchard's controller is the API (`/v1/`, OpenAPI in `api/openapi.yaml`, HTTP basic auth with a service account's name and token). Its version is at `/v1/controller/info`; the docs' `/v1/info` is a 404.
- **The controller's certificate is ours**, from SOPS through `--controller-cert` and `--controller-key`. Orchard's client, given a certificate, trusts it alone and sets the TLS server name to its first DNS name, whatever address it dials, so one SAN, `orchard.regulad.internal`, serves every route. Go's verifier passes the certificate on those terms.
- **A bootstrap token is derivable without the controller**: `orchard-bootstrap-token-v0.<name>.<token>[.<certificate PEM>]`, each part base64url without padding (`internal/bootstraptoken`). The worker's stage can build it from the shared SOPS values.
- `ORCHARD_BOOTSTRAP_ADMIN_TOKEN` re-creates `bootstrap-admin` with that token at every start, and the controller then logs the token as `<hidden>`; without it, the first start prints a random token. The controller keeps its database in `$ORCHARD_HOME/.orchard/controller/` and writes a context for `bootstrap-admin` to `$ORCHARD_HOME/.orchard/orchard.yml`.
- **Worker flags for later**: `--default-memory` is 8192 MB unless set and `--default-cpu` 4. `--user <name>`, started as root, is Orchard's way past macOS's Local Network prompt. `--bootstrap-token-stdin` keeps the token out of `ps`. Workers need macOS 15 or later; the worker binary also builds for Linux, with a Vetu runtime for Linux guests only. Apple's licence allows two macOS guests per Mac, and Tart refuses a third.
- **overture**: a MacBook Air M1 (MacBookAir10,1) with 8 GB, on macOS 27.0.1, 81 GiB free of 460 GiB. Homebrew is in `/opt/homebrew/bin`, which a non-interactive SSH session's PATH lacks. Tart 2.40.1 and softnet from `openai/tools` were installed with no VMs, and socktainer (a Docker API over Apple's `container`) runs as a brew service. With no VMs it already had 989 MB of its 2 GB swap in use.
- A check run of `site.yml` on a new container stops at `auto_updates`, which reads the file that the not-yet-installed unattended-upgrades package provides; `--tags host_files` previews a host_files service on its own.
- The `terraform_state` inventory failed once with "Failed to install provider" from its scratch `tofu init`, while GitHub's API was also timing out; the next run parsed.
