# mail_relay sets an existing account's password by a maintenance play (2026-11-09)

- **`mail_relay` sets an account's password only when it creates the account.** An account that already exists keeps the password it had, and the relay's login fails. freeipa's `null-freeipa` came over from the old directory with its old password; the SOPS password made for it the same day was never set, so the relay refused every login from freeipa with `535` from 10-27, and its mail waited in Postfix's queue until it expired.
- `maintenance.yml --tags mail-password-reset --limit <host>` sets the account's password to the host's SOPS value, then sets its expiry back, as FreeIPA expires a password an administrator sets. The expiry is `mail_relay_password_expiration`, which the role's main tasks and the reset both use.
