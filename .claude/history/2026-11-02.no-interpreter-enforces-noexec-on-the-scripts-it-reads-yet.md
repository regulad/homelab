# No interpreter enforces noexec on the scripts it reads yet (2026-11-02)

- **What a `noexec` mount stops.** The kernel refuses `execve` of any file on it, and `mmap` with `PROT_EXEC` of one, so a program cannot be run from it, nor loaded through `ld.so /path/program`, `LD_PRELOAD` or `dlopen`. The one known gap in the second rule is a crafted ELF that injects code into an anonymous segment (glibc bug 21718, open since 2017). It does not stop `sh /tmp/x.sh`, `bash`, `python3` or `perl` reading a script from it.
- **Linux's script execution control exists, but nothing uses it.** Linux 6.14 added the `execveat(2)` flag `AT_EXECVE_CHECK` and the securebits `SECBIT_EXEC_RESTRICT_FILE` and `SECBIT_EXEC_DENY_INTERACTIVE`, with their `_LOCKED` variants (https://docs.kernel.org/userspace-api/check_exec.html). The kernel only answers the check: an interpreter that sees the bits set is meant to run only files that pass it, which `noexec` fails, but `security/commoncap.c` calls them "not restrictions enforced by the kernel but by user space on itself". As of 2026-11-02, no released interpreter or C library loader calls it or reads the bits: CPython, bash, dash, busybox, Perl, Ruby, PHP, Node.js, Lua, glibc's `ld.so` and musl. glibc 2.43 has the constant in `<fcntl.h>` alone. There are proposals (a CPython discussion thread, nodejs/security-wg#1388, PowerShell#25527, and php-src#17834 for `pcntl_exec()` only) and one out-of-tree patch set, exec-aware, packaged with Nix, never submitted upstream.
- **Setting the bits is not possible here yet either.** systemd v262 sets them per unit (`SecureBits=`); the fleet's releases ship 255 (Ubuntu 24.04), 259 (Ubuntu 26.04), 257 (Debian 13, AlmaLinux 10) and 252 (Oracle Linux 9). util-linux's `setpriv` support is merged but unreleased. Until a fix in Linux 7.4 (`Cc: stable` for 6.14 and later), creating a user namespace cleared them, locked ones included.
- **Kernels.** prodingus's Proxmox 7.0 kernel, so every container, and Ubuntu 26.04's 7.0 have the feature. Ubuntu 24.04's 6.8, Debian 13's 6.12, Oracle Linux 9's kernels (RHCK 5.14, UEK7 5.15, UEK8 6.12) and AlmaLinux 10's 6.12 do not.
- **What does work on Enterprise Linux** is fapolicyd: its upstream rules refuse untrusted files of the languages it knows (Python, Perl, Ruby, PHP, Lua and more), but allow shell scripts.
- **So scripts read from a `noexec` path are left to the other tools:** auditd records the interpreter's `execve` with the script among its arguments, and AIDE and ClamAV see the file.
