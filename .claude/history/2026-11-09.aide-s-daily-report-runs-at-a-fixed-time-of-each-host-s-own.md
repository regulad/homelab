# AIDE's daily report runs at a fixed time of each host's own (2026-11-09)

- **systemd adds `RandomizedDelaySec=` to a missed run counting from the boot.** For a `Persistent=` timer whose calendar time passed while the host was down, systemd moves the elapse up to the boot and then adds the delay, `FixedRandomDelay=` or not. So a host rebooted between midnight and its fixed delay ran its report that much late, and one rebooted shortly before its time put the report off past the next day's. This is systemd#21166; systemd 258 added `RandomizedOffsetSec=` (PR #36437), a fixed offset that is not counted from the boot, and Ubuntu 24.04 has 255.
- `aide-report.timer` now runs at `aide_report_minute` UTC, derived from the host's name (the first 8 hex digits of its SHA-1, modulo 1440), so the checks still spread across the day, and a check missed while the host was down runs once it is up.
- **Moving a timer's calendar time can run it at once.** systemd computes the next elapse from the last trigger, which the stamp file in `/var/lib/systemd/timers/` keeps; where the new time's last occurrence falls after it, the timer elapses as soon as it is restarted. The rollout's restart handler so started a check, before the run's AIDE refresh, on each host whose new time had passed since its last check, and those mails listed the role's own files, `/usr/local/bin/aide-report` among them. It happens again only when a host's time moves.
