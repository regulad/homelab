# auditd's space_left_action is written out of reach of oci-linux-config (2026-11-10)

- **oci-linux-config's `%post` runs `/usr/lib/oci-linux-config/passwd_mgmt.sh` at every install and upgrade,** with no opt-out. It edits the authselect custom profile `custom/oci-default` (pwquality, pwhistory, faillock with `deny=5 unlock_time=1800`), appends `FAIL_DELAY` to `/etc/login.defs`, and runs `sed -i "/^space_left_action = / s/=.*/= email/" /etc/audit/auditd.conf`, which turned the `auditd` role's `SYSLOG` into `email` on the Oracle Linux instances until the role's next run.
- **auditd splits each line of `auditd.conf` on runs of spaces** and takes the `=` as a token of its own (`audit_strsplit` and `nv_split` in audit-userspace 3.1.5), so `space_left_action  = SYSLOG`, with two spaces before the `=`, reads the same to auditd and falls outside the sed's address. The template writes it so, with a comment saying why.
- `sed -i` replaces the file even where its address matches nothing, so each upgrade still rewrites `auditd.conf` with the same content: a change of inode and times alone, which aide-report leaves out of its reports.
- **Finding what ran a command:** auditd's `ppid=` chain led to PIDs reused since earlier boots. Searching the installed packages' files for the command's own text (`sed` and its address) found `passwd_mgmt.sh` at once, and grub2's `/etc/grub.d/10_linux`, which rewrites each BLS entry's `options` line from `GRUB_CMDLINE_LINUX` when a kernel is installed; `audit=1 audit_backlog_limit=8192` and `crashkernel=` survived it on these hosts.
