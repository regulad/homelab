# dodo boots from LUKS on its own SSD, copied from the interim disk with the VM off (2026-11-20)

- **The copy took 17.5 minutes.** `rbd export --no-progress` of the 238 GiB image, 49 GiB of it used, into `dd` onto the SATA SSD ran at 243 MB/s, in a `systemd-run --wait` unit on prodingus, so it didn't depend on the SSH session. rbd exports an image's unwritten blocks as zeros, so every block was written, and `fstrim -av` in the guest afterwards trimmed 175 GiB of the root again.
- **The SSD's last 486 MiB, past the image, keep what the old layout left there.** On dodo they held only that layout's backup GPT, 123 nonzero bytes in the last 33 sectors, which `sfdisk --relocate gpt-bak-std` overwrote, and zeros. The runbook now discards that range before the GPT moves, whatever it holds.
- **A `tofu/gonkputer` apply locks every host the root lists**, so an Ansible apply another session made to wako during the copy, from a branch not yet on master, made alock refuse dodo's detach. dodo stayed off, from 21:37 to 22:14, until that branch reached master and this one was rebased onto it.
- **With the VM off, bpg/proxmox 0.122.0 plans `started` from false to true.** The apply sent Proxmox a delete for `virtio1`, which kept the image as `unused0`, then started dodo, in 24 s. The firmware's entry for shim names the EFI system partition's PARTUUID, which the copy kept, so nothing in the NVRAM changed. GRUB's debconf `install_devices` moved from `/dev/vdb1` to `/dev/vda1`.
