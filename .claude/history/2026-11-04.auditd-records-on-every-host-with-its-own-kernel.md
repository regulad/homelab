# auditd records on every host with its own kernel (2026-11-04)

- **Containers cannot run auditd.** The kernel takes audit messages only from the initial user and PID namespaces (`audit_netlink_ok` in `kernel/audit.c`), so privileged containers are refused too. prodingus's audit records every container's processes, with the host's PIDs and UIDs (each unprivileged container's root is 100000) and container-relative paths; a record's `subj=` is the container's AppArmor label, `lxc-<vmid>_</var/lib/lxc>`. Path watches resolve to the host's inodes, so they do not cover a container's files.
- **The rules,** rendered by the `auditd` role into `/etc/audit/rules.d` beside the package's own `audit.rules` (`-D`, `-b 8192`, `-f 1`, `--backlog_wait_time 60000`): writes to identity, privilege, login, loader, schedule, unit and audit paths that exist on the host; the clock set; mounts by a login; module and kexec loads; ptrace's POKETEXT, POKEDATA, POKEUSER, ATTACH and SEIZE, and `process_vm_writev`; and every `execve` and `execveat`, by a login or a service, as an intrusion through a service has no auid. Every syscall rule is written for each syscall table the host's CPU runs: `b64` and `b32` on x86_64, `b64` alone on aarch64 (mail, livekit, doppelgangerhq.com).
- **auditctl's i386 table has no `kexec_load`,** and `auditctl -R` stops at the first rule it cannot parse, leaving every later rule unloaded; kexec is the 64-bit table's alone. `-w` watches, and `perm` without an arch, apply to every syscall, which auditctl warns is slower; each watch is a `path=` or `dir=` rule for each table.
- **`augenrules`** joins `rules.d` in version order into `/etc/audit/audit.rules`, with the last `-D`, `-b` and `-f` first and `-e` last, comments and blank lines dropped, under a header naming the directory; it replaces the file only if the result differs, keeping the old one as `audit.rules.prev`. `--check` exits 0 either way. AIDE watches `rules.d` and leaves both generated files out.
- **The logs keep at most 10% of the root filesystem,** in files of 100 MB, `num_logs` derived from its size at each run: 30 on the Oracle Linux instances' boot volumes, 96 on prodingus, 98 on doppelgangerhq.com, about 200 to 240 on the VMs. auditd rotates them itself, and when space runs low or the disk fails it only logs to syslog (the Oracle Linux image's own settings mailed through the relay and suspended auditd). Its unit refuses a manual stop, so settings are reread on SIGHUP (`systemctl kill --signal=SIGHUP auditd.service`) and rules loaded with `augenrules --load`.
- **Volume, from a 30-second sample after the rollout:** prodingus about 1.4 GB a day, mostly Proxmox's pollers, about six and a half days kept; vkasm about 700 MB, Kasm's health checks, about four weeks; doppelgangerhq.com about 200 MB; mail about 100 MB; the rest under 50 MB. prodingus showed 180 lost records from before the rules, and none since.
- **Auditing from boot.** Without `audit=1`, the kernel audits only once auditd starts, before `sysinit.target`, and a process that exists by then never gets an audit context: PID 1, journald, udevd and its early workers, and anything a unit orders before auditd. Every process forked later is audited, theirs included. `audit=1 audit_backlog_limit=8192` (the boot backlog is otherwise 64) is the `kernel_params` role's GRUB drop-in `/etc/default/grub.d/99-audit.cfg` on Debian and Ubuntu (`kernel_params_audit`), as prodingus's hugepages and CPU isolation are its drop-ins too, taking effect at each host's next boot. Enterprise Linux has no `grub.d`; there it would take `grubby`, which edits the boot entries in `/boot`.
- **Decided against:** forwarding records off-host, the one defence against an intruder with root deleting them (records stay on each host, read there), and exclusions of periodic pollers, so `auditd_exec_exclusions_host` stays empty.
- **What a package's install makes is explained by aide-report** for packages installed or upgraded since the baseline: a unit's links by its packaged unit file's `[Install]` (systemctl enable or preset, and deb-systemd-helper, whose `deb-systemd-helper-enabled/<unit>.dsh-also` lists the links it made, beside an empty marker mirroring each), update-rc.d's `/etc/rcN.d/[SK]01<name>` links by the init script's LSB `Default-Start` and `Default-Stop`, and dpkg's `diversions` when every diversion added or removed is such a package's (auditd's install pulled in `libauparse0t64`, which diverts its library for the merged /usr). dpkg logs no files its maintainer scripts make; the explanations follow from files the packages vouch for, not from the scripts' own records. Each baseline now keeps the diversions it accepted.
- **Loading the installed aide-report as a module leaves bytecode beside it,** in `/usr/local/bin/__pycache__/aide-report<tag>.pyc`, as `SourceFileLoader` writes it. Scripts that do so set `sys.dont_write_bytecode` or run `python3 -B`.
