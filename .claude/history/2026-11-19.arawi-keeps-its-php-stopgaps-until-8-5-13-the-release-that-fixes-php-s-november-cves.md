# arawi keeps its PHP stopgaps until 8.5.13, the release that fixes PHP's November CVEs (2026-11-19)

- PHP 8.5.13, 8.4.28, 8.3.37 and 8.2.36 (2026-11-19) fix 18 CVEs, 17 of them with php-src advisories, seven critical at CVSS 4.0 9.2. What each critical one needs:
  - CVE-2026-129289 (GHSA-qc49-hpvq-g2w6), PHP-FPM request smuggling: FastCGI connections the front end reuses (nginx `fastcgi_keep_conn on`, Apache `enablereuse=on`) and an application that leaves `php://input` unread.
  - CVE-2026-115560 (GHSA-658j-r8rw-q6mx): upload progress writes attacker-chosen bytes into a session store that a reader with another `session.serialize_handler` deserializes. The fix turns upload progress off by default.
  - CVE-2026-126714 (GHSA-fm2m-fjf5-v3cp): the `files` handler replaces a session file in place, so an interrupted write leaves a partly overwritten file for a later read to deserialize. Upload progress is one way to fill it, large user strings in `$_SESSION` another; turning upload progress off is its listed mitigation.
  - CVE-2026-129481 (GHSA-g3vh-838c-65v7), 8.3 and later, an incomplete fix for CVE-2026-109619: a fatal error in a callback during session shutdown leaves a dangling pointer for the worker's next request. Upload progress off does not address it; the workaround is FPM's `pm.max_requests=1`.
  - CVE-2026-129496 (GHSA-gr4f-wgx5-jpfv), the timezone cache: needs a startup warning logged to a file. `php -i 2>&1` (`php-fpm8.3 -i` for an FPM's configuration) prints any the configuration raises.
  - CVE-2026-129474 (GHSA-8mjj-2r7p-4hg2), 8.5 only: needs `fatal_error_backtraces=1`, 8.5's default, with `zend.exception_ignore_args=0`, plus a fatal error entering a reachable `__call()` or `__callStatic()` and usable memory addresses.
  - CVE-2026-129182 (GHSA-2fjv-p558-g82m), 8.5 only: needs a per-path `max_memory_limit` or `zlib.output_compression` that differs from the global one.
  - The high CVE-2026-129291 (GHSA-jm4m-qfqx-967m) needs FPM's epoll backend, `catch_workers_output`, and code already running in a worker.
- PHP runs on three hosts. Pi-hole is blocky now, docker-mailserver carries no PHP, dodo's went in the 2026-10-24 cleanup, and no other image or role ships it.
- arawi: pfSense 2.9.0-RELEASE ships `php85-8.5.7` under FPM, still short of 8.5.12; no Netgate update for either PHP release had been seen. `pfsense_php_stopgap_until` moved from 8.5.12 to 8.5.13, because an 8.5.12 build would otherwise drop the upload-progress stopgap while CVE-2026-115560 and CVE-2026-126714 are still open. Its `memory_limit = -1` also rules out memory-limit failures as a write interruption, and removes CVE-2026-129474's demonstrated trigger.
  - `/etc/rc.php_ini_setup` writes `zend.exception_ignore_args=1` into `php.ini` on RELEASE builds and `=0` on development builds, which blocks CVE-2026-129474 whatever `fatal_error_backtraces` (On) says.
  - `/var/etc/nginx-webConfigurator.conf` has no `fastcgi_keep_conn` and passes no `PHP_VALUE`; its `/status` location admits 127.0.0.1 only. FPM uses kqueue and runs its pool as root. `error_log` is `/tmp/PHP_errors.log`, and no startup warning was printed.
  - CVE-2026-129481 stays open there: `pm.max_requests = 5000` is `$PHPFPMREQ` in the `/usr/local/lib/php-fpm.conf` that `rc.php_ini_setup` generates, so its workaround would mean editing a file pfSense rewrites.
- Nextcloud's `nextcloud:35-apache` runs PHP under Apache's mod_php, so neither FPM bug applies; its image built 2026-11-13 has PHP 8.5.12. The image loads no `php.ini`, only shipping the `-development` and `-production` templates, so `zend.exception_ignore_args` is Off with `fatal_error_backtraces` On: CVE-2026-129474's configuration holds. Sessions use the `files` handler with the `igbinary` serializer; upload progress is off; nothing overrides `max_memory_limit` or `zlib.output_compression` per path.
  - The rebuilt tag carries `PHP_VERSION=8.5.13` and `NEXTCLOUD_VERSION=35.0.3` (image config created 15:13 UTC, tag pushed 22:51 UTC), for `podman-auto-update`'s next run, 00:05 EST on 2026-11-20. An image's PHP is in its registry config's `Env`, readable with an anonymous pull token before anything is pulled.
- pterodactyl: noble's `php8.3-fpm 8.3.6-0ubuntu0.24.04.13` had no newer build, and Ubuntu listed CVE-2026-129289 for it as "Needs evaluation". Ubuntu keeps the 8.3.6 version string, so a fix shows by CVE ID in `/usr/share/doc/php8.3-common/changelog.Debian.gz`.
  - The `php_fpm` role removed the PHP2Shell stopgaps once that build arrived, so upload progress is on again. That exposes nothing: the one pool uses the `php` serializer, and the panel keeps its sessions in Redis (`SESSION_DRIVER=redis`), never reading PHP's session files. nginx sets no `fastcgi_keep_conn`, the pool no `catch_workers_output`, `date.timezone` is UTC, and no startup warning was printed.
