# Sentry's code mappings for every project in tofu/sentry, and matrix-synapse deleted (2026-11-17)

- `jianyuan/sentry` 0.16.0 manages code mappings (`sentry_organization_code_mapping`, imported as `<org>/<id>`) and repositories (`sentry_organization_repository`, imported as `<org>/github/<integration id>/<repository id>`). It has no repository data source, so a mapping's repository is adopted as a resource. Deleting that resource removes the repository from Sentry. The integration comes through the `sentry_organization_integration` data source, by `provider_key` and the account name.
- `organizations/<org>/integrations/` answers 404 on the region host `us.sentry.io` and only answers on `sentry.io`, the provider's default; repositories and code mappings answer on both. The repository list includes disabled repositories: picture-triangulator's is disabled in Sentry, its GitHub repository archived, and both still import and link. A mapping's empty `stack_root` or `source_root` is the same as leaving it out.
- `projects/<org>/<project>/stacktrace-link/` (`file`, `absPath`, `platform`, and for Java `module` and `sdkName`) shows how Sentry would link a frame with the live mappings: `sourceUrl`, or an `error` such as `stack_root_mismatch` or `file_not_found` with the URL it tried. Sentry tries longer stack roots first; a mismatch from one it tried earlier can appear in `error` beside a correct `sourceUrl`.
- How each project's frames look, and so its mapping:
  - PepperCord's Python frames are `/app/src/...`.
  - The pheidippides apps' Java frames give a module, which Sentry turns into a path by writing each `.` as `/`, so their stack roots are package paths.
  - RosellaView's frames carry its build checkout's absolute paths, so it has a mapping per checkout, plus one per checkout for its `third_party/UxPlay` submodule. GitHub keeps only a pointer for a submodule, so the submodule's frames resolve only in its own repository.
  - doppelganger's in-app frames are its built server output (`app:///_next/server/...`), whose source maps it does not upload, so its mapping, from `web/`, matches none of them.
- Symbolicator (crates/symbolicator-js) sets a source-mapped JavaScript frame's `filename` to the map's `sources` entry as written, and its `abs_path` to that entry joined to the bundle's base, such as `app:///home/...`. Metro writes absolute `sources` by default. A mapping's stack root is matched against `filename`, then `abs_path`.
- Deleting a key or a project needs the internal integration's Project at Admin; at Read & Write, Sentry answered 403 partway through an apply that had already made its other changes.
- matrix-synapse, which took upstream Synapse's errors, was deleted, after Synapse's `sentry:` block left its `homeserver.yaml`. doppelganger's platform became `javascript-nextjs`, which its session replays need.
- Data scrubbing is beyond 0.16.0. Upstream merged it after that release, in jianyuan/terraform-provider-sentry#995 (6dc3061): `data_scrubber`, `data_scrubber_defaults`, `scrub_ip_addresses`, `sensitive_fields`, `safe_fields` and `relay_pii_config` on `sentry_project`, all optional and computed, and a new `sentry_organization_data_scrubbing`. That resource resets every attribute it leaves out, and destroying it resets them all. Writing it needs Organization at Read & Write. It has no `store_crash_reports`. Live, the organization requires the data scrubber, the default scrubbers and IP-address scrubbing, with no sensitive or safe fields and no advanced rules.
- Custom integrations have no resource; the request, jianyuan/terraform-provider-sentry#164, was closed as not planned on 2026-09-01. The organization has two internal integrations, `homelab-tofu` and Vercel's.
