# OneSignal in tofu/onesignal, on a provider of our own, and doppelgangerhq.com's IP-restricted key (2026-11-16)

- OneSignal has no OpenTofu or Terraform provider, so `regulad/terraform-provider-onesignal` (MPL-2.0) covers its configuration API except Journeys: apps, app API keys, segments and templates. It is on no registry: `regulad/opentofu-registry`'s mirror builds it from a pinned commit, and the root's `tofu.rc` leaves it out of `direct` and takes it from the mirror alone. `tofu providers lock -net-mirror` records only the platforms named with `-platform`.
- Found against a test app, `homelab-provider-test`, which the root adopts and the provider's live tests (`make testlive`) work in, as OneSignal cannot delete apps through its API:
  - The Organization API key covers apps and app API keys, and viewing one app; segments and templates refuse it (401) and take an app's own key.
  - Updating an app merges. `site_name` and the default web push icon are accepted and dropped, and `additional_data_is_root_payload` goes to true and never back, so the provider reads all three only. APNs settings are kept only alongside a credential.
  - A key's allowlist takes CIDR ranges only, IPv6 included, and returns a `/32` or `/128` as a bare address and IPv6 in canonical form. Rotating or deleting a key revokes its old value at once.
  - Templates drop `big_picture`, `chrome_web_image`, `data`, `web_url`, `app_url` and `disable_email_click_tracking`, and keep `global_image`. A map such as `headings` sent as `null` fails with HTTP 500; `{}` clears it. A push template made without platform flags targets web push on Chrome, Edge and Firefox. `email_bcc` needs OneSignal's own email platform.
  - The organization's plan refuses to create segments: HTTP 403, "This API is not available for applications on your plan".
- doppelgangerhq.com's key `doppelgangerhq.com` is allow-listed to the instance's IPv4 `/32` and IPv6 `/128` from `tofu/oracle`'s `public_addresses`. The app's containers sit on a dual-stack Docker bridge with a ULA prefix, so their IPv6 leaves through the host's one GUA, which is the allow-listed address; from inside the web container the key works over both families.
