# bin/do_task shares go-task's state, and clean markers decide skips

- go-task saves a task's checksum whenever the task succeeds, whatever it found (`internal/fingerprint/sources_checksum.go`, at v3.54.0), so a plan with changes, or an Ansible check with changes, counted as done. A root's `pending/<step>` and its `status:` check had papered over that for OpenTofu alone, and only within one checkout; an Ansible check with changes was skipped on the next pass as if it were clean. A clean marker in each plan's `generates`, written only on a clean result, makes go-task's own rule (checksum matches and every `generates` file exists) skip only clean steps, and replaces `pending/`.
- An absolute `TASK_TEMP_DIR` keeps go-task's checksums under `<dir>/<the checkout's directory name>` (`setup.go`), which differs between worktrees; `bin/do_task` links that name to one shared `checksums/` directory under `~/.cache/regulad/homelab/task/`, beside `clean/`.
- In an included Taskfile, a variable defined from another of its variables (`CLEAN: '{{.CLEAN_DIR}}/{{.STEP}}'`) rendered `.STEP` empty in a real run that checked `generates`, though not under `--dry --force`; the marker's path is written in place where it is used.
