# mail's docker-mailserver trusts the host's CA store alone (2026-11-05)

- The container reads the host's trust store, the one the `ca_trust` role builds, in place of the image's Debian bundle. The Quadlet binds update-ca-trust's `/etc/pki/ca-trust/extracted/pem` at its own path, and its `directory-hash` over `/etc/ssl/certs`, both read-only. `directory-hash` holds each certificate, its OpenSSL hash links, and `ca-certificates.crt` and `ca-bundle.crt`, which point at `../tls-ca-bundle.pem`. Bound at `/etc/ssl/certs`, those two resolve to `/etc/ssl/tls-ca-bundle.pem`, which `user-patches.sh` links to the bound bundle, as the host's own `/etc/ssl/cert.pem` does.
- Inside the container, Postfix reads `CApath=/etc/ssl/certs`, with `tls_append_default_CA = no`. libldap's `TLS_CACERT`, OpenSSL's default `/usr/lib/ssl/cert.pem` and Python's default context read the bundle `/etc/ssl/certs/ca-certificates.crt`. The image has no other bundle: no certifi, no Java store. Its own Mozilla sources stay in `/usr/share/ca-certificates`, read only by `update-ca-certificates`, which nothing runs and which could not write the read-only `/etc/ssl/certs`.
- update-ca-trust keeps `pem` and `directory-hash`, both born when the image was installed, and replaces the files in them: `tls-ca-bundle.pem` was born at the last update. A bind of the directories follows each update. A bind of a file would keep the replaced file.
- docker-mailserver applies its configuration, and runs `user-patches.sh`, only when its container is created: `start-mailserver.sh` skips `_setup` when its `/CONTAINER_START` marker exists, as it does when the same container restarts. Quadlet runs the container with `--rm` and `--replace`, so each start of `mailserver.service` creates it anew, while `podman restart` applies nothing. Each of its files in `host_files` restarts the service. When a run changes both a file and the unit, mail restarts twice, once for each role's handler.
- The old bind of the FreeIPA CA, and `user-patches.sh`'s copy of it through `update-ca-certificates`, are gone. The empty `ipa-ca.crt` the runtime had made as the bind's mountpoint in `/etc/mailserver/config` is removed.
- The image has no `ldapsearch`. A login over IMAP, which Dovecot authenticates against LDAP over `ldaps://`, exercises libldap's trust.
- A script fed to `ssh host 'sudo bash -s' < script` shares its stdin with the commands it runs, which can read the rest of the script. The check on mail stopped after `podman healthcheck run`, and its remaining commands ran whole with `< /dev/null`.
