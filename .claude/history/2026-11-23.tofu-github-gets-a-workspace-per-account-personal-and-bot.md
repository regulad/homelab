# tofu/github gets a workspace per account, personal and bot (2026-11-23)

- **One App per account:** a provider block authenticates as one installation, and an App that installs only on its own account cannot be installed on another. So each account has an App of its own, `regubot-homelab` beside `regulad-homelab`, and a workspace of its own, `personal` for regulad's and `bot` for regubot's, which keeps one App's key out of the other's runs.
- **Each workspace's key on 6.13.0:** the provider reads its key only from `GITHUB_APP_PEM_FILE` or `pem_file`, so `prepare.sh` exports the selected workspace's `GITHUB_APP_<WORKSPACE>_PEM_FILE` as `GITHUB_APP_PEM_FILE`. A key left over from another workspace signs a JWT for the wrong App ID, which GitHub refuses. `app_auth_env_prefix`, which would let each workspace read a variable of its own, is not in 6.13.0. `GITHUB_OWNER` in the environment overrides the `owner` written in HCL.
- **Gating disjoint resources by workspace,** checked on OpenTofu 1.13.9 with built-in providers only:
  - `lifecycle { enabled }` works on data sources as well as resources, and sits beside `prevent_destroy` in one `lifecycle` block.
  - A disabled block evaluates to `null`; a conditional's untaken branch may reference it without an error.
  - `for_each = <cond> ? <map> : {}` and `<cond> ? toset(...) : toset([])` keep the instance keys, and so the addresses; the maps' object types unify with `{}`, sensitive values included.
  - `tofu validate` checks a resource's arguments even when its `for_each` is empty, and refuses a required one that is `null`: the gated repository name falls back to `""`, which no request ever carries.
  - Indexing a literal map by `terraform.workspace` fails even `tofu validate` in a workspace the map lacks, as `tofu/stripe`'s `publishable_key` does: validation needs one of the root's workspaces selected.
- **Moving the state into a workspace:** `tofu init -migrate-state` would copy a single state into the new configuration's `default` workspace, which with `key = "terraform.tfstate"` sits at the bucket's top level, beside `tofu/stripe`'s. Instead, `aws s3api copy-object` copied `github/terraform.tfstate` to `github/personal/terraform.tfstate` inside the bucket. The encrypted state does not record its key, so it decrypted there, and the plan in `personal` showed no changes. With `workspace_key_prefix = "github"`, `tofu workspace list` does not count the old object as a workspace.
- **The aws CLI against the state bucket:** the shell's `AWS_PROFILE` names a profile (`ceph`) that a temporary `AWS_CONFIG_FILE` lacks, so set `AWS_PROFILE=default`. The config sets `addressing_style = path` and `request_checksum_calculation` and `response_checksum_validation` to `when_required`, which the backend's `skip_s3_checksum` matches; the CLI reads `AWS_ENDPOINT_URL_S3` from `backend.sops.env` through `sops exec-env`.
