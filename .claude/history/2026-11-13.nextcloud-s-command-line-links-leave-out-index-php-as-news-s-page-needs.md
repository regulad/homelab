# Nextcloud's command-line links leave out index.php, as News's page needs (2026-11-13)

- aboriginal's Nextcloud has pretty URLs: its `.htaccess` has `occ maintenance:update:htaccess`'s section, with `RewriteBase /` and `SetEnv front_controller_active true`, so web requests generate and serve URLs without `index.php`.
- On the command line, as in cron and `occ`, nothing sets `front_controller_active`, so the router's base is `WEBROOT` plus `/index.php` (`OC\Route\Router::__construct`) unless `config.php` sets `htaccess.IgnoreFrontController`, and `URLGenerator::getAbsoluteURL` puts `overwrite.cli.url` in front. Links in mails from background jobs therefore carried `/index.php/`.
- News 29's page, opened at a `/index.php/apps/news/…` address while pretty URLs work, takes `/apps/news` as its router's base (`generateUrl`, with `modRewriteWorking`), matches none of its routes, and rewrites the address to `/apps/news/index.php/apps/news/…`, which is a 404 on reload.
- `podman logs nextcloud` carries Apache's access log, with each request's Referer, which shows a rewrite made by a page's own script as the next request from that page.
- Setting `front_controller_active=true` in a command's environment previews, on the command line, the links `htaccess.IgnoreFrontController` would make.
