# tofu/github-user becomes a root, with a workspace per account (2026-11-23)

- **A user owner creates under the token's account:** in `integrations/github` 6.13.0 and the mirror build, `github_repository` creates a repository for an owner that is not an organization with `POST /user/repos`, under whichever account the token belongs to, and its fork sets the fork's organization only for an organization owner. With no `token` or `GITHUB_TOKEN`, the provider falls back to `gh auth token`, regulad's own. One postcondition on `data.github_user.self`, read with `username = ""`, fails the plan unless the token is the workspace's account.
- **Forks:** `fork` is a string attribute; `source_owner` and `source_repo` force a replacement only when changed from a value already set (`CustomizeDiff`). The fork is created asynchronously (`202 Accepted`) and not awaited, and the create always ends in the update, which sends `PATCH /repos/{owner}/{repo}` (`Repositories.Edit`).
- **Settings without defaults:** `has_issues`, `has_wiki`, `has_projects` and `auto_init` have no default; an unset one is sent as `false`. Read calls the vulnerability-alerts endpoint whenever the repository's `security_and_analysis` comes back, which needs admin access, as an account has to its own repositories.
- **What only a token can do,** from the REST docs' token types for each endpoint: the user endpoints for SSH, GPG and signing keys take no App installation token, and an App forks only from an account it is installed on, so it cannot fork `microsoft/winget-pkgs`. Installation tokens with Administration write do create, update and delete repositories. Accepting a repository invitation and listing a user's App installations take only a token an App issues for a user, never a PAT.
- **Classic, not fine-grained:** a fine-grained token forks with Contents read and Repository creation write, but the update after every create needs Administration write, which also deletes repositories. Classic scopes separate them (`public_repo` and `delete_repo`); the token here holds both.
- **Disabled blocks:** a resource with `lifecycle { enabled = false }` may reference another disabled one (`github_repository.regubot.name`): neither body is evaluated, and the plan is clean.
- **A new root without a download:** a root pinning a provider release another root has installed initializes with its `.terraform/providers` linked to that root's and that root's `.terraform.lock.hcl` copied in; `tofu init -lockfile=readonly` then reports "Using previously-installed" and downloads nothing.
- **`tofu providers schema`** reads the backend, so it needs the root's state passphrase and backend credentials, not only installed providers.
